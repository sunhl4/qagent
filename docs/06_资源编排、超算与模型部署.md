# 资源编排、超算与模型部署

## 1. 目标

让 Agent 能够申请、使用、监控和释放计算资源，同时保证：

- 资源不被长期占用
- 成本可控
- 执行可恢复
- 不重复计费
- 多租户隔离
- 真实设备安全

## 2. 资源类型

| 类型 | 示例 | 调度方式 | 典型时长 |
|---|---|---|---|
| CPU 批任务 | 单测、解析、评估 | Kubernetes / Slurm | 秒–分钟 |
| GPU 训练 | 微调、训练、推理 | Slurm / K8s / SkyPilot | 分钟–天 |
| HPC | 大规模模拟、MPI | Slurm | 小时–天 |
| 云突发 | 弹性 GPU、临时集群 | SkyPilot | 分钟–小时 |
| 存储 | 对象存储、共享文件 | 平台 | 长期 |
| 真实设备 | QPU、实验仪器 | 专用调度器 | 按供应商 |

## 3. 分层调度

```text
平台准入
  ├─ 身份、租户、项目

        │
        ▼

```

## 5. 租约

### 5.1 字段

```text
lease_id
tenant_id / project_id
holder_type: TASK | ATTEMPT | SESSION
holder_id
resource_scope
state: REQUESTED | PREPARED | ACTIVE | DRAINING | RELEASED | REVOKED | EXPIRED
not_before / expires_at
fencing_token（单调递增）
checkpoint_uri
cost_reservation
```

### 5.2 规则

- 只有 `ACTIVE` 可以执行。
- 续租必须重新评估预算与配额。
- 过期立即拒绝新工作。
- 旧 fencing token 永久拒绝。
- 释放必须幂等。
- 回收失败要告警并补偿。

### 5.3 状态机

```text
REQUESTED → PREPARED → ACTIVE → DRAINING → RELEASED
        ↘ REVOKED / EXPIRED / FAILED
```

参考实现：`packages/domain/src/lease.ts` 实现上述状态机、时间窗口、续租与 fencing token 递增；`packages/pipeline/src/lease.ts` 把租约接到 `ComputePort`，准入时按 `maxCost` 预留，释放成功后才结算实际成本并退回预留。`UNKNOWN_EXECUTION` 保留预留，禁止自动重试。未知执行或释放失败会写入 `hold_reason`，供后续扫描识别。

### 5.4 自动回收与泄漏告警

单次扫描，不在进程内循环：

- 窗口内的租约做一次对账。任务已结束则结算并释放。
- 过期且没有资源句柄：就地标记 `EXPIRED`。
- 过期仍持有资源：释放。默认宽限 0 秒；超过 300 秒仍持有则告警。
- 上次释放失败：下一轮补偿释放，并告警。
- 未知执行或回收原因不明：只告警并升级，不释放结算，不重新提交。
- 确认未执行：记录“允许重提”，扫描本身不提交。
- 告警经 `TelemetryPort` 发出，指标标签只用稳定错误码和资源类型。遥测失败不阻断回收。

参考实现：`packages/domain/src/reclaim.ts` 给出回收决策；`packages/pipeline/src/reclaim.ts` 的 `sweepLeases()` 执行一轮扫描。记录符合 `schemas/reclaim-sweep.schema.json`。常驻调度仍由 Temporal 或外部定时器触发。

## 6. 两队列问题

### 6.1 问题

HPC 队列和外部资源队列独立，可能出现：

- HPC 已分配节点，但 GPU/云/QPU 还在排队 → 节点空转。
- QPU 已就绪，但 HPC 还没启动 → 设备空转。

### 6.2 缓解

1. 一次只允许一个长等待点。
2. 经典预处理完成即写检查点并释放。
3. 使用短 TTL 的 prepare/commit 协调。
4. 设置最大空等时间。
5. 超时降级为批处理。
6. 远程无预约能力时不承诺协同。

### 6.3 门控伪代码

```text
request soft lease
if remote ETA unknown:
    wait in control plane, not on HPC node
when start gate:
    release held HPC job
    activate lease
    submit
```

## 7. 检查点与恢复

| 任务类型 | 检查点内容 | 频率 |
|---|---|---|
| 训练 | 模型权重、优化器状态、步数、随机数状态 | 每 N 步或每 15 分钟 |
| 模拟 | 体系状态、轨迹、随机数 | 每 N 步 |
| 扫描 | 已完成参数组合 | 每完成一组 |
| 数据处理 | 已处理文件清单 | 每批 |
| 前端测试 | 已完成用例、失败 trace | 每用例 |

恢复规则：

- 从最近有效检查点恢复。
- 新 attempt 不覆盖旧产物。
- 记录恢复原因。
- 多次恢复失败进入人工处理。

参考实现：`packages/domain/src/checkpoint.ts` 的 `planResume()` 输出恢复、重启、升级或无需恢复；只接受同一实验、同一 attempt 且哈希合法的检查点。检查点缺失、过期、代码版本或环境不一致时重启；未知执行或恢复次数达到上限时转人工。`checkpointArtifactKey()` 使用 attempt 前缀，避免覆盖旧产物。检查点记录符合 `schemas/checkpoint-record.schema.json`。

## 8. 成本控制

### 8.1 三段账本

```text
预留（admission）
  → 实际（execution）
  → 释放（completion）
```

### 8.2 规则

- 准入时按悲观上界预留。
- 执行中按 chunk 重估。
- 超预算在安全点停止。
- 释放未使用部分。
- 每日汇总与告警。
- 异常成本自动降级或暂停。

### 8.3 成本归因

- 租户
- 项目
- 用户
- 任务
- 资源类型
- 模型调用
- 存储

参考实现：`packages/domain/src/cost.ts` 提供 `reserve`、`actual`、`release` 三类条目和 `checkBudget()`；已承诺成本按 `max(实际, 净预留)` 计算，避免重复计费。条目 ID 确定性生成，重试幂等。账本快照符合 `schemas/cost-ledger.schema.json`。`runExperiment()` 配置 `lease` 后启用完整链路：准入预留、结束后释放结算，并把 `costs.json` 快照写入该 attempt 产物。

## 9. 模型部署

### 9.1 三种模式

| 模式 | 说明 | 适用 |
|---|---|---|
| API | 调用官方或第三方 | 快速验证、非敏感 |
| 自部署 | 公司机房/云 GPU | 敏感数据、稳定高频 |
| 混合 | 路由按任务分配 | 成本与能力平衡 |

### 9.2 自部署组件

```text
模型权重
  → 推理引擎（DeepInfer / vLLM / SGLang / TensorRT-LLM）
  → KV cache
  → Prefill/Decode 分离
  → 副本负载均衡
  → 推理网关（鉴权、配额、限流）
  → 可观测
  → 评测与灰度
```

DeepInfer 公开说明其开源版本不包含完整服务所需的 KV cache、PD 分离和副本负载均衡，因此这些必须由公司补齐或选择其他引擎。

### 9.3 硬件考量

- GPU 型号与显存。
- 互联带宽（NVLink / RDMA）。
- 存储吞吐。
- 网络出口。
- 电力与散热。
- 国产加速卡生态。

### 9.4 模型版本治理

- 每个版本有 ID、哈希、评测报告。
- 灰度发布。
- 可回滚。
- 记录每次调用的模型版本。
- 换版本必须重跑关键评测。

## 10. 资源适配器接口

```text
discover() -> resources
quote(request) -> cost/time estimate
reserve(request) -> lease
submit(lease, job) -> jobHandle
status(jobHandle) -> state
cancel(jobHandle) -> result
logs(jobHandle) -> stream
artifacts(jobHandle) -> refs
release(lease)
reconcile(jobHandle) -> evidence
```

要求：

- 幂等。
- 超时可区分“未执行”和“未知”。
- 不把供应商状态直接透传为平台状态。
- 错误码稳定。

## 11. 故障处理

| 故障 | 处理 |
|---|---|
| 调度器不可用 | 排队等待，不重复提交 |
| 节点丢失 | 从检查点恢复，新 attempt |
| 网络中断 | 重连；超时后对账 |
| 存储不可用 | 本地缓冲，达到上限停止新任务 |
| 租约过期 | 停止新工作，释放资源 |
| 供应商未知 | 进入 `UNKNOWN_EXECUTION`，人工对账 |
| 成本异常 | 降级或暂停 |
| 模型服务降级 | 路由回退 |

## 12. 反模式

1. 为等待远程资源长期占用 HPC 节点。
2. 任务失败后不释放资源。
3. 不做检查点就跑长任务。
4. 用平均延迟代替端到端时间。
5. 把“提交成功”当作“已执行”。
6. 执行未知时自动重试。
7. 把供应商状态直接映射为平台状态。
8. 无预算上限的自动扩缩容。
9. 自部署只部署推理引擎，不部署网关与评测。
10. 把模型 API 密钥发给 Agent。
