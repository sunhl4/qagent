# 实施路线图与验收指标

## 1. 总体策略

不要一次建成“全自动科学家”。按能力依赖顺序推进：

```text
可追踪
→ 可恢复
→ 可回滚
→ 可复现
→ 可扩展
→ 多用户
→ 才谈完全自动化
```

每个阶段必须有明确的退出标准，未达标不进入下一阶段。

## 2. 阶段 0：边界与基线（1–2 周）

### 2.1 目标

建立一个可控的最小实验环境。

### 2.2 交付

- 研究章程：一个问题、一个基线、一个指标、一个预算。
- DSH 版本锁定（commit 或发行版）。
- 插件骨架与 manifest。
- 沙箱基线。
- `run-manifest` 与 `experiment-spec` schema。
- 人工审批流程。
- 最小日志与指标。

### 2.3 退出标准

- [ ] 能手动完成一次完整实验
- [ ] 代码、数据、环境、结果可追溯
- [ ] 能回滚代码
- [ ] 能释放资源
- [ ] 有审批记录

### 2.4 参考实现进度（2026-11-02）

- 研究章程已成文：`docs/16_研究章程.md`（问题、基线、指标、预算、停止与回滚）。章程中的"DSH 版本锁定"与"真实基线哈希"明确标注为待公司确认项。
- 可追溯：`ExperimentSpec` / `RunManifest` / 账本 / 审批决定均已落产物，`tests/pipeline.test.ts` 与 `tests/records.test.ts` 校验。
- 回滚代码：工程自身自 2026-11-02 起在 git 内（分层提交，见 `docs/交付清单.md` 变更记录）。
- 释放资源与审批记录：租约 + 账本 + 策略引擎已在桩上实现并测试；"能手动完成一次完整实验 / 能释放资源"为真实资源动作，接入 harness-core 后才能勾选。

## 3. 阶段 1：单任务自动实验（2–4 周）

### 3.1 目标

实现固定预算的自动实验循环。

### 3.2 交付

- autoresearch 式循环。
- Git 分支与 worktree。
- 结构化运行记录。
- 失败分类。
- 本地 CPU 或单 GPU 执行。
- 基础日报。

### 3.3 退出标准

- [ ] 连续运行 24 小时
- [ ] 无无限循环
- [ ] 每轮有唯一 ID
- [ ] 每轮有结果
- [ ] 失败可恢复
- [ ] 资源可释放
- [ ] 负结果被保存

### 3.4 参考实现进度（2026-10-30）

仓库内已覆盖可在桩环境验证的部分：

- `packages/pipeline/src/loop.ts`：有界循环、每轮唯一 `run_id`、预算与截止时间检查、连续失败与早停。
- `packages/domain/src/failure.ts`：失败分类与可重试性，未知执行强制不可重试。
- `packages/domain/src/failure-library.ts`：失败去重、检索与分类统计；循环写入 `failures.json`。
- `packages/pipeline/src/report.ts`：基础日报聚合与 `report.json`、`report.md` 写入。
- `packages/pipeline/src/run.ts`：成功、失败、未知执行、策略拒绝都写 `manifest.json`；循环写 `loop-summary.json`。
- `packages/workspace/src/worktree.ts`：实验尝试的 Git 分支/worktree 创建、复用与清理；脏工作树拒绝删除，分支保留；可通过 `LoopInput.workspace` 接入循环。
- `tests/loop.test.ts`、`tests/failure-library.test.ts`、`tests/report.test.ts`、`tests/worktree.test.ts` 与 `tests/records.test.ts`：验证停止条件、失败检索、日报、worktree 与 schema。

尚未完成的部分：24 小时连续运行、真实资源释放、真实 HPC/云作业恢复（依赖 harness-core 或真实环境）。对应勾选项保持未勾选。

回滚方式：本阶段新增能力都是增量文件与导出；回滚时删除 `loop.ts`、`report.ts`、`failure-library.ts`、`packages/workspace/` 及其导出和测试即可回到单次尝试流水线，已写入的 manifest、循环摘要、日报和 worktree 记录仍可读取。`on_unknown` 移除 `retry_once` 属于安全修复，不建议单独回滚；如必须回滚，需同时移除策略引擎对 `retryAfterUnknown` 的拒绝逻辑，并明确接受未知执行重试风险。

### 4.4 参考实现进度（2026-10-31）

仓库内已覆盖不依赖真实适配器的部分：

- `packages/domain/src/lease.ts`：租约状态机、时间窗口、续租、fencing token 递增与可执行判定。未知执行和释放失败记入 `hold_reason`。
- `packages/domain/src/cost.ts`：三段成本账本、预算检查、租约成本汇总与幂等条目。

- `packages/domain/src/reclaim.ts`：单次扫描的回收决策。过期回收、释放失败补偿、未知执行升级。
- `packages/pipeline/src/lease.ts`：报价、项目级预算预留、提交、释放结算与一次性对账；释放失败保留预留，未知执行不自动重试。
- `packages/pipeline/src/reclaim.ts`：一轮周期对账、过期回收和泄漏告警。确认未执行时不重新提交，遥测失败不阻断回收。
- `packages/pipeline/src/run.ts`（2026-11-02）：`runExperiment()` 支持 `RunInput.lease` 租约门控。准入预留 → 提交 → 结束统一释放结算，`costs.json` 快照写入 attempt 产物并计入 manifest；未知执行走对账，升级保留预留，确认未执行或已取消退回预留后按失败落盘。预算不足直接拒绝且不提交作业。
- `packages/pipeline/src/loop.ts`（2026-11-02）：`runExperimentLoop()` 支持循环级租约门控与恢复决策。共享账本跨轮串联，剩余预算按账本已承诺成本扣减（未释放预留同样占用）；`LoopOutcome.ledger` 返回最终账本可直接接 `sweepLeases()`。每轮结束用 `planResume()` 生成恢复/重启决策并写入尝试记录，恢复次数达到上限转人工；`loop-summary` 增加可选 `resume_plan` 与 `resume_from`。循环终止与运行级租约状态迁移会发布平台事实事件到 `EventPort`。
- `packages/domain/src/policy.ts` + `pipeline/src/run.ts`（2026-11-03）：策略评估正式留痕。`buildPolicyDecisionRecord()` 产出符合 `schemas/policy-decision.schema.json` 的决定记录，每次评估写 `policy-decision.json` 产物；允许、拒绝与需要审批的路径都可通过 `RunOutcome.policyRecord` / `policyRecordRef` 追溯。
- `packages/pipeline/src/retrieval.ts`（2026-11-03）：跨循环失败召回。`loadFailureLibrary()` 经 `ArtifactStorePort` 读回历史 `failures.json` 并用 `mergeFailureEntries()` 去重合并；`LoopInput.recallFailureUris` 在任务开始前召回，历史条目挂在 `LoopOutcome.recalledFailures`。
- `tests/lease.test.ts`、`tests/cost.test.ts`、`tests/lease-pipeline.test.ts`、`tests/checkpoint.test.ts`、`tests/reclaim.test.ts`、`tests/reclaim-sweep.test.ts`、`tests/lease-run.test.ts`、`tests/loop-lease.test.ts`、`tests/loop-signals.test.ts`、`tests/policy-record.test.ts`、`tests/failure-retrieval.test.ts`：覆盖状态迁移、幂等、预算、释放、对账、检查点、回收决策、补偿、运行级与循环级门控、恢复决策、事实事件、审批留痕与失败召回及 schema。

尚未完成、需要 Temporal 或 harness-core 真实适配器的部分：持久工作流、控制面重启后续跑、Slurm/Kubernetes/SkyPilot 接入。周期对账、自动回收和泄漏告警已经是可重复调用的单轮扫描，没有常驻循环。对应退出标准保持未勾选。

回滚方式：删除 `packages/domain/src/reclaim.ts`、`packages/pipeline/src/reclaim.ts`、`schemas/reclaim-sweep.schema.json` 及其导出和测试，即可回到一次性对账。撤销 `runExperiment` 的租约门控只需不传 `RunInput.lease`；撤销循环级门控与恢复决策只需不传 `LoopInput.lease`、`LoopInput.checkpoints` 与 `LoopInput.resume`（均保留旧路径，无破坏性回滚）。`hold_reason` 是可选字段，留着不影响旧逻辑；若要去掉，需同时改 `schemas/resource-lease.schema.json` 和 `transitionLease()`。再删除 `packages/domain/src/lease.ts`、`packages/domain/src/cost.ts`、`packages/domain/src/checkpoint.ts`、`packages/pipeline/src/lease.ts` 及其测试，则回到实验流水线。已写入的租约、账本、检查点与扫描记录仍可读取。

## 6. 阶段 4：软件工厂（上游 Super-agent 冻结后，8–12 周）

### 6.1 目标

在开源 Super-agent 上跑通从规格到可合并 PR。本工程提供规格、Superpowers 门禁、独立评审和合并策略，不自研 Router、Worker 或 Watchdog。

### 6.2 交付

- 锁定的上游 Super-agent 版本，以及本仓库作为它的一个 Source。
- 规格进入 Mandate 范围。
- Executor 加载 Superpowers 技能：计划、TDD、验证命令。
- 一工单一目录。后续评论回到同一 Executor。
- 独立评审工单或 pr-agent。作者不审自己的 PR。
- 后端测试、Playwright E2E、安全扫描。
- 平台策略拦截花钱、上机、合并主分支和外发数据。
- 主动行为默认只记录；书面规则批准后才允许交付。
- 进程重启后续跑，且不重复已经发出的外部动作。

### 6.3 退出标准

- [ ] 合并候选通过全部门禁
- [ ] Agent 无法越权，Watchdog 不能修改策略、预算或租约
- [ ] 失败有可复现证据
- [ ] 人工可接管
- [ ] 回滚方案存在
- [ ] 同一工单的后续讨论不新开一套任务状态
- [ ] 上游不可用时，可切换到单工单 headless 降级，并标记 `degraded`

### 6.4 降级

上游没有可锁定版本时，本阶段不开始自研路由器。降级实现是：一张工单、一次新的 headless 会话、独立 worktree、与上面相同的门禁。实验循环代码不改作这个降级实现。细节见 `docs/15_Super-agent接入与两套时钟.md`。

### 6.5 降级实现进度（2026-11-01）

仓库内已覆盖不依赖上游 Super-agent 的门禁：

- `packages/domain/src/software-gate.ts`：规格、四类证据、独立评审、人工审批、主动行为只记录、禁止跳过门禁。未锁定版本时拒绝声称使用上游。
- `packages/pipeline/src/software.ts`：结构预检后为一张工单启动一次 `SessionPort` 会话。会话先行，随后由调用方以外部证据调用 `evaluateSoftwareMerge`。会话输出不作为证据，再次启动被拒绝。
- `packages/domain/src/platform-signal.ts`：实验完成、租约变化、预算耗尽三类事实事件。同一资源版本重复生成同一事件标识，且拒绝凭据字段。
- `schemas/software-merge-record.schema.json`、`schemas/platform-signal.schema.json`。
- `tests/software-gate.test.ts`。

尚未完成、需要上游可锁定版本的部分：把本仓库注册为 Source、Executor 技能、进程重启后续跑。对应退出标准保持未勾选。

回滚方式：删除上述两个领域文件、`packages/pipeline/src/software.ts`、两个 schema 与 `tests/software-gate.test.ts`，并去掉 `packages/domain/src/index.ts` 与 `packages/pipeline/src/index.ts` 中的导出。实验循环、租约和回收不受影响。

## 10. 里程碑时间线

```text
第 1 月：阶段 0 + 阶段 1 起步
第 2 月：阶段 1 完成 + 阶段 2 起步
第 3 月：阶段 2 完成
第 4 月：阶段 3 完成
第 5 月：阶段 4。若上游 Super-agent 尚未可锁定，则只交付降级路径
第 6 月：阶段 5 起步
第 9 月：多租户稳定
第 12 月：全面运行与优化
```

时间取决于团队规模与既有基础设施，不是承诺。

## 12. 预算与资源估算

需要按公司实际情况填写，建议至少估算：

- 开发人力
- GPU/HPC 机时
- 云资源
- 模型 API 费用
- 存储
- 安全与合规
- 运维

估算方法：

```text
月度成本 =
  人力
  + 固定基础设施
  + GPU/HPC 机时 × 单价
  + 模型 token × 单价
  + 存储 × 单价
  + 外部服务
  + 预留 20% 缓冲
```

## 13. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| DSH API 变化 | 高 | 中 | 锁版本、适配层 |
| Super-agent 晚于假设开源或接口不同 | 中 | 中 | 阶段 0–3 不依赖它；阶段 4 降级为单工单 headless |
| 自部署成本超预期 | 中 | 高 | 试点、混合路由 |
| 资源泄漏 | 中 | 中 | 租约、对账 |
| 模型输出不可靠 | 高 | 中 | 校验、评测、人工门 |
| 多租户越权 | 低 | 高 | 硬隔离、审计 |
| 实验不可复现 | 中 | 高 | 清单、种子、环境 |
| 团队采用率低 | 中 | 中 | 培训、模板、快速见效 |

## 14. 退出与回滚

每个阶段都要有回滚方案：

- 代码回滚。
- 数据迁移回滚。
- 模型版本回滚。
- 工作流版本回滚。
- 插件版本回滚。
- 资源释放。

回滚必须演练，不能只写在文档里。
