# Company Agent 商业化开发计划：约 2000 人天

版本：v1.0；日期：2026-10-26；状态：用于立项、预算和技术评审的条件性基线，不是固定报价或交付承诺。

机器可读分解：[company-agent-2000-person-days-development-plan-v1.0.json](company-agent-2000-person-days-development-plan-v1.0.json)。本计划建立在 [DSH Harness v0.8 对齐设计](company-agent-harness-framework-v0.8.zh-CN.md)、[工程衔接建议](oss-survey/04-工程衔接建议.zh-CN.md)、[开源复核总报告](oss-survey/05-复核总报告.zh-CN.md)和已有 P0/P1/P2 落地记录之上。

## 一、先给结论

可以把当前目标整理成一个约 **2000 人天**的商业化开发计划，但这个数字必须按“产品化集成与验收”理解，而不是重新建设量子云平台、HPC 调度器、基础模型或第二套 Agent Runtime。

本计划覆盖以下产品目标：

- DSH（DeepSeek Harness，唯一 Agent Runtime）承载通用对话、模型调用、工具调用、会话事件和受管 Skills。
- 复用公司已部署的本地大模型和 DeepSeek，不建设新的基础模型训练、推理引擎或模型循环。
- 复用成熟云平台和 HPC 平台的身份、资源、作业、队列、存储、计量和账单事实源。
- 形成内部账户和外部账户的租户隔离、服务开通、凭据托管、审批和撤权闭环。
- 形成三栏 Web / 本地 UI：左侧导航，中栏工作台、文件、任务、结果、图表和 Canvas，右侧 DSH 对话。
- 具备正常通用 Agent 能力，但通用代码、网页、文件和工具执行必须通过受管 provider、插件、MCP 和 Skills；不能通过可写 preset 或 shell 绕过审批。
- 接入量子模拟、编译、QASM 上传、算法目录、HPC 协同和受监督真机任务。
- 具备结果回收、指标模板、绘图模板、知识入库和内部知识权限控制。
- 具备商业化运行需要的测试、审计、对账、计费映射、监控、发布和支持体系。

**2000 人天包含 1740 人天基线建设和 260 人天受控风险储备。** 风险储备不能在第一天全部投入，必须在架构变更、平台接口不一致、安全缺陷、真实设备窗口或试点缺陷出现时按变更记录释放。

## 二、估算边界

### 2.1 已经存在、因此不重复建设的基础

以下内容作为规划输入复用：

- DSH 是唯一生产 Agent Runtime；不另写模型循环、会话循环或工具循环。
- `contracts/`、`src/company_agent/`、`packages/`、`profiles/` 和 `tests/` 已形成目标架构的基本边界。
- 已有工具合同、provider 检查、策略 ask/deny、结果预算、短结果和未知执行状态。
- 2026-10-22 已落地 P0：统一能力分层判据、外发回执与对账入口、验收反例门禁（[实施记录](implementation-2026-10-22-oss-survey-p0.zh-CN.md)）。
- 2026-10-23 已落地 P1/P2：`metric-summary`/`shots-audit` 分析模板、知识登记治理、Skills 注册表 sync/verify、13 场景合规门禁、工作台只读投影、模型服务六点探针、平台侧 `asset.metrics` 适配和绑定业务引用的回执 v1.1（[实施记录](implementation-2026-10-23-p1-p2.zh-CN.md)）。截至该记录：主仓 pytest 843 通过、UI node 24 通过、平台仓 provider 子集 77 通过。

本计划的阶段口径只计**剩余的硬化、联调、扩展和验收**，以上已落地能力按既有基线对待，不从零再算一遍。

与既有估算的对照：[量子专项条件估算 v1.2](quantum-agent-delivery-estimate-2026-10-20.zh-CN.md) 的有界首版为 94–156 人周（风险后 113–203 人周，约 565–1015 人天），仅覆盖量子工作区子集。本 2000 人天计划以该子集为内核（主要落在 P4/P5），其余人天投在通用 Agent 产品化、企业身份与租户、三栏 Web/本地 UI、运营计费、安全验收和发布交接；已落地部分在阶段计数上只计剩余工作，不重复从零开发。
- 公司已有本地模型和 DeepSeek；本计划只估算 DSH 接入、行为评测、容量和数据边界验收。
- 公司云平台和 HPC 平台成熟；本计划只估算 Agent 面向这些平台的身份委托、作业适配、结果对账和权限验收。
- Uniqon 或公司量子平台负责科学算法和平台侧执行；Agent 不直接 import `company_quantum_platform` 或科学算法包。

### 2.2 2000 人天不包含的内容

以下事项不计入本计划，若实际需要，应单独立项：

- 基础模型训练、模型权重研发、通用推理引擎重建或大规模GPU/NPU集群建设。
- 新建云平台、HPC调度器、QPU控制系统、商业账本或企业身份平台。
- 新的量子算法研究、解码算法训练、线路优化算法研发、离子调度算法研发和QPU硬件研发。
- 无人值守真机校准或绕过公司审批的设备自动执行。
- 无限量的公司知识整理、历史数据清洗或全公司业务流程数字化。
- 为了兼容某个开源项目而引入第二套Agent Runtime，或将多个通用Agent框架串成生产链路。
- 未知外部平台的长期运维承诺、采购等待、法律审批等待和供应商合同谈判等待时间。

### 2.3 估算单位和日历含义

- 1 人天：一名具备相关经验的人员投入一个完整工作日。
- 人天包含设计、编码、代码评审、单元测试、集成测试、必要的技术文档和缺陷修复。
- 平台团队、安全、设备、财务和法务需要提供接口、测试租户和审批窗口；他们的底层平台建设不计入2000人天，但等待这些输入会延长日历工期。
- 2000人天不是2000个连续工作日。按12–15名核心成员、有效交付率约70%估算，含储备2260人天的纯容量约10–13个月；考虑关键路径、平台联调、设备窗口和发布波次，建议按 **14–18个月**准备商业化首版。
- 如果只有8–10名核心成员，含储备的纯容量约14–19个月，建议按 **18–26个月**准备；增加人数不能消除平台接口等待和真机验收关键路径。

## 三、总体交付原则

### 3.1 先合同，再适配器，再插件，再测试

每个新能力必须按以下顺序交付：

1. 在`contracts/`定义输入、输出、身份、provider、状态、句柄和失败行为。
2. 在`src/company_agent/`实现Python adapter和执行前/执行后门禁。
3. 在`packages/`注册薄插件，只转调`company-agent invoke`。
4. 在`profiles/`配置受管组合，不把业务逻辑放入profile。
5. 在`tests/`加入正常、拒绝、故障、恢复和跨租户反例。

### 3.2 必须保持的产品不变量

- DSH仍是唯一Agent Runtime。
- 算法只能从平台`algorithm.catalog`发现，标识只能使用平台`component_id`。
- 业务句柄只有`asset_id`、`circuit_id`、`twin_id`。
- 只有`quantum_device_run`且provider为`ionstack-twinrun`时才允许返回`twin_id`。
- `quantum_device_run`在`lab`和`sign`必须ask，在`boot`和`algo`必须deny。
- 未知工具、未知preset、缺失provider、坏信封和未知状态都必须失败闭合。
- 云/HPC/QPU的受理、完成、取消、计费和未知状态以平台事实为准；Agent会话和UI只保存受控引用及投影。
- 工具结果必须短；完整QASM、bitstrings、Pauli、CAL、shuttle、密钥和完整科学正文必须留在受控平台资产中。
- 平台已受理但响应丢失时标记`unknown`，不自动重投设备；`request_id`不能被假设为幂等键。

## 四、阶段与人天分配

以下十个阶段的基线合计1740人天，另有260人天风险储备，预算总额为2000人天。阶段安排遵循 [v0.8 框架](company-agent-harness-framework-v0.8.zh-CN.md)的投入优先级**S6 权限治理 > S4 执行隔离 > S2 上下文 > S5 状态记忆 > S7 验证 > S3 工具 > S8 界面 > S1 模型验收**：合同与授权硬化（P0/P1）先于工具扩容（P3），失效反例（P8 前置部分）先于插件面积增长；P3 的通用能力扩展必须在身份与审批（P1）之后才达到可验收状态。

### P0：产品边界、合同基线和工程治理——100人天

- 产品范围、内部/外部用户场景、试点边界和不做清单：30人天。
- DSH、公司Agent、Uniqon、云平台和HPC的版本、provider身份和接口清点：25人天。
- 工具、能力、provider、preset、结果、分析模板、Skills和事件合同基线：25人天。
- CI、发布、证据、版本钉、环境清单和变更审批流程：20人天。

**阶段出口：** 完成正式provider身份确认、首期能力目录、两类账户边界、验收四元组和风险登记；没有真实平台接口说明时，不进入大规模适配开发。

### P1：统一身份、租户、服务开通和授权——200人天

S6 权限治理是最优先投入位。本阶段承接演示级 `host.mjs` 全局开通状态向企业逐用户授权的升级，从现有策略合同出发加固，不从通配符重写审批。

- 用户、组织、项目、内部/外部账户和租户模型：55人天。
- 复用公司登录、云平台账号委托和HPC账号映射：35人天。
- 能力、项目、资源、工具和结果的授权矩阵：45人天。
- 托管凭据、短期令牌、凭据轮换、撤权和服务开通申请：30人天。
- 审批主体、参数快照、审批关联、可靠审计字段和权限异常处理：35人天。

**阶段出口：** 两个隔离租户能够证明“可登录、已开通、凭据已注入、工具已注册、执行获准、探测成功”是六个独立状态；用户不能通过模型参数、UI开关或工具描述伪造身份。

### P2：DSH、本地模型、插件、MCP和Skills产品化——150人天

模型服务六点探针、Skills 注册表 sync/verify 与知识登记治理已落地；本阶段只计剩余的运行时加固与接入治理。

- DSH事件、会话、工具调用、取消、恢复和错误信封接入加固：40人天。
- 本地模型和DeepSeek行为验收收尾：容量、租户隔离、回退与上下文/结果合同清点：30人天。
- MCP/插件清单、版本、provider绑定、schema投影和回滚：35人天。
- MCP两个传输通道的差异门禁：STDIO没有OAuth概念，由宿主进程边界加公司授权兜底：25人天。
- Skills注册表运营、跨端状态刷新与观测出口许可选型：20人天。

**阶段出口：** 右栏能使用公司本地模型完成受管通用对话；模型服务异常不会静默切到未批准外部模型；MCP声明、Skill正文和工具注释不直接产生执行授权。

### P3：受管通用Agent能力——180人天

调研结论直接进入本阶段设计：网页内容一律按不可信观测处理（参考 Firecrawl 注入检测 fail-open 的反例），受管代码上下文需显式读取与字节预算（参考 Repomix 整文件读取后再查大小）。

- 会话、消息、文件引用、历史、任务拆分和工作区上下文：35人天。
- 受管代码执行和文件操作provider，包括网络、凭据、路径和资源限制：45人天。
- 受管网页检索、内容注入隔离、来源引用和未完整扫描的显式状态：25人天。
- 通用办公、文档、数据处理和项目协作插件：25人天。
- token、调用次数、墙钟、费用和审批等待等终止预算：25人天。
- WorkBuddy/Codex类通用场景的拒绝、恢复、工具错误和跨端体验验收：25人天。

**阶段出口：** 通用Agent可完成文件、代码、网页和文档类受管任务；没有新增模型循环或工具循环；官方Codex保持`permissionMode: never`、`inheritsParentContext: false`，且不获得设备工具。

### P4：量子、云平台和HPC作业适配——230人天

- QASM上传、内容限制、线路版本和`circuit_id`资产注册：40人天。
- 模拟、编译和平台算法调用的provider适配：40人天。
- `algorithm.catalog`同步、`component_id`映射和算法权限：25人天。
- 云平台任务提交、排队、运行、完成、取消、事件游标和未知结果对账：45人天。
- HPC提交、SLURM作业号映射、状态、日志/指标文件、结果资产和失败语义：45人天。
- 一个成熟QPU provider的受监督接入、审批参数绑定和真实测试窗口：35人天。

**阶段出口：** 一个模拟器、一个HPC流程和一个受监督真机流程形成端到端窄链；平台作业事实可从Web和本地UI查询；不把HPC作业号、容器ID或checkpoint ID伪装成三类业务句柄。

### P5：结果回收、分析模板、Canvas、知识和Skills内容——190人天

`metric-summary`/`shots-audit` 模板与知识登记 registry 已落地；本阶段在其上扩展生产形态，并继续遵守 64000 字节短结果合同，不采用上游 16KB 截断语义。

- 结果资产、指标表、schema版本、单位、完整性和权限检查：45人天。
- 在已落地两个模板基础上扩展统计、绘图、报告和Canvas模板：35人天。
- 大结果资产的分页、摘要、下载授权和指标化读取：30人天。
- 知识登记治理硬化与检索评测：撤权即时性、时效、多租户与摘要漂移：40人天。
- 面向量子任务的受管Skills和模板内容包：20人天。
- 内部算法接口、软件文档和数据知识的内部账户权限链：20人天。

**阶段出口：** 模型只看到短摘要和授权引用；完整科学结果保留在平台；单位、概率、NaN、跨租户资产、恶意文件名、撤回文档和过期知识均有确定性处理。

### P6：三栏Web、本地UI和工作台——190人天

- 三栏布局、主题、路由、登录态和DSH右栏挂载：60人天。
- 本地UI外壳、网页/本地端同步、启动、升级和断线恢复：35人天。
- 工作台的运行、排队、历史、取消、未知和待审批任务投影：35人天。
- 文件、代码、报告、指标、图表和Canvas资源查看器：30人天。
- 事件订阅、通知、去重、分页、权限变更和跨端一致性：30人天。

**阶段出口：** Web和本地UI消费同一服务端事实源；界面显示在线不代表工具可执行，前端按钮和状态不作为权限来源；任务关闭右栏后仍可在工作台查询。

### P7：计费、额度、运营和支持——140人天

- 用户/项目额度、报价、预估、预留和实际用量映射：30人天。
- 云平台、HPC和QPU账单引用及部分失败/取消/重复事件对账：35人天。
- 管理员、服务开通、权限变更、审批查询和运营后台：30人天。
- OTel/日志/指标/审计出口、数据脱敏和告警：25人天。
- SLO、值班、故障分级、运行手册和支持流程：20人天。

**阶段出口：** 模型token费用、HPC节点时、QPU用量和企业账单分开核算；审计记录、观测trace和平台账单不互相冒充；运营人员能定位unknown、重复事件和权限失配。

### P8：安全、可靠性、性能和商业验收——240人天

调研里的失效模式（H 反例库）逐条映射为本阶段验收用例：见“十一、调研结论如何进入计划和验收”。

- 合同、provider、preset、句柄、结果预算和坏信封门禁：50人天。
- 身份、权限、真实提示注入面、数据外发、密钥回显和供应链测试：45人天。
- 双租户、内部/外部账户、撤权、资产越域和权限缓存测试：35人天。
- 会话、工具、模型、MCP、事件、结果和工作台容量测试：30人天。
- 平台受理丢包、取消、重连、unknown、重复事件和账单对账演练：35人天。
- 开源许可与第三方组件合规评审：ELv2/AGPL/品牌限制等逐项登记：25人天。
- 代表性量子任务、HPC流程、通用Agent任务和用户验收：20人天。

**阶段出口：** 安全红线、跨租户隔离、故障恢复、性能容量和真实平台窄链全部有证据；上游组件源码研究、模型回答或UI绿色状态不能替代验收证据。

### P9：发布、试点、文档和交接——120人天

- 内部试点、外部小范围试点、灰度和回滚：30人天。
- 版本清单、合同/插件/Skills迁移、数据库和配置回滚：25人天。
- 用户、管理员、平台Owner和支持团队文档培训：25人天。
- 事故演练、值班交接、问题分级和供应商升级路径：20人天。
- 试点缺陷修复、发布复盘和下一版本范围冻结：20人天。

**阶段出口：** 首批用户可在受管范围内使用；发布可回滚，作业状态可追踪，支持团队能处理权限、平台、模型、结果和计费问题。

## 五、风险储备：260人天，必须按门释放

风险储备不是隐藏的“免费工作”，也不是默认把范围扩大到所有算法。建议拆为：

- 平台Agent接口、身份委托或provider身份不一致：100人天。
- 安全、租户隔离、密钥和数据外发整改：60人天。
- 本地模型/DeepSeek协议、流式、工具调用或容量差异：40人天。
- QPU/HPC测试窗口、结果格式、未知状态和数据缺陷：40人天。
- 试点UX、发布缺陷和跨端同步返工：20人天。

每次释放风险储备必须记录：触发事实、影响阶段、替代方案、增加或删除的范围、验收证据和剩余预算。储备耗尽时优先缩小首版范围，不降低审批、租户、结果完整性和失败闭合门槛。

## 六、角色投入分布

- DSH、Python和模型集成：220人天。负责本地模型、DeepSeek、插件、MCP、Skills和运行时边界。
- Web和本地UI：250人天。负责三栏、工作台、资源查看、跨端状态和发布外壳。
- 量子、云平台和HPC集成：230人天。负责QASM、算法目录、模拟、云任务、HPC和受监督QPU。

## 七、建议团队和日历排程

### 7.1 核心团队

建议配置12–15名核心成员，另有平台、设备、安全、财务和产品Owner作为固定支持：

- 产品/业务：1人。
- 架构/技术负责人：1人。
- 后端与合同/provider：2–3人。
- DSH/Python/模型集成：1–2人。
- Web/本地UI：2人。
- 量子/云/HPC集成：2人。
- 结果/知识/Skills：1人。
- QA/可靠性：2人。
- SRE/发布：0.5–1人。
- 安全/身份和UX按阶段投入，不要求全程满配。

### 7.2 关键日历阶段

- 月1–2：P0和P1启动，完成合同、身份、租户、provider身份和首期接口冻结。
- 月3–5：P2和P3，形成内部通用Agent alpha；可使用本地模型和受管工具，但不宣称真机可用。
- 月5–8：P4前半和P5前半，形成模拟器、QASM、HPC和结果模板的内部beta。
- 月8–11：P4后半、P5、P6和P7，形成受监督云/HPC/QPU和工作台试点候选。
- 月10–14：P8安全、性能、故障和跨租户验收；在发现问题时释放风险储备。
- 月13–16：P9内部/外部小范围试点、灰度和回滚。
- 月16–18：处理平台窗口、储备释放和试点复盘；若基础接口稳定，可提前结束，不为消耗预算延长项目。

### 7.3 里程碑门禁

**G0：立项基线。** 预算、范围、正式provider身份、模型入口、测试租户、QPU审批人和HPC测试窗口均已登记。

**G1：通用Agent内部Alpha。** DSH、本地模型、会话、受管插件/MCP/Skills、文件和受管代码路径可用；未知工具、坏信封、无provider和跨租户调用均拒绝。

**G2：模拟/HPC内部Beta。** QASM受支持子集、模拟、HPC提交、作业状态、结果资产、一个分析模板和工作台查询闭合；无真实QPU自动执行。

**G3：受监督量子试点。** 一个真机provider在lab/sign人工ask链路通过；boot/algo拒绝；unknown、取消、重复事件和计费引用均能对账。

**G4：商业Beta。** 内部/外部账户、额度、知识/Skills权限、三栏Web和本地UI同步、结果模板、审计、监控、SLO、回滚和支持流程通过。

**G5：小范围生产发布。** 至少一个内部租户和一个外部租户完成代表性任务；没有未关闭的P0安全问题；平台Owner确认作业、结果和计费事实；所有版本钉和验收报告齐全。

## 八、首版范围控制

如果项目出现预算或平台接口风险，按以下顺序缩小范围：

1. 先保留身份、租户、审批、作业对账、结果完整性和失败闭合。
2. 将真机范围限定为一个provider和一个审批流程，将模拟器/HPC保留为首版主路径。
3. 将知识库限定为有限的已审批内部资料源，暂缓自动记忆、图谱和向量多后端并行建设。
4. 将分析模板限定为指标摘要、shots审计和少量声明式图表。
5. 将通用Agent的代码执行限定为一个受管provider，暂缓更多第三方工具。
6. 暂缓新的量子算法研究、自动校准和多QPU复杂协同；不通过降低安全门槛来保持功能数量。

## 九、必须持续记录的度量

- 合同、工具、provider、preset和Skills版本及摘要。
- 模型路由、模型版本、DSH版本和任务集版本；不记录密钥和完整敏感正文。
- 工具调用成功、拒绝、ask、unknown、取消和失败比例。
- 平台受理到完成的时间、回执丢失、对账延迟和重复事件数量。
- 跨租户拒绝、撤权生效时间、敏感数据拦截和审计写入失败。
- 结果模板结构错误、域级flag、完整性错误和用户修正次数。
- Web/本地UI事件延迟、断线恢复、状态不一致和回滚成功率。
- 模型token用量、HPC节点时、QPU用量和企业账单分别记录。

## 十、调研结论如何进入计划和验收

依据本轮57项开源源码复核（[总报告](oss-survey/05-复核总报告.zh-CN.md)、[本地架构对照](oss-survey/03-本地架构对照与工程边界.zh-CN.md)、[工程衔接及已落地清单](oss-survey/04-工程衔接建议.zh-CN.md)），以下经固定SHA核实的结论被固化为本计划的工作项与验收反例：

| 调研证据（固定SHA复核） | 计划落点 | 固化到验收的行为 |
| --- | --- | --- |
| Docker MCP Gateway 在非 Desktop 或治理 flag 失效时返回全允许 NoopClient（H23） | P8 门禁、P2 插件接入 | 引入任何治理组件时，客户端失效必须拒绝执行；公司策略在`invoke`前强制，不依赖网关完成授权 |
| Firecrawl 注入检测默认关闭、分类器故障 fail-open、超长内容跳过（H40） | P3 受管网页检索 | 未完整扫描的内容标记未验证，不进入模型上下文或自动执行；网页始终是数据不是授权来源 |
| FastMCP 明文声明 STDIO 跳过 OAuth 检查（H16） | P2 MCP 接入 | stdio 与 HTTP 两种传输分别测宿主边界和公司授权；middleware 覆盖不免除逐传输测试 |
| Ollama chat 路径按上下文裁剪历史且存在云模型代理分支（H50） | P2 本地模型验收 | 上下文裁剪不得移除审批/参数依据；本地部署不推导为全离线 |
| Inspect 工具输出默认 16KB 截断（H42）；公司合同 64000 字节且禁止会损截断 | P5 模板、P8 门禁 | 模板与 provider 输出遵守 64000 合同；越界转平台资产引用，不静默截短标成功 |
| CopilotKit 每线程克隆实例与运行事件仅前端语义（H48） | P6 工作台投影 | 订阅绑定实际会话实例；“运行完成/取消”不等于平台作业终态 |
| Langfuse 登录 Session 与业务 TraceSession 不同；ReplacingMergeTree 非不可变账本（H54） | P7 审计与观测 | 审计字段公司自持；trace 只作观测，不充当计费与合规凭证 |
| Phoenix 根 ELv2，独立 phoenix-otel 包为 Apache-2.0（H55） | P2/P7 观测选型 | 按引入范围分别登记许可，不整仓默认采用 |
| LiteLLM 预算 hook 仅覆盖模型 token 维度（H53） | P7 计费对账 | 模型 token、HPC 节点时、QPU 用量与企业账单分账 |
| open-swe 数据库 event claim 去重不等于设备 exactly-once（H15） | P4 作业对账 | unknown 以平台事实为准；`request_id` 不作幂等键，设备零自动重试 |
| Aider repo map 排名不授予读取权限（H07）；Repomix 整文件读取后再查大小（H39） | P5 知识检索、P3 上下文预算 | 检索前按租户过滤；代码/文件上下文有显式读取路径与字节预算 |
| Goose 撤销后旧授权不得复活（H03）；gptme 无 hook 走 default_confirm=True（H02） | P1 审批、P8 门禁 | 撤权即时生效且有跨实例反例；无确认路径默认拒绝，不套用默认放行 |
| SWE-bench 零执行/矛盾退出码判无效（H43） | P8、P9 验收 | 成功必须有真实执行证据；未运行、全跳过或日志矛盾不判通过 |

## 十一、评审结论和下一步

这份2000人天计划适合作为立项基线，前提是公司确实提供成熟云/HPC的Agent可用接口、测试租户、模型端点说明、QPU审批窗口和账单映射。它不是“2000人天后所有算法、所有设备和所有知识自动完成”的承诺。

启动后的前10个工作日应完成：

1. 确认Agent正式provider身份与Uniqon身份是否已按当前版本统一。
2. 由平台Owner提供云/HPC/QPU的非敏感接口合同、状态枚举、事件游标、取消语义、业务作业号和测试租户。
3. 由模型Owner提供本地DeepSeek的模型标识、OpenAI兼容或DSH适配协议、tool-call、SSE、结构化输出和限流说明。
4. 跑通两个租户、一个模拟器、一个HPC作业、一个QASM、一次拒绝和一次unknown恢复，不触发真实设备。
5. 根据这10个工作日的实测结果，决定释放或保留260人天储备，并把2000人天基线收紧为正式版本。

在上述输入没有确认前，2000人天应作为预算区间和工作包基线，不应对外承诺具体发布日期。
