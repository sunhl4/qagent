## 一、产品定义：通用 Agent 为基础，量子能力为专业扩展

**Company Agent 首先应当是一款能够实际完成日常工作和软件开发任务的通用 Agent，再接入公司知识、云平台、HPC 与量子计算能力。**

用户以 WorkBuddy、Codex 为参照，重点是“给出目标后，能够读取相关资料、制定步骤、使用工具、观察结果、修正问题并交付文件或代码”，不是只有聊天、说明文档或量子工具菜单。

即使用户没有绑定量子云账号，也应能在其获准工作空间里整理文件、写文档、分析表格、检索资料、修改普通软件并运行测试。不必先创建科学作业、发现量子算法或选择设备。

产品由三部分组成：

- **通用工作能力**：对话、任务规划、文件读写、文档与数据处理、网页检索、代码修改、隔离命令执行和成果交付。
- **企业能力**：账号与项目、既有模型、代码仓、知识库、协作系统、授权与审计。
- **量子专业能力**：动态算法目录、科学计算、云任务、HPC / QPU 协同、结果模板和受监督设备操作。

三部分共用 DeepSeek Harness（DSH）这一套 Agent 运行时和三栏界面；不再新增模型、会话或工具循环。

公司已有成熟云平台、HPC、本地大模型及 DeepSeek，继续复用。参考其他产品的能力与体验，不等于直接嵌入它们的运行时，也不承诺采用同一界面就获得同样的模型效果。

## 二、通用 Agent 必须能做什么

以下是产品能力，不是已注册工具名；具体办公格式是建议的有界验收样例，不把完整办公套件作为上线前置。优先复用插件 / MCP 与现有执行环境，新增或暴露工具仍须正式修订合同和门禁。

### 2.1 任务理解与连续完成

- 接收自然语言目标和明确选择的文件 / 仓库；仅在范围、权限或交付标准确有歧义时追问。
- 按复杂度制定步骤，执行后观察真实工具结果，在授权范围和预算内修正、继续，直到完成或明确阻塞。
- 显示正在做什么、已产生什么、待用户决定什么；支持用户停止当前推理与执行请求。
- 会话恢复沿用 DSH。已受理的后台进程和平台作业由执行服务记录状态，恢复先核对，不能重放整段对话造成重复写入或提交。
- 任务结束交付可打开的文件、差异、报告及验证结论；失败与未验证内容明确列出，不用一段“已完成”的回复代替实际产物。

### 2.2 文件、文档与办公产物

- 在明确授权的目录中列出、查找和读取文件；新建、编辑、整理和保存工作产物，展示来源与修改差异。
- 首期支持文本 / Markdown、CSV、受支持的 XLSX 表格和可提取文本的 PDF；对 DOCX、PPTX 先支持选定模板的生成与预览，不承诺任意复杂版式的无损往返编辑。
- 整理纪要、周报、调研材料、技术方案和演示材料；输出实际文件，不仅在聊天中给出可手工复制的正文。
- 批量改名、移动、覆盖或删除先预览影响；保存采用版本检查或备份，避免覆盖用户并发修改。恢复只承诺已保存版本的文件，不承诺撤销已经发送的邮件或发生的设备动作。
- 本机目录通过浏览器显式选择 / 上传或受管本地连接器接入。服务器 Web 应用不自动取得用户整台电脑的文件权限。

### 2.3 通用编程与命令执行

- 搜索并理解获准仓库，跨文件修改实现、配置和测试，展示变更差异。
- 在隔离开发环境运行 Python、Node、构建、测试以及获准的命令行工具；能够依据失败输出定位问题、修改并再次验证，而不只生成代码建议。
- 支持受控依赖安装和必要开发预览；限制包源与网络，固定或记录依赖版本。脚本、安装钩子与测试都按不可信代码执行处理。
- 使用独立工作树或受限目录保留用户改动；本地修改、创建提交、推送和合并分别授权。发布凭据由可信服务掌握，不能放进模型生成代码的运行环境。
- 通用执行器不持有设备凭据或任意 HPC SSH 密钥，不挂载生产 profile，不通过“运行测试”访问设备控制网。

**允许执行命令是目标能力；禁止的是直接开放生产宿主 shell 或切换到带 shell 的 preset 绕过策略。** 本方案以受合同约束的隔离执行服务提供这项能力，不把安全规则解释成产品永远只能给建议。

### 2.4 数据分析与可视化

- 对普通 CSV / 表格数据进行清洗、计算、统计与绘图；产出分析脚本、环境版本、图表和报告。
- 检查列类型、缺失值、单位、样本范围和失败记录，允许用户审阅所用方法。
- 指标由实际程序计算，模型解释结果与限制。量子科学分析另执行专业语义验证，不能把通用数据脚本当成已验收科学服务。
- 用户生成图表、HTML 或文档在受控预览中展示，不继承主站会话、平台 token 或设备访问权。

### 2.5 网页与外部资料

- 首期提供受管网页搜索、读取与来源引用，用于调研、接口查阅与材料整理；网络受限时使用获准代理或明确报告不可用。
- 网页与下载文件作为未可信内容，不能授予权限或触发隐含执行。抓取服务检查目的地址、重定向、文件大小与类型，不可被用作访问内部敏感服务的通道。
- 交互式浏览器操作属于完整产品目标：在隔离浏览器和获准站点内导航、填表、下载；提交表单、发送或购买须按副作用再次校验。首个通用试点先完成搜索 / 读取，浏览器写操作随后单独验收。
- 不承诺绕过登录、验证码、站点访问限制或公司网络策略。

### 2.6 知识、连接器与可复用工作方法

- 接入获准知识、源码和业务接口，按来源引用；工作成果可整理为草稿，经确认和审核后进入既有知识源。
- Skill 是可复用的工作方法，不是权限或可执行能力本身。安装一份 Skill 不代表其要求的读写、浏览器、命令或邮件工具已经存在。
- 企业连接器或 MCP（Model Context Protocol，工具与资源连接协议）用于服务适配；管理员审核版本、工具合同和数据范围后才暴露，不自动信任发现到的所有工具。
- 邮件、会议、协作系统以及定时任务是后续连接范围；先做草稿与人工触发，再逐项验收发送、发布、去重和撤权。事件触发复用受管 DSH 入口，不另起后台模型循环。
- 跨会话记忆区分用户偏好、任务状态和公司正式知识；明确范围、查看 / 删除与撤权规则，不静默采集所有文件或共享所有对话。

## 三、让正常工作流畅，而不是每一步都审批

### 已授权范围内连续完成

可信策略预先限定用户 / 项目、工作目录、模型目的地、可用工具、隔离环境、网络、资源和时间。用户提出清楚任务后，允许范围内的读取、草稿编辑、普通计算和测试连续执行，不因每条命令或每个文件改动都要求重复点击批准。

该授权由服务校验，不能由模型声明“只读”“安全命令”来取得。命令可能包含子进程、依赖钩子和隐藏副作用，因此以隔离环境和资源 / 网络限制兜底，不仅依靠命令字符串白名单。

### 需要额外确认的动作

扩大目录或资料范围、改变联网范围、批量破坏性修改、外发消息、提交 / 推送 / 发布、使用额外付费资源等，按组织策略确认具体内容与目标。批准绑定动作快照和有效范围；编辑后的内容不能沿用旧发布审批。

设备继续执行更严格规则：`quantum_device_run` 在 `lab / sign` 必须 ask，在 `boot / algo` 必须 deny。一次普通研发任务、内部账号或编程沙箱授权不能覆盖后续设备调用。

### 停止、失败与恢复

停止对话生成、终止隔离进程、取消云作业是不同操作。展示各自真实状态，已经发生的写入、发送或执行不会因关闭聊天自动回滚。普通任务可按预算修正；可能发生外部副作用且结果未知时先查状态，不盲目重发。

## 四、沿用唯一运行时，补齐真实执行能力

### DSH 与模型

DSH 负责理解、规划、模型交互、工具生命周期和会话事件。通过其受管模型适配接入现有本地模型 / DeepSeek；模型网关只负责协议、鉴权、限流和推理，不另做任务规划或工具执行循环。

本地模型能聊天不代表能可靠完成跨文件修改和多步工具任务。用公司的真实办公、编程、分析样例验收；记录完成率、返工、越权阻断、延迟和成本，不凭品牌承诺与 Codex 效果一致。内部资料不因任务失败静默转发到外部模型。

### Company Agent 与执行服务

- `contracts/` 声明新增能力、参数、结果、provider 和策略；`src/company_agent/` 负责校验与适配；`packages/` 只注册并转调 `company-agent invoke`；`profiles/` 不加入业务逻辑。
- 文件、开发、分析与浏览器执行服务只接受已校验动作，管理进程、输出与状态；它们不自主调用模型或编排工具循环。可以复用现有服务，不要求一类能力新建一个微服务。
- 完整正文和产物走授权内容通道；工具仅返回合同允许的短片段、差异摘要和必要引用。源码按需分段读取，不一次返回完整仓库；原有科学敏感内容限制不放宽。
- 现有句柄仍只有 `asset_id`、`circuit_id`、`twin_id`。文件 / 命令结果如需资产化，先定义 `asset_id` 的通用资产合同；内部任务、仓库、文件关联键留在业务层，不擅自新增模型句柄或伪装成科学资产。
- Agent 不直接 import 科学实现。科学仓库中的开发 / 测试由隔离开发服务执行，已发布科学运行仍经平台动态 `algorithm.catalog` 与 `component_id` 接入。

### 与官方 Codex 的关系

“像 Codex 一样完成开发任务”是能力要求，不等于“让主模型调用官方 Codex 再运行第二套 Agent”。官方 Codex 宿主 provider 继续保持 `permissionMode: never`、`inheritsParentContext: false`，不挂模型可见委派工具，也不继承设备工具。

若以后确需并行任务，先验证固定版本 DSH 自有生命周期与隔离支持；本版不新增委派链或多 Agent 调度器，不把并行数量当成通用能力完成标准。

## 五、当前仓库与目标之间的实际差距

本次只读核对如下：

- 当前 `contracts/tools.json` 为 2.0.0，包含公司能力查询、受管知识短检索、静态工作流校验，以及科学目录 / 资产 / 模拟 / 编译 / 设备工具；尚无完整文件编辑、通用命令、办公生成、浏览器或 Git 交付合同。
- 当前 profile 中网页插件配置 `fetch: false`；不能将上游“有网页工具”理解为本项目已有完整网页检索 / 浏览器工作流。具体暴露工具仍以固定版本运行时门禁为准。
- `packages/company-agent-policy/src/index.js` 当前只接受设备执行的 `ask`；新增发布、覆盖等确认能力需要同步合同与策略测试，不能只画审批按钮或把其他动作冒充设备调用。
- `company_workflow_validate` 明确只校验结构和参数，不执行计划；Skill、原型界面和宿主 Codex provider 都不能替代缺失的生产工具。

因此，**当前实现是受控专业能力基础，目标产品应升级为能完成通用任务的公司 Agent；不能把这份设计当成已经具备 WorkBuddy / Codex 同等能力。**

## 六、首期顺序修订

### 阶段 0：盘点与合同设计

复用现有身份、模型和存储，核对 DSH 固定版本；确定一个获准工作空间、一套隔离开发环境、一个网页读取路径和受支持文档格式。盘点文件 / 开发服务能复用多少，再定义合同、授权与结果通道。

### 阶段 1：通用 Agent 内部可用版

首期必须同时通过办公、编程、数据分析与网页调研四类代表性任务：文件实际可写、测试实际可运行、计算结果真实、产物可打开。范围内连续工作，越界时明确阻塞或审批。

只有问答、知识检索或代码建议不算阶段 1 完成。继续使用 v0.5 三栏视觉基准；设计说明留在文档，操作页显示文件、差异、进度、产物和必要审批。

### 阶段 2：企业协作与专业研发

接入代码仓交付、知识候选审核、更多办公格式、受管浏览器操作及协作系统；并行接入一个实际 HPC / 模拟任务和真实结果报告。必要的企业身份 / 权限基础必须在阶段 1 到位，不推迟到本阶段。

### 阶段 3：客户服务与设备扩展

开放外部租户前单独完成隔离、配额、数据流向与商业验收；量子云、账单和真机沿用专项验收，设备逐次审批不变。通用 Agent 的上线不依赖所有量子后端完成。

## 七、首期验收任务

- **办公交付**：给定获准的会议记录与材料，生成周报 DOCX 和选定模板的 PPTX；文件可打开、来源可追溯、用户编辑未被覆盖。
- **编程交付**：给定测试仓库中的缺陷，完成跨文件修改、补测试、运行验证；交付差异和真实测试记录。失败用例未解决时如实说明，不能修改测试结果伪造成功。
- **数据交付**：给定 CSV / XLSX，完成清洗、统计、图表与报告；保存脚本、环境和输入版本，人工可复算。
- **调研交付**：检索获准网页和资料，生成有来源的比较报告；访问失败或信息不足显式标注，不编造引用。
- **授权体验**：同一获准任务的普通编辑和测试可连续完成；跨项目读取、目录越界、恶意依赖获取密钥或访问设备必须阻断；发布 / 外发时绑定实际内容确认。
- **恢复与诚实状态**：断连恢复能找到原产物和进程状态，未知外部执行不重复提交；没有工具证据不显示“已保存”“已测试”或“已发送”。

这些是待执行验收用例，本次没有运行真实模型、办公渲染、沙箱命令或业务服务测试。

## 八、工期口径随范围更新

原 v1.2 的 9–15 / 12–20 / 28–50 周是原定量子工作空间有界范围，不再代表整个产品的首期与完整目标。它仍可用于量子专项参考，不能直接承诺“通用 Agent 加量子平台”的总交付时间。

新的排期先盘点 DSH、现有插件 / MCP、Skills 和公司服务可直接复用多少，再核算装配、薄适配、隔离与验收；通用任务运行、文件、办公、命令、网页等不默认全部自研。只为确有缺口的能力增加实现工作，并扣除旧方案身份、界面、模型、知识及分析的重叠。以 [v0.7 集成路线](company-agent-dsh-integration-v0.7.zh-CN.md) 为准，不把两份估算简单相加，也不在复用盘点前凭空给新的总周数。
