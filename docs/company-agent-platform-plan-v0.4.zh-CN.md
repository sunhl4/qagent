## 一、核心定位：公司能力与日常工作的统一入口

Company Agent 面向三类工作：内部研发、外部客户服务、通用办公与编码。三者共用产品界面和 DeepSeek Harness（DSH）运行时，但按用户、组织、项目、数据等级和执行环境隔离权限。

量子能力是这个平台的重要专业能力，不应成为每次对话的强制入口。用户写周报、读文档、整理会议纪要、分析普通文件或讨论代码时，可以直接开始；只有任务需要时，才发现并使用已获授权的科学、知识或开发服务。

公司已有软件算法、内部高性能计算集群（HPC）、对外云平台和知识库；用户另于 2026-10-21 补充已有本地部署的大模型和 DeepSeek。云平台与 HPC 的成熟度沿用用户已确认前提，模型层同样按既有服务复用。需要盘点的是 Agent 所需 API、认证方式、联网范围和实际接入状态。本项目建设连接、权限与交互，不重复建设已有的算法平台、集群调度器、代码仓、知识正文库、账本或基础推理服务。

### 内部研发

首批围绕量子算法组：查资料与接口 → 阅读授权代码 → 形成修改方案 → 隔离开发与测试 → 获准的 HPC 计算 / 模拟验证 → 分析报告 → 提交代码与知识候选。

同一套机制可逐步服务软件、测试、应用和设备工程团队。内部身份不等于全公司数据可读；源码读取、代码提交、计算运行、设备审批和知识发布分别授权。硬件控制、校准应用和实时联锁仍留在专业设备系统。

### 外部服务

外部客户使用同一产品形态完成已发布知识问答、授权算法发现、云任务提交、结果分析和报告查看。客户只能访问自己的组织 / 项目与公开或获授权的产品内容。

内部 HPC 根入口可以按后端能力清单不呈现，不能让客户填写地址就访问内网。公司若把某些 HPC 能力作为云服务出售，由对外资源网关暴露受限服务，不能直接共享内部集群账号。支持人员进入客户项目须有显式授权、时限与审计；员工身份不自动获得客户正文。

### 日常办公与编码

支持文档撰写、技术调研、材料整理、数据分析、代码解释、修改建议、测试与评审等工作。读取文件、编辑代码、运行程序、外发邮件 / 消息、发布内容等动作分别检查权限和副作用；普通对话不要求先建科学作业。

产品可展示“内部研发、客户服务、日常工作”的场景模板，但这些只是任务入口，不是角色、授权或可以随意切换的生产 preset（运行配置）。用户不能通过点击“开发”获得 shell、内网或设备权限。

## 二、产品结构：保留三栏，扩展工作空间内容

### 左栏

保留 v0.3 顺序：云平台（默认收起）→ HPC（默认收起）→ 本机文件 → 工作空间与会话；底部固定 Agent 账号和设置。对未获授权的资源，服务端不返回目录数据；折叠只是显示偏好。

工作空间可以对应一个研发项目、客户项目或个人工作，不等于磁盘目录本身。它关联：

- DSH 会话和明确选择的文件 / 仓库。
- 当前项目的算法与计算服务使用权限。
- 可检索的知识范围，以及项目知识草稿 / 待审核条目。
- 代码版本、测试证据、计算与分析产物。

知识入口放在对应工作空间内和中栏首页，不打乱原有四层目录。允许看到哪些知识库与源码，由后端返回，而不是靠选择工作场景决定。

### 中栏

除云 / HPC 网页、文件、报告、可视化和 Canvas，增加：

- 知识中心：按权限搜索与查看原文、版本、引用和适用范围。
- 知识草稿与审核：从当前工作中整理候选，检查来源、差异、可见范围，提交审核。
- 开发工作页：需求与文件关联、修改差异、测试日志摘要、代码评审与交付证据。
- 普通工作产物：文档、纪要、研究笔记、图表与待发送材料。

知识生成和代码执行的状态由对应服务确认；界面不能因为模型回复“已保存 / 已测试”就标为完成。当前原型只演示流程，没有实际写知识库或执行代码。

### 右栏和设置

右栏原样复用 DSH 的消息、输入框、模型显示、上下文用量、工具记录和审批。设置保留 Agent 账号、云平台、HPC、模型与对话，并增加“知识与开发”区域：

- 展示当前项目获授权的知识来源和允许的保存范围；知识发布权限不能由个人开关授予。
- 展示受管代码仓、开发环境、可运行测试和资源限制。
- 展示数据可发送到哪些获准模型服务；模型选择不能绕过组织的数据出域策略。

不增加第二份模型配置、第二套聊天或第二套工具执行循环。场景模板 / Skill 只描述工作方法，不新增授权，不固化算法名单，也不自动发布知识。

## 三、系统职责：通用能力与公司能力共同接入

### 1. 统一产品与身份层

工作空间前端与后端负责登录、组织项目、连接管理、内容导航及会话关联；知识浏览、任务查询、设置等正常业务操作可以直接经鉴权 API 完成，无需消耗模型推理。

DSH 原生 UI 可以共用，不代表多用户可以共享运行时 token、进程环境、工作目录或缓存。内部、外部至少具有独立身份范围和资源 / 网络策略；运行实例是否按用户或项目隔离，以验证结果决定，不能用前端角色切换代替隔离。

### 2. DSH 交互与能力编排层

DSH 负责理解需求、对话和工具生命周期。Company Agent 合同负责已注册工具的参数、策略、结果与来源校验。通用能力和公司专业能力都在这套机制下接入；缺失能力时明确说明，不伪造执行。

能力类别包括知识访问、开发协作、文件与办公、量子软件、计算资源、结果分析。这是产品分类，不是本次新增的工具名，也不是必须拆成六个独立服务。优先复用受管且已经验证的现有接口。

### 3. 公司服务与受管连接

- **软件算法平台**：拥有算法实现、组件目录、版本和科学资产；可用算法仅来自 `algorithm.catalog` 的平台 `component_id`。
- **代码仓与开发服务**：拥有代码版本、分支、修改差异、测试和评审记录；为 DSH 提供受限开发动作，不拥有 Agent 对话循环。
- **HPC / 云平台**：拥有队列、持久作业、资源限额、受理、取消、用量和结果；长任务不依赖聊天进程存活。
- **企业知识服务**：接入既有知识正文与权限，管理检索索引、候选提交、评审、版本发布与撤回。可先做适配，不先重建全套知识管理平台。
- **文件与分析服务**：传递授权文件和产物，执行受管分析；大正文进入中栏，模型仅接收合同允许的短结果。

统一记录用户、项目、来源版本与相关操作，具体业务关联键留在业务服务；不把它们擅自扩展为科学工具句柄。

## 四、知识使用与沉淀：边工作边形成可复用资料

### 4.1 知识范围

- 公开 / 已发布产品知识：可对外检索的文档和支持资料。
- 公司内部知识：按部门、岗位和文档权限授予，不等于全员可读。
- 项目与团队知识：研发过程、接口约定、已验证经验，默认不跨项目。
- 个人或当前工作空间草稿：用于整理自己的工作；仍继承来源数据限制，不能把受限材料复制到个人空间后任意外发。
- 客户私有知识：归客户组织 / 项目使用，不因部署在同一产品就并入公司知识库。

这些是逻辑访问范围，不要求分别建五套数据库。查询、原文、引用、下载、缓存和索引更新都按当前授权处理。组合多份资料生成的条目，默认不能比任一来源的限制更宽；希望扩大范围时须单独审核或删去受限内容。

### 4.2 两种沉淀方式

**主动保存**：用户选中回答、代码差异、报告或片段，点击“整理为知识草稿”，或在 DSH 中明确提出保存要求。

**工作节点提醒**：代码合并、问题关闭、实验报告确认后，提示“是否总结本次经验”。可在用户和项目明确启用后生成私有候选；触发事件仅通知或调用既有受管流程，不运行新的后台 Agent / 模型循环。不得静默上传所有聊天、文件或目录。

个人草稿保存应轻量；团队共享和对外发布按风险增加审核。避免每次记笔记都走长流程，也避免把“顺手沉淀”做成无审核的公司知识覆盖。

### 4.3 从工作记录到正式知识的流程

1. **选择证据**：当前对话中明确选择的片段、代码版本、测试记录、报告、文档引用；先确认读取和派生许可。
2. **形成草稿**：提取问题、适用版本、解决方法、证据、限制与作者。模型推断和未经验证建议须单独标注。
3. **自动检查**：检测密钥 / 敏感数据、版权和客户来源、重复条目、过期引用及范围扩大；检查结果辅助决策，不作为绝对无泄漏保证。
4. **作者确认**：中栏审阅草稿、原文差异、来源及保存范围，可修改或放弃。
5. **提交审核**：服务端创建待审记录；用户有读取权限不等于有发布权限。团队共享由知识维护人按业务规则批准；对外发布增加产品 / 资料所有者审核。
6. **版本发布与索引**：批准版本存到既有知识源，检索索引单独报告同步状态。显示“已保存待索引”与“已可检索”，不能混成一步成功。
7. **维护与撤回**：旧接口、撤销权限、错误结论或来源删除触发复核；撤回后停止新检索与下载并清理适用缓存，历史引用显示版本 / 撤回状态。

草稿、待审、退回修改、已批准、已发布、已撤回是内容状态；待索引 / 已同步 / 同步失败是检索状态。网络重试不创建重复条目，旧版本审批不覆盖新编辑，索引失败只恢复索引而不重复生成内容。知识服务应有幂等、版本冲突与审计规则。

### 4.4 最少知识元数据

每条正式知识至少记录标题、问题与结论、适用软件 / 接口版本、来源链接与版本、验证证据、作者 / 审核者、组织与项目、可见范围、敏感级别、更新时间、有效性 / 复核时间和与旧条目的关系。

代码仓是代码真源，平台目录是算法能力真源，知识库是解释与经验来源。知识条目可以引用它们，不复制一份永久算法名单，不把测试失败的建议变成“已验证操作规范”。

检索增补、个人记忆和模型训练是不同机制。本期知识沉淀只建立受控文档及索引，不自动训练模型、不自动跨会话携带私密材料，也不把整段聊天当公司正式事实。

## 五、通用编码：复用体验，单独限制执行环境

### 当前事实

本仓生产 profile（运行组合）只允许项目管理的 `company-agent` system-trust preset；关闭内置和用户可写 preset 根。官方 Codex 仅注册宿主 provider，保持 `permissionMode: never`、`inheritsParentContext: false`，不挂载模型可见的委派工具。

因此，“底层使用 DSH”不能证明当前产品已经支持任意文件写入、终端执行、Git 提交或完整自动编码。`company-software-development` Skill 是工作指引，不是赋权工具；现有知识能力是受管文本短检索，不含企业知识写入、评审和租户隔离系统。

### 目标开发体验

用户可以在授权仓库中讨论代码、生成修改差异、申请测试并审阅结果；确认后提交到指定分支 / 代码评审流程。DSH 仍负责会话与调用，不引入另一个模型或工具调度循环。

实现路径优先采用独立受管开发服务：

- 每用户 / 项目使用受限仓库快照、工作树或隔离环境；模型不能任意指定宿主路径。
- 以代码版本和修改摘要绑定写入与测试；限制目录、文件数量、时间、存储、CPU / 内存及并发。
- 依赖安装、测试脚本和项目钩子同样是不可信执行；使用无生产凭据的环境，默认限制出站网络。
- 沙箱不持有设备凭据、云平台高权限 token、HPC 通用 SSH 密钥或可修改生产 profile 的挂载；不能访问生产设备网段。
- 若需要代码仓提交，由沙箱外可信服务使用最小权限、短期凭据执行；测试进程不能读取 Git 发布凭据。
- 常规文件编辑和无副作用测试可在项目已授权范围内执行；删除、外发、发布或扩大范围的动作独立确认。设备始终走既有逐次审批。
- 确实需要 HPC 验证时，经获授权的作业服务提交受限任务；测试环境不能借“跑测试”取得内网或设备入口。

公司科学算法代码仍在算法平台对应仓库开发，Agent 不直接 import 科学实现。代码“可编译 / 测试通过”不等于算法已获科学验收或可以接真机；合并、目录注册、服务准入、设备审批分别负责。

上述是待建接入方案，不新增可切换的 shell 编码 preset，也不启用 Codex 模型委派。若后续增加工具，先改合同，再改 Python adapter、DSH 注册与测试；工具结果仍使用短摘要，不回传完整代码库或敏感日志。

## 六、数据与模型选择的联动

### 6.1 首期复用已部署的大模型与 DeepSeek

从公司已经提供的模型服务中确定一个获准默认入口，先验证问答、工具调用与真实任务；需要其他模型时，仍通过同一 DSH 的模型适配机制配置，不增加独立研究、执行或后台模型循环。已有 DeepSeek 模型服务不等于已接入 DSH，两者分别承担推理与 Agent 运行时职责。

首期只需确认可用模型 / 版本、接口协议、鉴权方式、流式工具参数、上下文与限流规则、数据与日志保留策略。GPU / NPU 和推理引擎选型不是本轮产品前置工作；出现具体兼容或性能瓶颈时再由现有推理团队处理。协议直接兼容则不额外引入 deepseek-recipe，底层内核优化也不进入必选依赖。

验收检查动态能力目录与参数、拒绝后停止、未知执行不自动重跑、引用与结果解释，以及并发会话的隔离。科学指标由受管计算 / 分析服务提供，模型不代替计算、测试或设备审批。本地部署也不自动使模型掌握公司最新知识，仍须接入获准资料、版本化引用与结果服务。

### 6.2 本地与外部服务适用同样的授权边界

模型配置继续复用 DSH；选择可用模型的范围受组织策略限制。内部源码、客户资料和设备文档能否送到外部推理服务，按真实数据许可和公司规则决定，不因用户填了 API key 就放行。

本地模型网关、日志、缓存和检索仍按用户 / 项目授权与保留策略处理，不能因“在内网”而共享所有上下文。默认沿用获准本地服务；故障时明确报告，不静默切换到公网 DeepSeek 或其他外部模型。任何获准的模型切换都须重新检查数据目的地和现有上下文。

## 七、三条典型流程

### 内部算法研发

创建项目工作空间 → 读取授权接口 / 知识 / 代码 → 提出版本化修改 → 隔离测试 → 获准模拟或 HPC 作业 → 中栏查看真实报告 → 审阅代码交付 → 将选定经验整理为知识候选 → 维护人审核后供授权同事检索。

代码、实验结果、报告和知识分别版本化并通过引用关联。需要设备实验时单独走设备准入与审批，不能把完整研发任务一次性视作设备授权。

### 外部客户计算服务

客户登录自己的项目 → 查询已发布文档和获准算法 → 通过云平台受理任务 → 如涉及设备则确认预算并逐次审批 → 查看结果 / 报告与账单 → 保存到客户自己的项目知识。

客户数据默认不进入公司共享知识或训练集。共性问题只有在合法授权、去敏和审核后，才可能形成对外支持文档。

### 员工日常工作

直接发起对话 → 在许可范围读取文件和知识 → 中栏生成文档 / 图表 / 代码差异 → 用户确认保存或发送 → 可选整理为个人或项目知识草稿。

这条流程不要求连接量子设备、创建科学作业或进入算法目录。实际文件写入、程序执行和消息发送能力必须先完成受管接入。

## 九、验收与衡量方式

试点开始前与团队约定基线和目标，不先虚构效果指标。

- **研发可用性**：真实任务能关联资料、代码、测试与报告；无法验证的结果如实显示，不把模型回复作为测试成功。
- **日常价值**：记录同类任务完成时间、实际采用的文档 / 修改、需要人工返工的原因；不只统计聊天次数。
- **知识质量**：观察候选采纳、重复率、过期发现、引用可核验性、检索相关性和后续复用情况；数量不是唯一目标。
- **知识权限**：受限来源不能被宽范围发布；作者和审核者权限独立；客户数据不能进入公司共享索引；撤回后旧缓存、摘要和引用受控。
- **编码隔离**：恶意测试 / 依赖不能读取生产凭据、修改受管 profile、访问设备或绕过审批；并发执行与路径越界被限制。
- **模型出域**：用户切换到不允许接收当前源码 / 客户资料的模型时，服务端阻止发送或构建经过验证的新上下文。
- **外部隔离**：客户猜测目录、文件、会话或结果引用被拒绝；内部支持人员访问须明确授权。
- **现有硬边界**：DSH 唯一 Runtime；科学句柄与结果限制不变；`quantum_device_run` 在 `lab / sign` 必须 ask，在 `boot / algo` 必须 deny；只有对应 `ionstack-twinrun` 设备调用可返回 `twin_id`。
