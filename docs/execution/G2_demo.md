## 一位客户

1. 打开 3080。输入框里写一句人话，例如：「扫一下氢分子，先估计，再上我们的机器，给我短回执。」不必 recipe 名。
2. 右侧「在办」出现待批，你点「批准上机」或「先不上机」。还是同一条对话，不是再开一套程序。
3. 看脸：未签收不是绿封条。排队、你先不批、失败，都不会盖绿印，也不会写成「已签收」。
4. 已签收的回执可以在 3080 下载短 JSON，并在脸上点核验。回执里没有电路正文，没有口令。换一台机器仍跑：

   `python3 scripts/verify_receipt.py receipt.json`

5. 云没开不上 IBM。设置里云入口空着，不会去上 IBM 或别人的云作业，更不会拿外机冒充我们的机器。
6. 没有活机器时老实说失败。不会手写一个假 `twin_id`。只有这边的活机器签收后，才可能出现真的 `twin_id`。Aer / IBM / 本地卡 / Cirq 都不许冒充。Cirq 不是我们的机器，不许铸 `twin_id`，provenance 不许写成 `qccd-twin`。
7. 打开设置：看不到超算密码值。密钥栏最多写「已保存」。

一位客户走完，只证明你自己的交办、脸和回执说得清。不要把它说成门禁已过。

## 两位客户（租户隔离）

两位客户各走各的。对话分开，不共用一条 session / 气泡。3080 可以用 `?tenant=`（例如 cust-a / cust-b）带上租户；请求头仍是租户头。空租户是组内，看见全部。在办分开，回执分开。

1. 客户 A：打开 3080，地址带 `?tenant=cust-a`。请求头仍是 `X-QAGENT-TENANT: cust-a`。用平常话交办一件自己的事。不必 recipe 名。
2. 客户 B：打开 3080，地址带 `?tenant=cust-b`。请求头仍是 `X-QAGENT-TENANT: cust-b`。另交办一件。B 的在办里看不见 A。B 去打开 A 的交办：这边就当没有。
3. A 看自己的脸：未签收不是绿封条。B 同样。谁都不要把别人的灰条当成自己的绿印。
4. A 在 3080 下载自己已签收的短 JSON，并在脸上点核验。没有电路正文，也看不到 B 的交办。换一台机器仍跑 `python3 scripts/verify_receipt.py receipt.json`。B 只能核 B 的回执。
5. 两位都一样：云没开不上 IBM。没有活机器时诚实失败，不假 `twin_id`。Aer / IBM / 本地卡 / Cirq 都不许冒充。Cirq 不是我们的机器，不许铸 `twin_id`，provenance 不许写成 `qccd-twin`。
6. 两位都看不到超算密码，也看不到对方的租户交办。

隔离成立，只说明客户 A 不见客户 B。组内空租户仍看见全部，那不是客户脸。仍不是过门证明。

## 当场要看见

- 平常话就能交办。
- 客户 A 不见客户 B（3080 `?tenant=`；请求头仍是 `X-QAGENT-TENANT`）。
- 空租户是组内，看见全部。
- 未签收不是绿封条。
- 已签收的回执能在 3080 下载短 JSON，并在脸上点核验；另一台机器仍能跑 `verify_receipt.py`。
- 云关时不上 IBM。
- 没有活机器时诚实，没有假 `twin_id`。Aer / IBM / 本地卡 / Cirq 都不许冒充。Cirq 不是我们的机器。

## 当场不要看见

- 别人的在办或回执。
- 电路正文、QASM、超算密码。
- 未签收却盖了绿封条。
- 云没开却声称 IBM 已跑完。
- 手写出来的 `twin_id`。
- 把 Cirq 说成我们的机器，或把 Cirq 的 provenance 写成 `qccd-twin`。

## 失败怎么记

当场抄你看见的：谁的租户、有没有绿封条、回执里有没有电路正文、IBM 有没有被挡住、有没有假 `twin_id`、有没有把 Cirq 说成我们的机器。缺哪项就写缺。不要补一个假 `twin_id`，不要把失败改口成过门。
