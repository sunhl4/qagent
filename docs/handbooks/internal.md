# Qagent 组内手册

给值班同事看。客户那本另写。造包仍用 Cursor / Codex；用包只走这一套脑和脸。不要另开第三套循环，也不要用 Qagent 去改 ionstack / qdata 内核。

## 脑是 dsh，脸是 3080

脑是 `dsh --profile qagent`。脸是 3080。人在 3080 说话，话进同一条 dsh session。不要把 `services/agent.py` 当成产品循环，不要再养一套自己的 agent loop。

3080 只是公司脸：对话、在办、批准、短回执。模型地址、软件包目录、超算和量子账户，都收在设置里的组内一块。关掉模型池时，界面要老实说还没接上，不要假装已经在算。

完整改文件、跑命令，仍走组内 runtime。客户面不是 Finder，也不是三房间。

## 只有三个句柄

全栈只认三个句柄：`circuit_id`、`asset_id`、`twin_id`。不要发明第四个。

- 线路钉住以后才有 `circuit_id`。对话里不要塞电路全文。
- 资产卡、配方跑完留下 `asset_id`。
- `twin_id` 只有 ionstack TwinRun 能发。Aer、IBM、本地卡的来源都不是 `qccd-twin`，不许抄、不许在本地手写一个。

造包时 TwinRun 对官方 Codex 不可见。algo 调 TwinRun 必须拦下。不要在对话里、夹具里、死链路上铸假的 `twin_id`。没通就失败，不要假 done。

Cirq 已在软件包目录，`kind` 是互通，provenance 不是我们的机器。Pennylane 已 reserved，不在目录，也不在软件包目录 / `engines[]`。再加真机仍按加包说明登记。加包不是加句柄。

## 上机要问人，批准走同一 session

要上真机或孪生，必须先问人。3080 右侧「在办」出现待批，人点「批准上机」或「先不上机」。批准走同一条 session：不要新开对话，不要另起 loop，不要把「批准」当成又一句 prompt。

没有待批时，老实说现在没有待拍板的上机。不要因此补一个 `twin_id`。换线路再签，必须还是当初问过的那条，不能偷偷换电路正文。

## 不要把 CAL、shuttle 当工具

校准表、shuttle、MS 矩阵是机器内部的事。不要把它们登记成工具，不要让模型去调，不要写进回执。北向只交该交的字段。Skill 触发也不能绕过「先问人」。

知识库只放手册、已发布规范、公开摘要。原始比特串、未脱敏计数、整段电路，都不要当知识条。

## 设置在组内，密钥不进对话

模型、软件包目录、超算和量子账户，放在 3080 设置里，而且是组内那一块。密钥只有三枚：大模型钥匙、超算口令、量子口令。页面只显示「已保存」，不回填值。

密钥不进对话，不进回给模型的工作台 JSON，不进 session 那一句人话。提交作业可以在本机用口令做南向认证，但不要把值送回模型。云地址如果填了，也不是第四个句柄，IBM 默认仍拒绝。

## 值班看实验记录，未就绪开设置

组内可只读看实验记录（ELN）。HTTP 是 GET，不要写 POST。可按交办过滤。拒铸行（claim_blocked）看得见短 reason（例如 Cirq 拒铸）。没有密钥、没有电路正文。仍只有 `circuit_id`、`asset_id`、`twin_id`。

工作台未就绪时，3080 会打开设置（`open_settings` / 设置对话框）。仍是同一张脸，不是第三套 loop。

组内空租户看见全部交办和实验记录。客户脸用 `?tenant=`，请求头带租户。空租户不要带头。仍是同一张脸。

已设租户各走各的，各一条对话，不共用一条 session。空租户仍是组内那条。

## 值班怎么走

1. 人用平常话说要算什么。不必先报内部配方名。
2. 需要上机就出现在办。问人。同一 session 批或拒。
3. 有活 TwinRun 才签收。没通就失败，不要假 id。
4. 组外只能拿走短回执，没有电路正文。

对照：客户本里写「未签收不是绿封条」。组内不要把排队、失败、先不批画成已签收。

## 值班时怎么回话

模型没接上：说先接模型，不要空跑一遍化学。

上机还没人点：指右侧在办，等同一 session 的批准，不要自己替人点头。

Twin 不通：说失败，停住。不要补编号，不要把 Aer 或 IBM 的结果说成我们的机器已经签收。

客户要带走东西：只给短回执。没有电路正文，没有口令。对方用核对脚本即可，不必把线路图纸交出去。

有人想加「作业号」「任务号」当第四样通货：拦住。还是那三个句柄。CAL、shuttle 仍然不是工具。

## 和客户面怎么对齐

对外只讲平常话、批准、绿封条、短回执。对内才讲 `dsh --profile qagent`、三句柄、TwinRun、组内设置。同一张脸，两套说法，不是两套循环。`start_ui.sh` 第二行是客户脸：同一 `?token=` 加上 `role=customer`，仍是 `127.0.0.1`，这不是 G2 过门。

密钥继续留在设置里。对话里只走人话。不要把钥匙贴进气泡，也不要让演示账号在屏幕上露出超算密码。

## 不要做

- 不要用 Qagent 改科学核，不要把 Cursor 当客户交付面。
- 不要把别人的 IBM 作业说成我们的机器。
- 不要训权重，不要把未脱敏实验塞进知识库。
- 不要 commit，除非人明确说。
