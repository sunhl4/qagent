# 调研深度复核：撤回项与更正原则

日期：2026-10-22。本文记录原 A–G 稿中必须更正的计数、证据和架构推断；每个上游项目的最终依据以 `reviewed/Hxx-*.zh-CN.md` 的固定提交源码为准。公司实现依据见 [本地架构对照](03-本地架构对照与工程边界.zh-CN.md)。

## 1. 完成度与研究对象

**撤回“深读 48 项”和此前的“全部结案”。** 原清单逐行只有 57 个独立项目。第一批是 13 项而非 12 项；前四批合计 29 项，第五批增加 9 个有专题稿的项目，另有 19 项只有清单速评。这只能证明原来 38 项有专题稿、19 项未做专题深读；专题稿存在也不代表证据已经充分。

“61 项”“46 份文档”“附属仓”“深读+速评”的数字不能相互替代。复核以编号 01–57 去重，不把 Letta Code、OTel GenAI 拆分仓或两篇同一项目文档另算项目。

## 2. 证据可信度

撤回“旧稿全部结论均有核过的文件行号证据”。若引用行号与正文不匹配、引用中混入转述、只看目录就推断实现，均不满足源码分析标准。本轮补真实 SHA、实际实现链路、测试断言和许可证来源，并使用逐字引用检查。

“某目录存在”最多证明结构，不能证明登录、权限、多租户、出网隔离、可靠持久化或收费功能已经实现。README 可以解释设计意图，但具体行为应以实现和测试支撑。

## 3. 维护状态

撤回对 Aider、SWE-agent、Continue 等项目的无依据“停推”标签。某次提交较早不代表停止维护，`git ls-remote` 也不能证明最后提交日期。本轮记录固定提交时间，除非获得维护者声明或明确归档事实，不另作维护状态推断。

## 4. 许可证

撤回“AGPL 是公司硬规则冲突、禁止使用”和“参考机制无风险”等绝对结论。本项目规则限制的是本轮不得复制上游实现及生产架构边界，并没有一条通用 AGPL 禁令。实际使用、修改、部署或分发的义务要根据许可证、具体模块和集成方式审查。

撤回未经具体条文限定的“Open WebUI 任何修改都需要企业许可”，以及未查具体目录就把 GitHub MCP、Phoenix、Daytona、open-swe 等项目归为某一种许可的说法。源码开放、OSI 意义的开源、商业功能授权和商标/品牌要求应分开记录。

本轮直接核对的新事实：open-swe 根 LICENSE 是 MIT；Open Interpreter 当前 README 描述 Rust/Codex fork 且根许可 Apache-2.0，旧稿沿用其历史 Python/AGPL 形态已不适用；Daytona 当前 README 明示 2026年6月后核心开发转私有，公开源码需固定 v0.190.0 历史版本，不能称当前仍有完整可审新版。

## 5. 审批策略不是待从零补建

旧稿建议“把设备 ask/deny 从工具内 if 移到策略文件”，但当前 `contracts/policy.json` 已声明该策略。Python 再校验合同不变量是防御措施，不是应删除的重复实现。

撤回把 inspect_ai 的五值审批结果直接套进公司权限合同的建议。公司仍是 `allow/ask/deny`。参数修改、升级审批和超时恢复可以另设计，但不能产生设备免审、旧批准覆盖新参数或模型判低风险直接放行。

## 6. 输出预算不能跨层混用

现有 `contracts/results.json` 已限制总结果 64,000 字节、字符串 4,000 字节、列表 32 项等。撤回“一期新增 16KB 默认输出预算”的断言式建议。

上下文输入截断、模型生成长度、provider HTTP 响应上限、工具结果限制、遥测 span 入库上限互不等价。科学结果超过边界时应拒绝或转为平台资产摘要，不能截断后仍声明完整成功。Ollama、Inspect 与 Langfuse 的参数须按其真实作用层分别解读。

## 7. 宽容解析、MCP 元数据与前端开关不能授权

撤回把 promptfoo 攻击样本修复、多别名工具调用解析直接搬进生产信封的建议。公司必须拒绝未知工具和坏信封；兼容解析可用于测试素材，不可默默扩张执行入口。

撤回“fastmcp 中间件已经足够完整治理”和“per-tool autoApprove 可作为设备免审位”的推断。协议框架、只读注解、显示过滤和审批 UI 都不能替代公司执行期策略；第三方 MCP 工具描述也是不可信输入。

本轮额外核实：FastMCP `AuthMiddleware` 文档明确 STDIO 跳过 OAuth 检查；Docker MCP Gateway `NewDefaultClient()` 在非 Desktop 或治理特性不可用时返回全允许 `NoopClient`。因此“用了网关/认证中间件就失败闭合”与当前源码不符，不能作为公司生产准入论据。

## 8. 沙箱、白名单与检查点

撤回“看到一个 network_mode: none 就证明所有 Docker 沙箱默认断网”“Python import 白名单直接等于安全执行沙箱”“microVM 配置语义可即抄即用”的推断。

强隔离需要实际进程/内核边界、挂载约束、凭据隔离、出网规则与部署验证。声明中的字段不证明目标操作系统已正确执行它；Windows/WSL2、自托管 HPC 与公有云沙箱不能视为等价环境。

Git 检查点、Agent checkpoint 和恢复令牌只能管理各自状态，不能撤销已执行 QPU 作业。`twin_id` 不能用作普通沙箱/工作区 ID，平台 request ID 也不能自动视为幂等键。

## 9. 观测不是审计与账单事实源

撤回“Langfuse trace 就是合规审计回执”“模型网关虚拟密钥预算就能覆盖量子/HPC 计费”的推断。

观测可以采样、异步传输甚至丢弃；合规审计需明确持久性、身份归属、访问控制和保留规则。业务账单与作业事实仍归成熟云平台/HPC。模型 token 花费只是其中不同维度的成本，不能合并成同一配额。

OTel 的上下文传播注入不是恶意提示注入。`gen_ai.*` 字段的 Development 稳定性需按版本记录；不把业务 provider 强塞进模型 provider 字段，不默认采集 prompts、完整参数或科学正文。

## 10. 本地模型与三栏界面

撤回“必须部署 Ollama→llama.cpp→LiteLLM 三层链路”以及“前端必须使用某框架才能订阅状态”的暗示。这些是候选或机制样本，不是公司既有部署事实；Ollama 与 llama.cpp server 可以是不同部署选项。

公司已有本地模型、成熟云/HPC，优先验收现有端点与 DSH 的工具调用、取消、流式、结构化输出及错误语义。三栏 UI 只消费受管事件和授权结果，不能因为收到 Agent state 就信任其中权限、租户或账单字段。

## 11. 知识、技能与摘要

撤回“技能都是纯文本所以天然安全”“把源码包装成 Skill 就可对外提供”的推断。技能可以携带脚本、hook、网络命令和内部知识；它们不能授予工具、系统或数据权限。

记忆抽取、图谱扩充、摘要与压缩都可能扩大敏感内容的可见范围。内部/外部账号边界必须在检索前、物化结果时和导出时检查，不能仅在最后的提示词里告诫模型。Skill 不得固化算法名单，算法发现仍来自平台 catalog。

## 12. 本轮补齐后新增的边界事实

- Firecrawl注入检测是可选项；分类器普通故障和扫描不完整会保留文档并警告，不是公司设备执行所需的失败闭合。
- LLMLingua加载模型默认`trust_remote_code=True`；压缩是额外模型推理，不能用于审批、合同和线路的有损转换。
- Repomix读取完整文件后再检查大小；maxFileSize不是读前内存硬限额。
- Continue的HTTP provider仅对workspacePath做本地地址判断，fullInput仍随请求发送；不能据此声称完整对话不会外发。
- Ollama有明确云/远程模型分支，且消息历史可能裁剪；本地服务进程不等于所有请求离线，审批依据不能只靠模型记忆。
- Langfuse登录Session与业务TraceSession不同；ReplacingMergeTree和遥测去重不是不可变审计账本。
- CopilotKit按thread使用实际运行实例，前端运行结束/取消与外部平台作业终态不同。
- 最终57篇都有限定范围分析；引用/版本校验通过不等于57个完整框架已逐行深审，仍保留4条明确测试/许可警告。

## 13. 状态说明

此次更正不代表已部署任何候选组件。静态复核可以完成；真实模型兼容性、负载性能、多租户访问控制、隔离强度、许可证合规和平台计费一致性仍需各自验收，不能因调研文档通过检查而自动标记为完成。
