旧稿“网络白名单语义即抄即用”“审批风险分析可直接用于设备降噪”等无条件建议撤回。沙箱能力取决于实际实现、宿主系统、网络和凭据部署，不能只由字段名或示例配置推断。

详见 [逐项目复核索引](reviewed/README.zh-CN.md)：04 OpenHands、09 smolagents、28 E2B、29 microsandbox、30 Daytona、31 container-use、32 Open Interpreter、33 Cloudflare Agents。

## 保留的方向

- 区分代码执行隔离、文件系统隔离、网络出口和外部业务授权；一个边界不能代替另一个。
- Python import 白名单不能作为恶意代码隔离保证，默认本地执行器不自动满足生产安全要求。
- 运行在云端也不免除设备 ask；网络允许访问平台不等于允许提交作业。
- Git 分支、容器快照和会话检查点不能撤销已执行量子/HPC 作业，`twin_id` 不用于普通环境。
- 现有 HPC 平台成熟，先核对其受管执行能力，再选择是否需要额外沙箱服务。

具体部署验证不在本轮静态调研范围，相关反例见 [工程衔接建议](04-工程衔接建议.zh-CN.md)。
