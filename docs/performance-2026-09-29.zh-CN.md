# 检索评测与本地性能基线

日期：2026-09-29。范围为 WSL2 / Python 3.12、固定合成知识集、本地调用与回环 HTTP，未调用真实模型或外部科学服务。绝对延迟依赖机器、文件系统和当时负载，不设固定毫秒 CI 门槛。

## 可复现命令

安装 `runtime/python-dev.lock` 后运行 `python scripts/benchmark_company_agent.py --repeats 10`。脚本输出短 JSON；CI 检查检索质量不劣于旧方法，不依据延迟数字判定通过。延迟的 p95 采用排序样本的第 95 百分位位置，十次样本下等于最大值。

## 检索质量

`tests/fixtures/knowledge_cases.json` 有 12 篇合成文档和 16 个问题：14 个有相关文档的问题、2 个空结果/恶意路径问题，覆盖中文自然问句、无空格文本、中英混合、同义表达和重复词项。

- 旧空白切词：前八条召回率 0.4286，前八条平均倒数排名 0.4286，空结果正确率 1.0；单查询中位耗时 0.768 毫秒。
- 中文连续双字词项扩展：前八条召回率 1.0，前八条平均倒数排名 1.0，空结果正确率 1.0；单查询中位耗时 0.890 毫秒。

因此保留原词项并增加中文双字词项、英文标识符及“审批→批准”“仿真→模拟”的有限扩展。该小型回归集只证明本项目已定义问法的改善，不代表真实用户准确率、语义理解能力或大型语料检索效果。没有引入向量库、数据库或额外运行服务。

完整性行为单独测试：返回前八条不会标记部分扫描；目录条目、文件、累计字节、深度、过大文件、读取异常、变化文件、超长元数据导致的漏扫都有固定原因。路径型查询仅作为文本，不触发任意文件读取。

## 性能与合同快照决策

改造前剖析十次 `company_capabilities`：1.341 秒，其中合同加载累计 1.276 秒，工具目录读取 60 次，总合同读取 110 次。瓶颈主要是 WSL 挂载盘文件访问和重复读取，而非业务逻辑。

采用单次调用内不可变合同快照后，本地调用六个合同文件各读一次，内容摘要作为身份；每次新调用重新读取、校验，provider 网络发送前再次读取核对。快照不跨调用存在，返回的解析对象也是独立副本，不能通过修改一个调用的工具字典污染另一个调用。

一轮十次测量的中位数及 p95（毫秒）：

- Python 空进程启动：11.834 / 18.728。
- 工具合同读取和定义验证：10.882 / 73.497。
- 本地能力查询、每次重复读取：99.916 / 451.586。
- 本地能力查询、调用范围快照：73.844 / 276.111。
- 回环 provider 完整调用：205.508 / 472.305。

在该次测量中快照本地中位耗时约降低 26%。另一次交替二十次对照为 98.441 → 29.059 毫秒。

最终验收后另行重测十次，完整输出保存于 `docs/benchmark-local-2026-09-29.json`：Python 启动 11.158 / 17.332、工具读取验证 9.320 / 18.373、重复读取本地调用 237.155 / 816.604、快照本地调用 295.858 / 582.477、回环 provider 296.033 / 723.590 毫秒（中位数 / p95）。这一轮快照中位数反而约高 25%；检索中位耗时为空白切词 0.715、中文双字词项 1.029 毫秒，质量指标不变。

这些短样本表明 WSL 文件访问及负载波动明显，**尚未证明稳定的端到端延迟下降**，不能只挑选较好的一轮宣传提速。基准按方法分组计时，不是随机交替的大样本实验；每个样本要求实际调用成功，但重复读取内部路径与完整快照路径还包含不同数量的整体合同一致性检查。保留快照的确定性依据是本地单次调用六份合同各读一次，以及同次调用合同内容一致性；没有增加全局热缓存、批准缓存或新的执行循环。更大规模的性能判断应在目标部署环境交替多轮测量，CI 仅检查正确性和检索质量。

## 依赖与构建

开发、性质测试和构建依赖由 `runtime/python-dev.in` 声明，`runtime/python-dev.lock` 固定直接/传递版本和发行包 SHA-256；安装使用 `python -m pip install --require-hashes -r runtime/python-dev.lock`。

锁定生成器为 pip-tools 7.5.3。更新时在隔离虚拟环境安装现有锁，然后运行 `bash scripts/lock_python.sh --upgrade`，审查锁变化并重跑统一验收。首次恢复生成器才需单独安装该确切版本。锁包含 Python 3.11 的 tomli 兼容依赖；本地实际验证使用 Python 3.12，CI 使用 Python 3.11。另以 pip 的 `--dry-run --ignore-installed --only-binary=:all: --python-version 3.11 --require-hashes` 验证全部锁定发行包可解析并通过哈希校验；这不是在 Python 3.11 下执行测试的替代证据。

wheel 测试共享会话级构建产物，在 pytest 临时源码副本中以 `--no-isolation` 构建，构建工具来自同一锁。每个并行测试进程各有独立临时副本；不清理或写入源码目录的 build/egg-info。生产 Python 仍无运行依赖，DSH 生产锁和入口版本保持不变。
