# 量子计算 Agent 架构深度审查与调研

日期：2026-10-20  
范围：产品与系统架构讨论稿 v0.2；当前 Agent 仓库的合同、Python bridge、DSH 插件与运行配置；公开的一手技术资料。  
配套可视化：[交互 HTML](quantum-agent-architecture.zh-CN.html#review)。

> 后续修订：账户入口、云平台 / HPC 连接、目录层级与原生 DSH 界面复用，以 [v0.3 工作空间架构与实施计划](quantum-agent-workspace-plan-v0.3.zh-CN.md) 为准。本报告保留 v0.2 审查时的证据和发现；其中“直接复用云平台账号”的产品表述调整为“Agent 产品用户与外部连接分开，可复用可信身份基础设施”。作业、审批、数据与失败闭合边界保持不变。

## 一、结论

**保留三栏工作空间和对话入口，但把产品交付重点从“模型能调用工具”转为“每次计算可授权、可追踪、可核对、可复现、可计量”。**

现有工程适合作为受管 Agent 的合同与治理基础；当前代码和合同不足以证明已经具备面向多租户的商业量子云产品能力。这不是现有工程偏离目标，而是单一受控环境中的工具桥接，与对外运营的工作空间之间存在新的责任边界。

建议先形成三条可独立验收的通道：

1. **产品业务通道**：浏览器 → 工作空间后端 → 平台身份、项目、任务查询、账单。用户查任务、下载报告、看余额不需要消耗模型推理。
2. **智能交互通道**：对话 → DeepSeek Harness（DSH，唯一 Agent 运行时）→ 合同校验与服务适配 → 获授权科学服务。模型只能提出动作，不能签发用户权限或批准设备执行。
3. **科学数据通道**：计算服务 → 原始结果存储 → 标准化与分析服务 → 受控报告 / 文件查看器。模型只接收合同允许的短摘要与句柄。

不新增模型循环、会话循环或工具执行循环。平台的持久作业状态机和科学程序的数值迭代，不等于再实现一套 Agent Runtime，也不允许成为绕过设备审批的路径。

### 对 v0.1 的实质修订

- 把一条串行“任务状态”改为执行、结果、分析、计费四条状态轴，并独立记录最后一次可信观察。
- 把用户级身份委托、可定位运行结果和服务端幂等受理列为上线前条件，而非后台实现细节。
- 明确“已有 DSH 审批”不等于“服务端能验证且一次性消费的用户级审批”。
- 明确混合算法每次设备调用与逐次审批之间的产品约束，不承诺无人值守真机迭代。
- 首期拆为 1A 模拟与结果闭环、1B 受监督真机与计费，避免一次接入过多未知系统。
- 补入模拟资源预算、结果语义、内容渲染隔离、本地模型评测与撤权后会话处理。

## 二、证据范围与结论等级

- **当前事实**：能由本仓代码或合同直接核实。
- **目标缺口**：要达到用户要求，当前 Agent 接口仍需补齐；不等同于断言独立云平台没有该功能。
- **设计建议**：基于需求和外部资料的工程选择，尚不是生产承诺。
- **待确认**：云平台、真实设备、HPC 集群、本地模型与商业规则未提供，不能据此判断其实际能力。

优先级含义：

- **P0**：面向相应多租户 / 真机 / 付费范围开放前必须解决。不是声称已发生安全事件。
- **P1**：试点必须定清边界，在扩大能力前补齐。
- **P2**：在基础闭环稳定后扩展。

本次未登录云平台、未运行真实模型、未提交科学或设备任务，也未修改工具合同与运行实现。公开资料是设计参考，不构成公司平台的验收证据。

## 三、十二项重点发现

### R01 · P0：身份登录与下游执行身份之间尚缺少可核验的关联

**当前事实。** `ProviderClient` 从进程环境取 provider token；发送的信封只有协议、操作、请求关联号和模型参数。当前调用合同没有可信的用户 / 租户 / 项目委托上下文。知识检索同样按配置知识根运行，不带用户级授权输入。见证据 E1、E2。

**影响。** 增加登录页不能自动让调用“以当前用户的权限执行”。如果共享服务凭据权限过宽，业务后端仍可能无法区分两个用户的资源许可。反过来，每用户单独运行并使用受限 token 也可能是有效隔离方案，但本次没有看到该部署的证据。

**建议。** 复用平台身份源；若支持 OpenID Connect（OIDC，单点登录身份协议），使用授权码流程和 PKCE（授权码交换保护）。可信后端验证身份并注入逐用户授权上下文，模型不得填写自己的角色或租户。资源服务验证令牌接收方、作用域、对象归属和当前许可；不能把 ID Token 当作任意 API 的资源访问凭据。正式传递方式须修订 bridge 合同，或通过平台认可的短期委托凭据实现，不擅自在严格信封中增加字段。[S1][S2]

**验收。** 两个租户各有同名项目和文件；互换线路 / 资产引用、猜测任务记录、共享下载链接、命中缓存、切换会话，均不能越权。撤销成员权限后，下一次检索、工具调用、事件订阅和下载按约定时限失效。

### R02 · P0：短请求桥接不是持久作业控制面

**当前事实。** provider 客户端默认 30 秒超时，Node→Python 桥接超时 35 秒；部分结果允许 `queued` / `running`，但本仓没有完整的任务提交、状态查询、取消、事件恢复合同。`company_workflow_validate` 的范围只是结构和参数校验。见 E3、E4。

**影响。** 后端一旦异步受理，模型工具返回并不说明作业结束。仅延长 HTTP 超时不能解决重启恢复、长队列、取消竞态和重复提交。

**特别注意。** 当前 provider 在响应通过验证后将诊断 `execution_state` 记为 `completed`，即使业务结果自身可能为 `queued`。这是本次调用边界完成的诊断语义，不能直接接到工作台当成设备作业完成状态。生产事件应区分 transport / invocation 和 scientific execution 两种层次。

**建议。** 优先接入已有平台作业 API；若缺失，由平台侧维护持久执行意图、受理回执和状态。短调用返回受理事实，状态由经过鉴权的事件订阅与必要的只读查询更新。浏览器的推送流不是事实源；断线后从权威快照与事件游标恢复。当前 200 JSON 响应约束不意味着必须改成某个 HTTP 状态码，关键是明确受理与完成的语义。

**外部参照。** Braket 的创建接口返回独立任务引用；查询接口另行返回状态、实际设备、结果存储位置与成功采样数，并包含 `CANCELLING` 状态。这支持将“受理回执”“实际执行状态”“结果位置”分开设计，但不要求照搬其 ARN 或响应格式。[S14]

**验收。** 提交后关闭浏览器、停止 DSH、重启界面后端，均能找回同一作业；重复事件、乱序事件、丢失事件可恢复，不产生新的物理执行。

### R03 · P0：同一线路多次运行，需要独立、持久的结果定位

**当前事实。** `quantum_simulate` 和 `quantum_compile_estimate` 的输出句柄列表为空；模拟的必填输出仅来源标识，编译估计必填来源和耗时估计。`quantum_device_run` 返回 `twin_id`，但当前没有对应的结果读取工具。`quantum_asset_get` 只返回有限摘要。见 E5。

**影响。** `circuit_id` 标识线路，不足以区分不同参数、随机种子、设备、实际采样和执行时间的实验。没有稳定关联，就无法可靠回收、比较、追责、复现或计费。

**建议。** 平台为每次执行建立独立业务记录，并关联输入线路与结果资产。科学结果统一登记到获授权的平台资产体系，优先沿用 `asset_id`；对应输出和读取能力必须正式扩展合同。不要给模拟器伪造 `twin_id`，也不要把 provider 的内部任务键或诊断 `request_id` 偷渡为新增科学句柄。平台业务记录可以在界面后端管理，不要求把它们全部暴露给模型。

**另一个合同边界。** 目前模拟和设备摘要不接收通用科学 metrics；现有 `scientific-metrics/1.0` 的标量类型也不足以表示完整分布、张量或置信区间方法。原始结果 / 分析合同在独立数据服务中扩展，模型只拿经批准的简短投影；不要为了画图放宽工具结果禁止大正文的规则。

**验收。** 同一线路运行两次可分别定位结果；回收失败后只恢复回收；模板分析可精确选择哪次执行。不同 provider 的来源不能被统一 UI 掩盖。

### R04 · P0：设备审批必须绑定不可变执行意图，并在服务端验证

**当前事实。** DSH 负责先审批再执行，Python 接受受管生命周期提供的 `approved` 标记；发送给科学服务的 payload 没有审批人、审批记录、报价或执行意图摘要。此机制在受管进程边界内有意义，但不是分布式用户授权证明。见 E1、E6。

**影响。** “已点同意”不足以约束排队后线路内容变化、设备重选、预算失效、审批重放或重复提交。若线路句柄允许内容变更，仅审批句柄字符串无法绑定原始意图；平台是否已实现不可变版本本次未知。

**建议。** 在可信服务中绑定申请人、项目、操作、目标、线路内容摘要、组件 / 编译版本、规范化参数、报价和有效期；审批与幂等受理记录原子关联。调度时复核执行前提，拒绝超范围变更。相同请求的重发返回已有受理记录，不重新消费审批、不再次运行。[S3]

**硬边界。** `quantum_device_run` 在 `lab / sign` 必须 ask，在 `boot / algo` 必须 deny。它们是运行配置，不是角色。仅 `ionstack-twinrun` 的该工具可返回 `twin_id`。不以共享 token、科学算法、编码 preset 或内部身份绕过上述规则。

**验收。** 批准后修改参数 / 电路内容、两个请求并发消费同一批准、过期批准、撤权后调度、重新选设备，都必须得到明确且可审计的处理。

### R05 · P0：端到端“只执行一次”不能由客户端 request_id 保证

**当前事实。** 现有 `request_id` 每次调用重新生成；结果合同明确它不是幂等键，设备自动重试为零，发送后不确定故障标记 `unknown`。这是正确的保守行为。

**建议。** 平台定义调用方 / 项目范围内的稳定幂等意图键，并绑定规范化请求摘要；相同键相同请求返回同一受理结果，相同键不同请求拒绝。定义保存期限和迟到请求行为。受理、审批消费和本地事件记录在可控事务中保持一致；跨系统使用事务发件箱（业务更新与待发事件一并持久保存）、消费者去重和对账。[S4][S5]

**重要限制。** 数据库中的去重不能自动解决“设备已执行、确认丢失”的物理边界。若设备服务没有稳定操作键或可核对回执，结果未知时只能停止自动重发并人工核对。不能因用了消息队列或工作流引擎就承诺设备恰好执行一次。

**验收。** 在发送前、服务受理后、设备执行后、结果保存后、账单处理前后分别注入崩溃；检查实际执行次数、审批消费次数、用量事件和结算记录。

### R06 · P0：混合算法迭代与逐次设备审批存在必须正面解决的约束

**当前事实。** 现有规则要求每次设备工具调用经人工审批；当前合同没有后台科学执行器申请、等待并恢复该审批的完整机制。

**影响。** “一个自然语言指令启动 HPC↔QPU 全自动迭代”不能作为当前可交付承诺。将迭代包进 `algorithm.run` 并给执行器设备密钥，会把审批边界移出受控路径。

**建议。** 首期支持纯经典 / 模拟迭代，以及受监督、逐次批准的设备步骤。平台可预先保存计划与依赖，但每个适用的设备调用仍要获得有效批准。所谓会话优先级、批量运行和资源预约只是调度策略，不是审批豁免。实时反馈、离子控制、在线解码由专业设备系统实现，不经过大模型。

**外部参照。** Braket Hybrid Jobs 将经典执行器与多个量子任务分开，提供容器环境与设备队列策略；取消混合作业时终止经典容器，对相关量子任务只做尽力取消。这是“停止编排 / 进程不等于停止全部设备执行”的明确实例，不意味着该平台替公司实现了审批规则。[S15]

**验收。** 第二次设备调用若没有新的有效批准就停止；迭代次数、累计采样、总预算和截止时间均有上限。平台执行器与通用算法组件不能持有可绕过设备准入的凭据。

### R07 · P1：OpenQASM 只是语言入口，不是统一设备可执行保证

**外部证据。** Amazon Braket 明确区分各设备支持的 OpenQASM 操作、扩展和仅本地模拟器支持的功能。规范合法、解析成功、本地模拟成功、目标设备可执行是四件不同的事。[S8]

**建议。** 首期发布明确的受支持子集：接受哪些语言版本、门、参数、测量、经典控制和 include；由 provider 能力快照决定是否可运行。设置文件大小、解析时间、展开后操作数与内存上限；不从上传内容任意拉取依赖、导入包或访问外部路径。脉冲、CAL、shuttle 等敏感控制能力不作为普通上传入口开放。

保留用户原始线路、规范化线路和编译产物的来源关系；编译引起门分解、量子位映射或语义相关变化时提供摘要。算法名单仍只来自平台实时目录，此处不列举公司算法组件。

**验收。** 语法合法但含不支持动态控制的线路必须被拒绝；未知语句不能静默忽略；目标设备改变后重新验证。恶意 include 和巨大展开输入被隔离解析器阻断。

### R08 · P1：结果统一格式必须保留测量语义，不能只统一字段名

**外部证据。** Braket 结果文档指出，不同设备可能返回测量记录或概率；SDK 展示出的逐次测量也可能是依据概率后计算得到，并提供来源标记。这直接说明“有 measurements 字段”不能推断存在真实逐次测量数据。[S9]

**建议。** 平台结果清单至少区分：真实逐次测量、计数聚合、精确概率、采样概率、期望值 / 误差，以及后处理产物；保存寄存器和位序约定、逻辑到物理映射、测量基、参数索引、请求与实际采样、后选择分母、噪声模型 / 校准时点和处理版本。

不同语义的数据不能默认进入同一统计模板：从概率生成的伪样本不得用于宣称真实时间相关性；精确模拟与有限采样估计不能套同一种置信区间；有漂移或时间相关性的数据不能默认独立同分布。大数组和敏感数据只存在受控资产通道，不进入工具结果。

**验收。** 位序相反、寄存器不同、缺实际采样数、只有概率却请求时序相关分析、单位不一致时，模板要么先做有记录的有效转换，要么明确阻断。

### R09 · P1：模拟、分析与模型本身也需要资源和成本准入

**外部证据。** Aer 文档指出，稠密状态向量的每个复数振幅在双精度下占 16 字节，方法与内存需求相关。仅状态数组的理论规模为 \(16\times2^n\) 字节；30 量子位约 16 GiB，32 量子位约 64 GiB，40 量子位约 16 TiB，尚不含工作区、复制和运行框架开销。张量网络等方法另有复杂度条件，不能照用该估计。[S10]

**建议。** 在模拟之前做资源估计与预算准入，不能只在真机前检查余额。限制经典 CPU / GPU 时间、内存、并发、解析时间、结果存储和模型推理预算。明确服务是否收费、计价单位、币种精度、部分执行收费及取消规则。

计费账本用可信用量事件计算，唯一事件键防重复；冲正与退款保留记录，不覆写历史金额。预算预留不是实际扣款，超时也不代表可以立即释放所有预留。模型调用和科学资源使用的费用分别归集。

**验收。** 超大模拟在执行前拒绝；大量小请求无法绕过累计配额；同一用量事件重放不重复扣费；计算成功但分析失败仍能正确解释两类费用。

### R10 · P1：本地模型“接口兼容”不等于任务能力和安全行为兼容

**当前事实。** 本仓说明和 `doctor` 主要围绕既有 DeepSeek 接入；`doctor` 检查配置而非真实模型行为。本次没有公司本地模型型号、部署配置或推理评测结果。

**外部证据。** vLLM 官方工具调用说明要求模型匹配的 parser / chat template，并区分 auto、required 和指定工具调用；结构化可解析不代表选择正确、科学有效或具有授权。[S6]

**建议。** 继续通过 DSH 的模型适配接入，固定模型权重 / 量化、推理引擎、工具解析器、模板、上下文预算和版本。不得为接入一个本地 endpoint 自写第二套对话 / 工具循环。

评测至少覆盖：中文需求澄清、目录版本固定、合法 / 非法工具参数、长上下文引用、流式中断、重复调用、拒绝结果后的行为、审批前停止、未知结果不重跑、虚假完成声明。结果同时报告任务完成率、无效参数率、误拒率、未授权执行次数、首字 / 完成延迟和资源成本；试验阈值由业务目标确定，不虚构一个通用及格分数。

### R11 · P1：文件、报告和知识是新的输入与权限边界

**当前事实。** 现有知识搜索是受管文本根上的短检索，不是租户化企业检索、源码浏览或上传系统。内部资料的权限和业务角色尚未贯穿当前检索合同。

**建议。** 检索前按授权过滤；原文、引用、下载、缓存和检索总数也要防泄漏。缓存键包含身份 / 租户、授权版本与内容版本。撤权不可能让人“忘掉已看过内容”，但可以停止后续读取；已有会话摘要和长期记忆的访问也要检查，必要时重建上下文。

自然语言、文件注释、目录描述、模板说明都可能携带提示注入；来源可信不代表内容可授权操作。用工具边界权限、出站网络限制和参数校验约束副作用，提示词和过滤器只提供辅助防御。[S3][S7]

Canvas / HTML 报告优先使用受控组件和声明式数据。需要运行脚本时在独立 origin、受限 iframe 和内容安全策略中展示，不继承工作空间 token、Cookie 或设备 API；下载与新标签页打开也要考虑隔离。当前讨论 HTML 是可信静态设计文件，其内联脚本许可不能直接复制成生产用户内容策略。[S11]

### R12 · P1/P2：数据治理、可复现性和上线运营应从首期建模

**建议。** 将数据资产、分析活动与责任主体分开记录，参考 W3C PROV 的来源关系，但首期不必引入复杂知识图谱。输入、执行器、编译器、环境、模板与报告的版本关系，在第一次运行时就保存，事后很难完整补回。[S12]

可复现有不同含义：从同一原始结果重做分析可以追求一致；重新运行真实硬件只能讨论统计复现，不能承诺逐比特一致。GPU / 并行数值差异需定义容差并保留环境。

外部数据默认不进入公司共享知识或训练集。发布、撤回、保留期、备份中的删除延迟、法定保留和派生知识回溯应有制度；自动总结不是自动获得发布权。

运营层记录不含科学正文的关联事件，覆盖身份、审批、受理、用量和报告；定义任务状态新鲜度、回收延迟、恢复目标、告警、值班责任和安全停机。全链路重放测试与真实服务验收分别记录，不能由本地测试通过推断生产已就绪。

## 四、建议的领域对象与状态模型

### 4.1 概念关系

用户属于组织并获得项目权限；项目拥有会话、输入资产和作业。一个作业绑定一个不可变的执行意图，关联批准记录、受理记录、实际执行、结果资产和计费事件。报告是使用特定模板处理某些结果资产产生的新资产。

这些是平台业务概念，不是新增的模型科学句柄。模型可见句柄仍限定为 `asset_id`、`circuit_id`、`twin_id`。一次线路、多次执行、多份结果、多个分析版本必须可区分。

### 4.2 分开保存的状态

- 执行：草稿、已校验、等待审批、已受理、排队、运行中、完成、失败、已取消。
- 结果：未产生、回收中、可用、部分可用、校验失败。
- 分析：未开始、运行中、完成、失败、不适用。
- 计费：未预留、已预留、待核对、已结算、已释放、已调整。
- 审批：待决定、有效、过期、撤回、已关联消费等，按平台事务规则定义。
- 观察质量：已确认或待核对，同时保存来源、版本和最后确认时间；不把 `unknown` 伪装为设备确定状态。

例如，“执行完成 / 回收失败 / 分析未开始 / 用量已确认待结算”是合法组合。界面展示简洁主状态和异常提示，详情可展开各状态，避免用户看到“失败”就以为没有产生费用。

### 4.3 时间与重试

登录会话、访问令牌、审批、报价、预算预留、资源预约、任务截止期各自有有效期，不能共享一个 TTL。用户退出不必取消已经受理且授权有效的作业；撤权后是否继续执行要按平台规则明确，并在下一个不可逆步骤前复核。

只读查询可按服务规则有界重试；结果传输可断点恢复；分析仅在输入和模板固定、没有外部副作用时可安全重跑。设备调用仍保持当前零自动重试策略。

## 五、HPC / QPU 调度的进一步拆分

1. **资源准入**：先判是否具备所需门集 / 动态能力、设备状态、数据许可、预算和配额，再在可行候选中优化成本或等待时间。不能简单按“量子位数最多”或“队列最短”分配。
2. **松耦合作业**：经典预处理、量子步骤和经典后处理通过资产传递；可从这一层开始。
3. **迭代混合执行**：平台维护迭代检查点、预算和设备审批等待，GPU / CPU 资源不应无限占用等待长量子队列。
4. **紧耦合实时反馈**：低时延解码、离子时序和设备联锁留在专业实时系统。本产品展示计划和结果，不进入控制环。
5. **多资源预约**：有租约、期限与释放规则；避免先占住 GPU 等 QPU、同时 QPU 又等待 GPU。若现有集群使用 Slurm，优先通过资源适配接入。Slurm 异构作业有自身同时调度和集群边界限制，不自动提供公司 QPU 的联锁、计量或跨系统原子预约。[S13]

当前 `clients()` 限制同一 provider kind 唯一，设备工具参数没有显式目标设备选择。不能简单添加多个同类 provider 就声称已完成异构调度。可以由已验证的资源服务在内部路由，但选中目标、能力快照与批准范围必须可核对；对外合同需要按实际需求扩展。

## 六、未来能力接入前的科学验收边界

以下是能力类别的设计要求，不是公司算法名单；实际组件、参数与版本仍从平台 `algorithm.catalog` 发现。

### 6.1 机器学习解码

先区分离线训练 / 基准、在线推断和实时反馈三种用途。离线数据应保存测量轮次、设备 / 实验批次、标签生成方法、预处理与解码器版本。训练与测试切分应防止同一实验或噪声轨迹泄漏到两边；同时报告适用误差指标、数据分布变化和推断延迟，而不是只给一项总体准确率。

在线路径要明确是否允许缓存、降级到哪种已批准实现，以及超时如何处理。真正实时反馈的延迟预算由设备系统提出并验收，Agent 不成为每轮测量后的同步调用环节。这些是评测设计建议，不是对任何公司解码算法效果的断言。

### 6.2 线路优化

优化不应只用门数下降作为成功标准。至少说明保持的语义、允许的近似与容差、目标门集 / 拓扑、物理映射、编译随机性和校准前提。小规模可采用适合的等价性检查，大规模采用经过批准的验证策略，明确其覆盖和局限。

优化前后保存不同的版本化资产；已批准线路被更换时重新校验批准范围。更短的线路不必然意味着真机误差更小，更低的估计耗时也不必然等于更低账单。

### 6.3 离子调度和内部校准

离子调度服务的合法性与设备时序由专业约束验证器确认，不能只以 makespan（预计总执行时长）作为成功标准。它与上层选择哪台 QPU 是两层不同调度；低层控制正文不进入模型结果。

校准从“观测 / 诊断 → 候选方案 → 审批后实验 → 统计评估 → 候选参数 → 独立授权后应用”推进。保留前后参数版本、维护窗口、设备状态和回退条件，校准质量不合格时不能自动发布新参数。内部测试与客户作业共享设备时，需要明确互斥、维护和在途任务策略。

## 七、按风险重新安排建设顺序

### 阶段 0：确认五份边界合同

- 平台身份 / 组织 / 项目 / 委托授权。
- 作业受理 / 查询 / 取消 / 事件 / 幂等 / 未知结果核对。
- 设备身份 / 能力 / 许可 / 审批 / 实际来源。
- 结果资产 / 文件授权 / 数据语义 / 模板输入输出。
- 报价 / 预算预留 / 用量 / 结算 / 退款和对账。

先做接口与责任盘点，不预设全部需要重建。后端可先模块化部署；安全域、状态所有权和故障恢复比“用了多少微服务”更重要。

### 阶段 1A：受限模拟试点

统一登录、隔离工作空间、受支持的 QASM、单模拟器持久任务、可定位结果和一份分析模板。记录真实用量；正式收费前验证账本。先验证两租户隔离、关闭会话后的恢复、重复提交和数据语义。

### 阶段 1B：受监督真机试点

接入一个确认来源的实际设备服务，补齐服务端审批绑定、幂等受理、执行核对、预算和对账。`ionstack-twinrun / qccd-twin` 的现有标记本身不证明真实 QPU 已接通。每次设备执行保持既有审批规则。

### 阶段 2：内部知识和模板扩展

内部身份源与项目权限贯穿检索、接口和源码；增加模板和报告比较。数据治理从首期保存来源，在此阶段扩大审核入库和复用范围。

### 阶段 3：受控混合与多设备

仅在审批、异构准入、资源预约、状态核对和账单归集可验收后扩展。继续由平台科学执行器实现算法，不在 Agent 代码中添加算法包或名单。

### 阶段 4：内部校准和数据运营

自动建议、分析与评估先行；设备实验和参数应用遵守独立授权、审批、安全验证和回滚约束。无人值守设备执行不属于本方案。

## 八、上线前应演练的故障和权限场景

以下为验收用例设计，当前没有声称全部通过：

1. 两租户互换线路 / 资产引用，服务端拒绝。
2. 获授权检索后撤权，再读原文、旧引用、会话摘要和缓存，按策略阻断。
3. 同一幂等意图并发提交，只有一个受理和一个物理执行；参数不同则冲突。
4. 审批后修改线路内容或采样参数，不能沿用旧批准。
5. 排队期间报价、预算或设备前提失效，重新准入而不是静默执行。
6. provider 已执行但确认丢失，界面显示待核对且不自动重跑。
7. 执行完成、结果文件缺失或内容摘要不符，隔离结果并单独处理用量。
8. 取消请求与开始执行竞争，明确实际停止点、部分用量和最后确认时间。
9. 事件重复、乱序、遗漏，工作台不回退到错误状态，消费者不重复计费。
10. 语法合法但设备不支持的 OpenQASM 被拒绝；解析超限不影响其他租户。
11. 同一线路两次运行、不同测量位序或不同结果语义，报告引用正确且阻止错误比较。
12. 恶意文档注释要求运行设备或导出内部资料，工具层拒绝，不靠模型口头拒绝计分。
13. 恶意 HTML / SVG 结果不能访问工作空间会话或外发数据。
14. 本地模型流式工具参数截断、错误工具名、重复工具调用，均先校验再执行。
15. 巨大模拟、海量小任务或无限迭代被累计预算和并发准入限制。
16. DSH、界面服务或结果处理进程崩溃重启，平台作业和账本不丢失，恢复不新增设备执行。
17. 第二次混合设备调用未获批准，执行器停止等待；不存在算法入口绕过审批。
18. 用户删除资料或知识撤回后，索引、引用、缓存和备份保留按可说明的生命周期处理。

## 十、外部参考资料与适用边界

访问日统一为 2026-10-20。动态文档可能更新；实施时要固定所用版本，重新核验。资料支持的是相应具体事实，不是对公司系统的功能背书。

- **S1 · IETF RFC 9700：OAuth 2.0 Security BCP**。正式最佳实践，重点为授权码 / PKCE、令牌最小权限与接收方约束、资源服务逐请求验证。不是要求公司一定使用某个身份产品。https://www.rfc-editor.org/rfc/rfc9700.html

- **S3 · OWASP AI Agent Security Cheat Sheet**。工具最小权限、动作绑定审批、一次性消费与重放防护；是工程安全指导，不是本项目渗透测试报告。https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html

- **S5 · AWS Prescriptive Guidance：Transactional outbox pattern**。业务记录与事件的双写问题、重复消息与消费者幂等。队列语义不等于物理设备恰好执行一次。https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html
