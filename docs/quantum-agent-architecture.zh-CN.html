一套 Agent 运行时

DSH 负责智能交互。平台作业服务只执行已校验的结构化步骤与科学工作流，不新增模型循环、会话循环或工具循环。

两条返回通道

完整文件和大结果经鉴权接口进入中栏；模型只收合同允许的句柄、少量指标和短摘要，避免敏感内容与大数据进入上下文。

三个事实来源

可信身份服务负责 Agent 用户；云平台与集群负责各自资源、授权和账本；科学服务负责结果。DSH 和 Agent 合同管理对话工具，聊天记录不替代这些正式记录。

设备来源必须明确：当前设备合同对接 ionstack-twinrun，返回来源为 qccd-twin，不能据此声称任意真机已接通。真实量子处理器（QPU）的执行、状态查询、计量与结果来源，需要按实际服务补齐合同并验收。

基于 DSH 的公司通用 Agent

公司本地模型、受管插件、MCP 与常用 Skills；通用任务不必经过量子算法。以下是集成设计，尚未全量启用。

v0.8 harness 框架对齐Super DSH 手册

复用 DeepSeek Harness 的原生对话和工具生命周期，优先装配成熟扩展。知识库、云平台、HPC 和量子算法并列接入；只补适配、权限、隔离与验收，不为每类能力重建后端。

首期必须实际完成

  • 文件与办公

    读取、编辑与保存获准文件，生成可打开的文档、表格和选定模板的演示材料。

  • 代码与命令

    跨文件修改、隔离运行脚本 / 测试、根据失败修正，交付差异和真实验证记录。

  • 数据与调研

    实际计算和绘图，检索获准网页并引用来源，保存脚本、报告与产物。

连续工作与风险分级

  • 范围内连续执行

    已授权的读取、草稿编辑和沙箱测试可连续完成，不每一步重复审批。

  • 副作用单独确认

    扩大访问、破坏性修改、外发 / 发布与新增费用按策略确认；设备规则不放宽。

  • 真实完成标准

    文件可打开、结果可复核、失败如实记录；只有聊天或代码建议不算通用 Agent 验收。

插件 / MCP / Skills 的分工

  • 插件与 MCP 提供工具接入

    插件负责扩展和注册，MCP 是工具与资源连接协议；可组合或直接接已有 API，不强制每项建设三套封装。

  • Skills 提供工作方法

    整理团队常用步骤、模板和检查要求，记录依赖工具、版本与样例；按需加载，不赋予额外权限。

  • 合同约束实际暴露范围

    安装不等于授权；工具发现不自动全量开放。公司工具继续经合同、策略和适配，量子目录保持动态。

接口鲁棒性是主要工程工作

  • 故障分类与限额

    启动、鉴权、限流、超时、断流和坏结果分别处理；限制并发、输出与资源，记录可诊断的短错误。

  • 恢复不重复执行

    只读有限重试，写操作按幂等合同；提交后未知先查询，设备自动重试为零，取消不冒充后端已停止。

  • 隔离、版本与回归

    固定版本，按租户保护凭据和缓存；单个服务失败不拖住无关任务，升级先过契约与故障测试。

以上按钮只切换方案说明，不切换用户角色、生产 preset 或工具权限。公司平台仍以可信身份与服务授权决定可用范围。

审核后发布版本并同步索引；以后按权限检索，过期可复核、纠错与撤回。

低负担保存，分级共享

  • 个人 / 项目草稿

    选择一次工作中的资料和结论即可开始整理；默认不自动上传全部聊天或文件。

  • 团队共享 / 公司发布

    校验来源、客户归属、重复和保密范围；读权限不等于发布权，不能通过摘要扩大来源权限。

  • 不是模型训练

    知识入库指受控文档与检索索引；个人记忆、跨会话上下文与模型训练需要独立许可。

通用编码与设备权限分离

  • 体验复用 DSH

    消息、模型、上下文和审批原样保留，文件 / 差异 / 测试证据在中栏。

  • 执行接入受管开发服务

    限定仓库和版本，隔离运行测试；测试环境没有生产凭据、设备网络或修改 profile 的能力。

  • 保留当前生产边界

    不启用 shell 编码 preset，不开放 Codex 模型委派。DSH 底层能力不等于本仓已经具备完整自动编码。

模型可选范围也受数据规则限制：内部源码和客户资料只能发往获准模型服务。切换模型不能绕过已有上下文的出域检查；具体接入点仍需验证。

建议建设顺序

  1. 首期：通用 Agent 内部可用版

    盘点 DSH 固定版本、已有插件 / MCP 与常用 Skills；接公司本地模型，装配受管最小集合，验证真实文件、编程、分析与调研交付。

  2. 并列接入公司服务

    知识库、云平台、HPC 与量子算法按接口就绪程度并行适配。优先复用已有 API / MCP，不为每项重建后端。

  3. 鲁棒性与业务专项验收

    版本、权限、超时、限流、幂等、取消和结果校验统一测试；外部租户与设备另做业务验收。工期按复用盘点重估，不将能力清单全算自研。

把“结果回收与分析”作为主流程设计

任务受理、执行完成、结果可用、分析完成、账单结算是不同状态，必须分别记录。

以下为目标流程，非已实现合同

分析能力建议拆成三个可版本化的合同

这些是未来分析服务的设计项；后续你提供的格式模板、绘图模板可接入这一层，而不是写进提示词。

① 数据格式合同

定义结果字段、类型、单位、测量语义、实际采样数、来源、版本和缺失值。原始结果保留，标准化数据另存，转换过程可追踪。

→
② 分析 / 绘图模板

固定输入 schema、模板版本、依赖环境和资源预算；确定性程序计算指标与不确定性，并生成可复现图表。缺失必要数据时明确阻断。

→
③ 报告与解释合同

图表和明细进入中栏；模型接收受限摘要，说明结论、误差与局限，并引用结果资产。把“程序算出的事实”和“模型解释”分开。

建议：四条独立状态轴

执行：草稿 → 校验 → 待审批 → 已受理 → 排队 → 执行中 → 完成 / 失败 / 已取消
结果：未产生 → 回收中 → 可用 / 部分可用 / 校验失败
分析：未开始 → 运行中 → 完成 / 失败 / 不适用
计费：未预留 → 已预留 → 待核对 → 已结算 / 已释放 / 已调整另记“观察是否可靠”：已确认 / 待核对（最后确认时间、来源、版本）。超时表示当前不知道结果，不表示设备进入失败状态。以上为目标领域模型，并非现有工具枚举。

同一作业可以同时是“执行完成、结果校验失败、分析未开始、账单已结算”。工作台按视图聚合，不能用一个 completed 字段代表所有阶段。审批的有效 / 过期 / 消费状态另存。

必须提前定义的异常语义

  • 发送后超时：结果可能未知，先核对服务状态，不能自动再跑一次。当前 request_id 仅作关联，不保证幂等。
  • 点击取消：取消本地会话或请求，不等于设备已停止；界面应显示“取消请求中”，直到服务确认。
  • 已计算但回收失败：保留计算事实，恢复数据回收；账单按实际用量和约定规则处理，不能盲目退款或重复计费。
  • 科学结论不足：显示数据缺失、误差或质量问题；模型不得填造指标，也不把一次运行包装为量子优势证明。

QPU 与高性能计算（HPC）协同：由平台承接长任务

  • 逻辑工作流

    经典预处理 → 量子任务 → 经典分析；算法迭代留在科学执行器。每个 Agent 发起的设备调用仍逐次审批；当前桥接没有让后台执行器自动申请、核验并续行审批的合同，不能将整套迭代隐含授权给 algorithm.run。

  • 资源级调度

    综合设备能力、拓扑、校准新鲜度、队列、配额、预算和数据位置。重新选择设备若改变批准范围、费用或科学语义，需重新校验和审批。

  • 设备内部调度

    离子调度和低时延控制留在专业编译 / 设备服务；QPU 资源分配与离子级调度是不同层次。时间敏感解码也应靠近设备执行。

  • 依赖与补偿

    平台维护步骤依赖、预留过期、部分失败、取消传播、用量和资产关联。交互层只订阅状态；算法失败不会触发未经审批的替代设备运行。

当前对外科学句柄只有 asset_id、circuit_id、twin_id。平台内部可管理任务、项目、账单等业务记录，但这些关联键不是新增的科学句柄，也不能直接作为现有模型工具参数。扩展工具时先修订合同。

登录、令牌与租户隔离

  • Agent 提供产品级注册、登录和退出；优先使用支持 OpenID Connect 的可信身份服务，也可联接现有平台身份源，不在前端自行保存密码。
  • 云平台账号与 HPC 集群账号是独立连接，绑定、撤销和权限分别管理；同一用户名或一次登录不自动取得另一个系统的权限。
  • 由工作空间后端管理短期、最小权限的会话和服务访问；长效平台密钥不进入模型上下文或前端持久存储。
  • 租户与项目上下文来自可信身份，不能由模型参数自行声明。服务侧逐次验证用户授权，防止共享服务凭据扩大权限。
  • DSH 现有本地登录 token 不等同于生产租户身份。共享运行时或每租户隔离部署，需根据会话、文件、插件及缓存隔离验证结果决定。

知识、算法实现与数据归属

  • 访问控制在检索前过滤，并在原文读取、引用、缓存命中和导出时复核；不能先把内部文档交给模型再要求它保密。
  • 源码、接口文档、运行权分开授权。员工也只看到许可项目；外部用户可调用发布能力而不暴露实现细节。
  • 外部用户数据默认仅归所属租户使用，未经明确授权，不并入公司知识库或训练集。
  • 知识扩充采用“候选 → 去敏与质量检查 → 权限 / 归属确认 → 审核发布”，保留来源、版本、撤回和删除机制。

计费由平台账本确定

  • 先确认计费单位：采样数、设备时间、计算资源时间、存储或服务套餐；本地模型服务是否收费也应单独约定。
  • 提交前给出报价版本、费用范围、预算上限和预留有效期；排队超时、重报价和追加迭代需要明确规则。
  • 设备 / 计算服务产生可信用量事件；账本按唯一事件去重，完成结算、释放预留、退款与对账。
  • 失败、取消、部分执行可能已经产生费用；模型只能解释账单，不能自行计算应扣余额或宣告退款成功。

自动化校准的安全边界

  • 可自动完成：历史数据分析、异常发现、方案生成、结果评估与候选参数建议。
  • 需要受控执行：设备实验、参数应用、影响在途任务的操作；设备安全联锁与紧急停止保持在专业设备服务。
  • 现有 quantum_device_run 在 lab / sign 配置下必须人工批准；在 boot / algo 下必须拒绝。这些是运行配置，不是用户角色。
  • 当前范围：先交付审批辅助的校准分析与测试；每次设备操作保持既有审批策略。无人值守设备执行不纳入本方案，科学执行器也不能成为绕过审批的通道。
始终失败闭合：未知工具、未知 preset（运行配置）、缺失 provider（服务适配方）、非法响应均拒绝处理。生产仅允许项目受管组合，不开放可切换到带 shell 的编码配置；官方 Codex 保持既有隔离设置，不成为设备调用通道。

下一轮最值得确认的五个问题

1. 云平台已经有什么接口，可以直接复用？

优先确认：统一登录 / 组织项目、配额余额、提交 / 状态 / 取消、设备目录、原始结果下载、报价 / 用量 / 账单、事件通知与服务端幂等。建议先做接口盘点，不先另建账号库、调度器和计费系统。

2. v0.6 首期怎样证明是通用 Agent？

独立完成办公文件、跨文件代码修改与实际测试、表格计算和网页调研四类代表性任务；不要求先绑定量子云。只有聊天、知识查询或代码建议不算完成。随后接入企业协作与 HPC / 模拟；外部租户和设备保持专项验收。

3. 真机由谁批准，费用如何控制？

需明确用户是否可自行批准获授权资源，是否还要项目负责人或设备管理员审批，以及预算阈值、排队过期、失败收费和取消规则。用户口头同意、账号有余额、内部身份，都不能代替本次有效设备审批。

4. 内部人员分别能看什么，又能运行什么？

建议列出研发、算法、设备操作、项目管理员、财务等业务角色，并将“看文档 / 看实现 / 运行 / 发布 / 审批”分别授权。这里的角色建议不新增 Agent preset，也不改变既有设备拒绝 / 审批策略。

5. 第一份结果和分析模板是什么？

最好提供一份脱敏模拟结果、一份真实设备结果、一份期望报告，以及字段说明、测量语义、误差定义和绘图规范。先验证模板能覆盖真实数据及失败情形，再扩充模型解释和更多科学能力。

建议以 Web 三栏工作空间作为首期形态，按需要再封装桌面客户端；界面服务、平台作业服务和设备控制不必同时拆成大量微服务，但部署与权限边界必须明确。后续实施保持：合同 → Python adapter → DSH 插件 → 测试，不为页面新增第二套 Agent 运行循环。

十二项关键发现

点击条目查看证据、建议和验收方法。
R01 · P0用户身份必须贯穿到科学服务与文件访问当前事实：进程环境 token + 固定服务信封，尚无逐用户委托上下文合同。

证据与风险

src/company_agent/providers.py 从环境读取 Bearer token；请求只包含操作、关联号与 payload。登录页不能自动赋予后端区分用户的能力；独立云平台的隔离能力仍待确认。

建议方向

复用身份源，可信后端注入短期、最小权限委托；资源服务验证接收方、作用域和对象归属。模型不填角色 / 租户；DSH 本地登录 token 不是生产身份体系。S1S2

验收：跨租户句柄、旧引用、下载地址、缓存和事件订阅均不能越权；撤权后按定义的时限阻止后续访问。
R02 · P0持久作业服务必须独立于对话和短请求当前事实：provider 默认 30 秒超时，CLI bridge 35 秒；工作流校验不执行。

证据与风险

providers.py 与 packages/company-agent-core/src/runtime.js 限制单次请求时间。诊断 completed 表示调用响应已验证，不等于业务任务完成；即使结果是 queued，诊断也可 completed。工作台必须读取平台作业状态。

建议方向

平台持久保存意图、受理记录和状态；工作台订阅权威事件，断线按游标恢复并重新查询快照。不是新增 Agent 工具循环。账号、任务查询不经过模型。S14

验收：关闭网页、停止 DSH 或重启界面服务，仍可找回同一受理记录；乱序和重复事件不创建新执行。
R03 · P0每次运行都需要可定位的结果资产当前事实：模拟与编译输出没有结果句柄；线路本身不能标识某一次实验。

证据与风险

contracts/tools.json 中模拟 / 编译的 output_handles 为空；设备虽返回 twin_id，当前无对应读取工具。重复线路实验无法仅靠输入句柄区分结果。

建议方向

平台将每次执行与资产关联；模型侧优先沿用 asset_id 并正式扩展合同。内部任务键留在业务层，诊断 request_id 不冒充结果句柄；模拟器不能伪造 twin_id。

验收：同一线路两次运行产生独立可追溯结果；恢复回收只读原结果，不重复计算；报告引用指定执行版本。
R04 · P0本地审批标记需要升级为服务端可验证的执行约束当前事实：DSH 先审批再执行；远端信封不携带动作绑定的审批记录。

证据与风险

现有 approved 标记属于受管进程信任边界，不是跨服务的用户级授权证明。排队后参数、线路内容、目标或价格改变，不能自动沿用批准。

建议方向

审批绑定申请人、项目、固定内容摘要、规范参数、实际目标、报价和有效期；在受理事务中关联一次性消费，调度时复核前提。现有 ask / deny 不放宽。S3

验收：改参数、线路内容变化、并发重放、过期、撤权和设备重选都不能沿用失效审批。
R05 · P0幂等受理与物理设备只执行一次是不同问题当前事实：request_id 不是幂等键；现有设备零自动重试是正确保守边界。

证据与风险

数据库去重不能消除“设备已执行、回执丢失”的不确定性。加入队列或工作流引擎也不会自动获得端到端恰好一次语义。

建议方向

平台稳定意图键绑定请求摘要；同键同参返回同一受理，同键异参拒绝。事务发件箱、消费者去重、可信用量和定期对账配合；设备无法核对则继续停止自动重发。S4S5

验收：在受理、设备执行、结果落盘与结算边界注入崩溃；核对执行、审批、计量与扣费次数，不以 HTTP 成功率代替。
R06 · P0全自动混合迭代不能隐含绕过逐次设备审批产品约束：科学迭代可在执行器中运行，但下一次设备调用仍须获准。

风险

“把迭代放进 algorithm.run”如果同时给它不受限设备凭据，就可能避开原来的审批边界。当前合同没有后台迭代等待审批并恢复的完整机制。

建议方向

首期支持经典 / 模拟迭代和受监督设备步骤。平台会话、批处理和预约仅影响调度，不代表设备授权。Braket 也明确取消混合容器只对量子任务尽力取消，不能等同设备停机。S15

验收：第二次适用设备调用没有新批准就停止；累计采样、迭代、预算和期限有上限；算法组件不能通过独立凭据绕开设备准入。
R07 · P1QASM 入口需要版本化的受支持子集外部证据：语言合法、本地模拟成功与硬件支持是不同层次。

证据与风险

Braket 官方列出设备与本地模拟器支持差异。上传中的控制流、include、测量或脉冲内容不能只凭语法解析通过就投递。

建议方向

规定版本、门、控制与测量子集；隔离解析，限制大小、时间与展开操作数；按 provider 能力快照准入。保留原始、规范化和编译产物的来源关系。S8

验收：未知语句不静默忽略；不支持的动态电路明确拒绝；恶意 include 和巨大展开被阻断。
R08 · P1统一结果字段之前，先统一可解释的科学语义外部证据：SDK 中的逐次测量可能由概率后计算，未必是设备原始测量。

证据与风险

Braket 文档明确提供测量是否来自设备的标记。仅看字段名或一幅直方图，会把概率、真实采样和后生成样本混淆。

建议方向

保留真实测量 / 聚合计数 / 精确或采样概率 / 期望值的语义；记录位序、寄存器、映射、测量基、实际采样与后选择分母。模板按能力和数据质量选择，不盲目套置信区间。S9

验收：位序冲突或缺采样数阻止错误比较；只有概率时，不能伪称拥有真实时序样本或执行时序相关分析。
R09 · P1模拟、分析与本地推理也有资源和预算风险推导示例：双精度稠密状态向量 32 量子位仅数组就约 64 GiB。

证据与风险

Aer 文档说明稠密状态为 2 的量子位数次幂个复数振幅；双精度每个 16 字节。30 位约 16 GiB，40 位约 16 TiB，均未计复制和运行开销；其他方法不能直接套用。

建议方向

模拟前做方法相关估计与准入；限制 CPU / GPU / 内存 / 并发 / 存储 / 推理预算。预留、用量、结算和退款分开记录，重复计量事件去重。S10

验收：巨大模拟在执行前拒绝；小任务洪泛不能绕过累计配额；分析失败不错误抹掉已发生的计算费用。
R10 · P1本地模型接通 API 后，还必须验证工具行为外部证据：工具解析器、聊天模板和模型配置直接影响调用兼容性。

证据与风险

vLLM 文档区分自动、必需和指定工具调用；结构化输出保证不等于科学正确或有权限。本仓配置检查不证明公司模型已通过端到端测试。

建议方向

固定模型 / 量化 / 引擎 / parser / template 版本，复用 DSH。评测中文任务、参数校验、流式中断、重复调用、目录版本、拒绝后行为和未知结果处理。S6

验收：同时报告合法任务完成、误拒、无效参数、越权执行、时延和成本；不能把“全部拒绝”计为模型安全且好用。
R11 · P1知识、源码、报告与旧会话都需要授权与内容隔离当前事实：配置知识根上的短检索不是租户化企业知识系统。

风险

提示注入可以藏在文档、文件注释或工具描述中。撤权后的旧摘要、缓存、引用和下载仍可能泄漏。内联 HTML 报告若与工作空间同源，还可能获得会话访问。

建议方向

检索前过滤，读取 / 引用 / 缓存复核；长期记忆按身份隔离并处理撤权。优先受控组件，脚本内容采用独立 origin 与最小 iframe 权限；不继承 token 或设备 API。S7S11

验收：恶意文档无法触发未授权动作；恶意 HTML / SVG 无法读取会话或外发数据；撤权后旧引用不能重新拉取正文。
R12 · P1复现、数据归属和运营证据要从首期保存设计建议：结果资产、处理活动与责任主体分开建模，不自动把报告入库。

风险

事后难以补回编译、环境、校准时点和数据转换版本。真机重跑有统计波动；“可复现”不能承诺逐比特相同。知识总结也不自动带来客户数据使用许可。

建议方向

记录输入→执行→结果→模板→报告的来源；独立审核知识发布，定义保留与撤回。用结构化短事件观察授权、审批、用量与恢复；真实服务验收与本地测试分开。S12

验收：同一原始数据可重做报告；重新运行硬件只按预定统计标准比较；删除 / 撤回覆盖索引、缓存和派生内容的既定生命周期。

异构调度先做可行性，再做优化

  • 硬约束

    门集、动态能力、设备状态、校准新鲜度、权限、预算、数据位置和批准范围先全部满足。

  • 软目标

    在可行候选中权衡等待时间、费用与任务质量要求。队列位置是带时间戳的估计，不承诺固定完成时间。

HPC 与 QPU 协同分三层推进

  • 松耦合资产流 → 受控迭代

    先做预处理 / 量子步骤 / 后处理；再加检查点、预约租约和等待审批的恢复。避免 GPU 长期占用等量子队列。

  • 实时路径独立

    在线解码、离子时序与安全联锁留在设备系统。Slurm 异构作业不自动提供跨 QPU 联锁和原子预约。S13

  2. 撤销文档权限，旧缓存、原文、引用与会话访问按策略失效。
  3. 同意图并发提交，只产生一个受理与一次实际执行。
  4. 同一幂等键参数不同，拒绝而非覆盖原任务。
  5. 批准后修改线路内容、参数或目标，要求重新审批。
  6. 排队期间报价 / 授权 / 校准前提失效，重新准入。
  7. 设备已执行但响应丢失，标记待核对，不自动重跑。
  8. 结果文件不完整，隔离数据，独立处理实际用量。
  9. 取消与执行开始竞争，正确呈现停止点和部分费用。
  10. 事件重复、乱序或遗漏，不重复计费或回退状态。
  11. 不支持的 QASM 和超限解析被阻断，不静默降级。
  12. 位序、结果来源和采样语义不兼容时，阻止错误统计。
  13. 文档 / 文件注入不能触发越权工具调用。
  14. HTML / SVG 报告不能取得工作空间会话或外发数据。
  15. 本地模型参数截断、错误工具名、重复调用在执行前处理。
  16. 巨大模拟或大量小请求被累计预算与并发限制。
  17. DSH 或界面服务重启，恢复不触发新的设备执行。
  18. 第二次设备调用未批准就等待，算法执行器不绕过准入。

一次审批，绑定一次明确的执行

正式审批卡应显示：申请人与项目、目标 provider 与实际设备、线路句柄及内容版本、采样次数与执行参数、预算上限、报价版本、有效期和风险提示。

  • 批准的是固定执行快照，参数、设备或费用范围改变时重新校验与审批。
  • 固定的执行意图在受理时原子关联审批与幂等记录；调度时复核授权、预算和设备前提。网络重发只返回同一受理记录，不重新消费审批或再次运行。
  • 审批人资格来自平台角色，不能由模型自称或通过前端开关赋予。
  • 提交后状态未知时先核对原请求，不自动创建另一笔执行。

当前工具只提供已有合同字段。上述费用、版本绑定和有效期等产品能力须通过正式合同扩展与平台支持落地。
