## 一、当前结论

**你们已经有受控 Agent 内核、科学计算框架、成熟的云平台和 HPC，以及本地大模型和 DeepSeek。下一阶段的定位是“在已有平台与模型服务之上交付量子计算工作空间”，不是重建这些基础能力。**

若配置 **6 名有经验、稳定投入的工程人员**，另有产品、云平台、设备、安全和财务接口支持，从人员、测试环境和首期范围到位后起算：

- **模拟作业试点：9–15 周，约 2–3.5 个月。** 登录、三栏工作空间、受支持的 QASM、一个模拟器、任务跟踪、结果回收和一份分析模板。
- **受监督真机与计费试点：累计 12–20 周，约 3–5 个月。** 对接一个实际设备、逐次审批、预算 / 用量 / 账单和故障核对；不重建现有账本。
- **较完整目标的有界首版：累计 28–50 周，约 6.5–11.5 个月。** 有限内部知识、更多分析模板、基于已有平台的多资源协同、已验证算法服务接入、受监督校准及数据治理。

三个时间是累计值，不能相加。第三档不是“所有算法和所有硬件永久完成”：原创新解码算法、模型训练、重新部署基础推理服务、QPU 硬件开发、从零建设集群调度器和无人值守设备执行不在范围内。

**范围说明：** 这些数字保持原定量子工作空间的有界交付范围。2026-10-21 09:02 用户明确要求通用 Agent 实际执行能力；09:33 进一步明确 [v0.7 DSH 集成路线](company-agent-dsh-integration-v0.7.zh-CN.md)：本地模型 + 受管插件 / MCP + 常用 Skills，公司服务并列接入。需先盘点直接复用、薄适配与确需新增部分，按装配、权限、鲁棒性和验收重估，不能把通用能力清单全部计成自研后端。本页数字只作原量子专项参考，不代表当前产品总工期，也不与新集成工作机械相加。

当前首要路径是：**已有 API 接入 → 当前两仓合同对齐 → DSH 与三栏界面 → 结果语义与模板 → 新增授权边界与真实业务验收。** 开源组件按需复用，没有另外叠加未经实测的“提效倍数”。

## 二、哪些基础已成立，哪些仍需对接

### 2.1 既有能力分别判断，不混用成熟度

- **量子云平台与 HPC**：用户确认成熟，作为既有系统复用。账号、资源、队列、存储、计量、运维等以现有系统能力和正式 API 为准。
- **本地大模型与 DeepSeek**：用户确认已有，首期复用现有推理服务；模型服务与 DSH 是不同层，接口、工具调用及租户数据路径仍需对接验证。
- **Uniqon**：公司科学计算框架，源码位于 `/home/sunhl/projects/company-quantum-platform`。它不是云平台或 HPC 平台的同义名称。
- **Company Agent / DSH**：受控智能交互与工具调用层，当前产品化集成仍需完成。

前版提到的“公司 HPC 节点验收尚未开展”，指的是所读 Uniqon 工作负载的节点验证，不是说公司 HPC 平台尚未成熟。Uniqon 的本地失败 / 安装前提也不能当成云平台质量结论。

### 2.2 Agent 和科学框架已有基础可以复用

Agent 侧已有 DSH（DeepSeek Harness，唯一 Agent 运行时）、工具合同、参数校验、服务桥接、失败闭合、版本绑定、设备审批和短结果限制。

Uniqon 侧已有科学对象与来源记录、受管计划、预览、结果 / 检查点、预算，以及本地持久执行意图、取消请求和未知提交核对参考模型。这些有助于定义科学语义，但不应在 Agent 旁另建一套云作业状态机。

`provider_lifecycle.py` 明确限定单属主 POSIX 本地持久化；`session_ledger.py` 是无网络调用的参考用量记录。这些与成熟云平台的真实生命周期 / 账本进行映射，不把 cancelled / unknown 的参考数值直接解释成商业免费或退款。

### 2.3 当前两仓接口漂移仍需解决

前次只读 AST / JSON 比较确认：

- Agent 平台 provider 预期 `company-quantum-platform`。
- 当前 Uniqon adapter 声明 `PROVIDER = "uniqon"`。
- Agent 的跨仓夹具仍导入 `company_quantum`；当前科学框架使用 `uniqon`，旧源码目录不存在。

若直接连接这两份当前实现会产生身份不匹配；但没有运行实际部署复现故障，也不排除线上仍使用旧冻结版本。处理顺序是确认正式服务身份与版本策略，然后按“合同 → Python adapter → DSH 插件 → 测试”迁移和复验，不通过放宽身份校验或恢复旧工具名掩盖差异。

平台成熟不会自动消除这一集成差异，也不会取消逐次设备审批、模型结果内容边界和租户授权测试。

### 2.4 历史测试是有界证据，不是产品完成比例

Agent 2026-10-09 记录为 616 项本地测试通过，并有当时快照的独立双仓门禁；同一报告明确外部验收 blocked、生产授权 false。本次未重跑全量。

所读 Uniqon 2026-10-20 状态引用的全量门仍有 19 failed、6 errors、1 skipped，并解释为已有产品 / 安装前提；“没有新增失败”不等于“全量通过”。这些仅说明对应科学框架快照的验收范围，不代表成熟云平台或 HPC 的状态。

## 三、当前剩余工作按复用关系划分

### 直接复用成熟平台，不重复建设

- 身份源、组织 / 项目、已有资源权限和财务规则；
- 量子任务受理、状态 / 取消、队列和已有结果服务；
- HPC 作业、配额、运行环境和存储；
- 权威计量账本、部署基础设施和通用监控；
- 已部署本地大模型与 DeepSeek 的推理服务，不重做基础模型训练或推理引擎建设。

是否有符合 Agent 需求的委托凭据、幂等键、事件游标、结果读取方式，属于接口适配核对，不是重新评判整个平台是否成熟。

### Agent / 产品层仍需开发

- 真正连接 DSH 和平台的三栏 Web 工作空间；
- 当前登录用户到工具 / 资源访问的可信授权映射；
- 每次运行独立定位的结果引用和报告关联；
- 上传线路的受支持子集、内容版本与平台注册；
- 数据标准化、绘图模板、解释与受控内容展示；
- 内部源码 / 知识权限贯穿检索、引用、缓存与撤权；
- 平台审批与 Agent 本次参数快照的绑定；
- 真实模型行为、端到端故障与安全验收。

既有 HTML 是产品讨论原型，不等于业务前端已交付。官方 DSH 的上游界面 / 事件扩展也必须与本仓锁定版本核对。

## 四、到真机计费试点的剩余工作包

单位：**人周**，即一名熟悉相关技术的工程师投入五个完整工作日。正常单元 / 集成测试包含在各包内，K 为跨域演练与试用修正。

- **A · 当前两仓合同对齐与基线复验：3–5 人周。** 正式身份与版本、消费者和测试、首期范围。
- **B · 账号委托与租户 / 项目权限接入：3–5 人周。** 复用成熟身份与授权服务，适配可信上下文，验证撤权和双租户隔离。
- **C · 三栏 Web 工作空间：6–9 人周。** 真实会话、导航、任务列表、文件 / 报告标签及审批视图。
- **D · 既有本地模型 / DeepSeek 接入与行为评测：3–5 人周。** 复用现有部署和 DSH，固定模型版本、接口与工具格式，验证流式调用、数据目的地、限流及拒绝行为；不计训练、重新部署模型或从零研发推理引擎。
- **E · 有界 QASM 上传与输入资产：3–5 人周。** 授权、解析隔离、语言子集与线路版本。
- **F · 既有云任务生命周期适配：3–5 人周。** 接入受理、状态 / 事件、幂等、取消与未知结果核对，不另建权威任务服务。
- **G · 结果回收与一个分析模板：5–8 人周。** 每次运行关联、科学语义、授权读取、模板版本与复现。
- **H · 一个实际设备的受监督接入：4–6 人周。** 复用成熟设备 API，绑定审批快照并做真实服务验收。
- **I · 既有报价、额度和账单接入：2–3 人周。** 映射用量与账单，验证部分执行 / 取消 / 重复事件。
- **J · 成熟基础设施上的 Agent 部署：2–3 人周。** 复用凭据和运维系统，补新租户边界、内容沙箱、恢复和审计。
- **K · 跨域故障 / 权限演练与试用修正：5–8 人周。** 新增入口端到端测试，特别是重复执行和重复扣费。

**A–K 合计 39–62 人周；加入低端 20%、高端 30% 的联调 / 返工准备，向上取整为 47–81 人周。**

模拟试点取 A–G，再加 K 中 3–5 人周：**29–47 人周，风险后 35–62 人周**。后续不能再次重复计算已完成的 K；完整对外试点仍要完成 J 的适用检查。

与 v1.0 比较，v1.1 主要减少 B/F/H/I/J 合计 8–14 人周。减少的是治理补建 / 平台基础设施部分，不是移除新入口的安全验证。v1.2 仅将既有模型服务从规划假设明确为用户补充事实；D 原本就是接入与评测，因此这次不额外扣减。

## 五、扩展到有界较完整首版

- **L · 内部知识 / 源码授权与检索评测：7–12 人周。** 有限资料源、引用 / 缓存 / 撤权；不含无限量材料整理。
- **M · 多种分析模板与数据沉淀：9–15 人周。** 有限格式、来源、质量、审核、删除和版本。
- **N · 既有多 QPU 与成熟 HPC 的协同适配：8–14 人周。** 复用调度与资源 API，补任务依赖、数据传输、预约和失败语义；单个平台成熟不自动等于跨平台协同已经验收。
- **O · 已验证科学服务的扩展接入：8–14 人周。** 解码 / 优化 / 调度服务封装与准入，不包含原创算法或新模型训练。
- **P · 受监督校准与内部测试：10–18 人周。** 观测、方案、审批后实验、评估与候选参数。
- **Q · Agent 特有的稳定性、容量与成本验证：6–10 人周。** 复用成熟运维基础，只补新增产品负载与故障路径。
- **R · 扩展能力联合验收：7–11 人周。** 跨域联调和试用修正，不与 K 重复。

扩展增量 **55–94 人周**；加基础 A–K，累计 **94–156 人周，风险后 113–203 人周**。六人条件下按容量和关键路径采用 **累计 28–50 周**。

比 v1.0 扩展阶段减少 6–9 人周，主要来自 N/Q；内部知识、科学结果质量和校准流程不会因为 HPC 成熟而自动完成。

## 六、计算方法与人数敏感性

有效投入系数 70% 是沟通、跨团队配合与人员可用性的规划假设，不是实测效率。风险准备 20%–30% 用于未计划联调、缺陷和返工；工时已假设正常使用编码辅助，不另套“AI 十倍提效”。

$$
T_{\mathrm{capacity}}=\frac{E_{\mathrm{remaining}}(1+r)}{N\,u}
$$

其中 \(E_{\mathrm{remaining}}\) 为人周，\(r\) 是风险准备，\(N\) 为专职工程人数，\(u=0.70\)。日历规划取容量工期与关键路径区间对应端点的较大值。当前关键路径判断为模拟 9–15 周、真机 12–20 周、有界首版 28–50 周。

这些区间是工程判断，尚不是逐人逐周资源平衡排程，也不是统计置信区间。

- **3 人专职团队**：模拟 17–30 周；真机累计 23–39 周；有界首版累计 54–97 周。
- **4 人专职团队**：模拟 13–22 周；真机累计 17–29 周；有界首版累计 41–73 周。
- **6 人专职团队**：模拟 9–15 周；真机累计 12–20 周；有界首版累计 28–50 周。
- **8 人专职团队**：粗模型仍受关键路径限制，不能只按人数承诺低于六人区间。

建议六人配置：前端 1、后端 / 平台适配 2、Python / DSH / 模型接入 1、量子软件 / 设备集成 1、测试 / 可靠性 1。既有平台团队负责其系统与 API，产品、设备、安全和财务仍需固定支持，不计入上述六名工程全职人员。

## 七、历史情景保留，但不再作为当前基准

v1.0 的模拟 10–18 周、真机 18–30 周、有界首版 36–60 周，含部分平台治理补建风险。用户在 21:20 明确两平台成熟后，这些不再是当前默认估算。

此前成熟平台情景已经给出真机 **12–20 周**，本版将其提升为主基准并逐包对齐。v1.0 的 **26–46 周**“核心服务也要建设”情景只保留作历史敏感性说明，不再用于描述公司现状。

仍需核实的不是“平台是否成熟”，而是 Agent 接入所需接口是否有现成映射，例如逐用户凭据、审批快照、结果引用和重复提交语义。如果其中某项缺失，仅对该项追加适配 / 扩展估算，避免把整个平台重新计价。

## 八、前两周重点：接入验证，不是平台重建

1. 固定 Agent / Uniqon / DSH 的版本，确认正式 provider 身份和当前接口兼容。
2. 由既有平台团队提供身份、任务、结果、账本、HPC 作业 API 与测试租户。
3. 从既有本地大模型 / DeepSeek 服务中确定一个获准入口，取得非敏感接口说明，验证 DSH 的流式工具调用、错误和数据边界。协议兼容就直接复用；确有缺口且模型受支持时才评估 deepseek-recipe，不先重选推理框架。
4. 跑通两租户、一种线路、一个模拟器、两次独立运行和一份模板报告的窄链；关闭对话后仍能查询。
5. 确认一个实际设备的批准人、测试窗口与未知执行核对渠道。

这两周包含在 A 及并行工作中，不额外叠加，也不承诺两周完成整个商业产品。退出时使用实际接口和试验结果收紧估算。

## 九、DeepSeek 组件对排期的实际影响

- 优先复用 DSH 的既有模型、会话、事件和必要界面扩展；不另建 Agent 循环。
- 扫描 PDF / 图片材料多时试点 DeepSeek-OCR-2；已有文本 / 代码 / QASM / CSV 优先原生解析。
- 本地模型协议不完整且属于受支持模型时，评估 deepseek-recipe；已有兼容服务无需多包一层。
- DeepInfer、DeepGEMM、FlashMLA、DeepEP 按模型、硬件和实测瓶颈由推理平台团队选择，不进入首期强制依赖。
- 3FS、smallpond、DualPipe 不因开源而替换成熟存储、数据系统或 HPC 调度。

官方 DSH 仍标 developer preview，安全文档明确不能作为唯一安全边界。复用平台基础设施不等于免测新 Agent 的权限、插件和内容渲染路径。详细官方依据和限制见配套选型文档。
