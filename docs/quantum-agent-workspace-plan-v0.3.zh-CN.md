## 一、这次确定的产品形态

### 1. Agent 有自己的用户制度

- 左下角固定账户入口，未登录时显示“登录 / 注册”，登录后显示用户头像、名称和账户菜单。
- 提供注册、登录、退出和切换账号；工作空间、会话映射与外部连接按用户和项目隔离。
- Agent 账号表示“谁在使用本产品”；云平台账号和超算账号表示“当前用户绑定了哪些外部资源”。两者不能合并成一个含义不明的 token。
- 独立产品账户入口不要求重复建设密码数据库。优先接入可信身份服务；条件合适时可复用现有平台身份源或企业单点登录。
- 身份服务选择、开放注册或邀请注册、企业组织策略，留待接口盘点确认。前端不能自行宣布用户已登录或具有某个角色。
- DSH 本机启动地址中的登录 token 是运行时访问凭据，不是产品注册登录制度，也不能直接对外作为共享用户会话。

### 2. 左下角齿轮进入设置

设置在中栏作为独立标签页打开，当前对话保持不变。至少包含四个区域：

- **Agent 账号**：当前产品用户、注册 / 登录入口、退出与组织 / 项目授权信息。
- **云平台账号**：平台网页地址、绑定账户、授权状态、默认项目 / 目录、连接与撤销入口。业务 API 地址与网页地址分别建模。
- **本地超算**：HPC（高性能计算集群）内部页面地址、受管网关 / API 地址、集群账户、默认目录和授权状态。具体调度与文件接口按真实集群确认。
- **模型与对话**：进入 DSH 原生模型配置。模型名称、模型切换、上下文容量与用量、压缩提示等使用固定 DSH 版本实际支持的功能，不重写一份配置、凭据存储或 token 统计。

云平台 token、SSH 私钥与模型 API key 不能进入模型上下文、工具结果、页面 URL 或浏览器持久存储。正式产品由可信后端或操作系统密钥库管理；界面只展示最少必要的连接状态。模型凭据继续由受管 DSH 配置入口负责。

### 3. 左栏固定目录顺序

从上到下：

1. **云平台**：默认收起，只显示根标题；展开后是授权项目、文件夹和文件，以及平台页面入口。
2. **本地超算 / HPC**：默认收起；展开后是获准目录、文件、日志和集群内部页面入口。
3. **本机文件**：展示当前用户明确选择的本地目录。Web 版本需显式目录授权或受管本地连接器，不能默认拥有任意本机路径的读取权。
4. **工作空间 / Workspaces**：采用 Cursor 的“文件夹式项目 → 多个对话”交互。每个工作空间展开显示自己的 DSH 会话。
5. **底部账户与设置**：固定在左下角，不随目录内容滚走。

“平时隐藏”按默认折叠子目录实现，根入口仍可见，便于发现和展开。目录折叠状态是展示偏好，不是权限控制；未绑定、无权限和网络不可达应各自显示真实状态。

这里的 Cursor workspace 指交互组织形式，不承诺读取或同步 Cursor 私有会话数据库。本产品的对话真源仍为 DSH；外围界面只保存经鉴权的用户 / 项目到 DSH 工作空间与会话的关联。

### 4. 中栏是统一内容展示区域

中栏使用多标签页，支持切换、关闭、重复打开定位已有标签；同名文件按来源与连接区分。

包括：

- 云平台现有网页：首期直接链接 / 展示，不先重建其业务页面。
- HPC 内部网页：与云平台页面相同的嵌入和降级规则。
- 云平台、集群、本机目录打开的文件：保留来源、授权与版本，默认只读。
- AI 请求分析后产生的图表和报告：分析服务生成实际产物，中栏展示；DSH 接收合同允许的短摘要和引用。
- Canvas：受控的分析 / 内容页面，同样在中栏打开，不替换右侧对话。
- 设置：统一中栏入口。

切换文件、报告或设置不会隐式切换对话，也不会自动把全部文件正文加入模型上下文。关闭标签不删除文件、作业或会话。选择左栏另一条对话才切换右侧 DSH 会话。

平台页面必须先核实 CSP `frame-ancestors`、`X-Frame-Options`、Cookie、跨站登录和页面自身导航限制。允许嵌入时才在中栏嵌入；否则中栏明确说明限制并提供新标签页打开，禁止用代理删头或传 token 的方式绕过限制。能打开网页不等于已接入文件目录、作业 API 或用户级授权。

### 5. 右栏原样复用 DSH

- 直接使用固定版本 DSH 原生对话组件 / 页面，不绘制一套相似的仿制聊天界面。
- 消息流、输入框、停止、工具记录、审批、模型展示与上下文用量保留原行为。
- 左栏的工作空间与对话只负责导航，实际会话创建、恢复、消息和工具生命周期仍由 DSH 管理。
- 左下角“设置 → 模型与对话”打开原生 DSH 设置；外围界面不维护第二份模型列表、API key 或上下文数字。
- 先核实固定版本可用的组件挂载、路由和设置扩展点。没有验证前不声称支持“只嵌入对话区域”或某个上下文开关。
- 若上游没有可用挂载点，选择范围最小、可持续维护的外围布局扩展，保持内部对话与状态逻辑不变；不能为方便集成新增模型循环、会话循环或工具执行循环。

## 二、系统职责的调整

### 产品身份与连接服务

可信身份服务管理产品用户；工作空间后端管理用户 / 项目、连接授权及可见目录的关联。外部资源服务仍验证自己的用户、项目和对象访问许可。模型不得声明自己的用户身份、租户或角色。

连接配置只是配置，不签发执行许可。登录 Agent、绑定平台账户、能够打开平台网页，以及被允许提交设备任务，是四件独立的事。

### 工作空间界面

只负责左栏导航、中栏内容与设置、右栏原生 DSH 挂载。目录、会话、报告和连接从已授权的后端读取；中栏不承担模型推理或科学计算。

账号切换 / 退出时清除旧用户的目录树、打开内容、会话关联、事件订阅和连接缓存，禁止残留跨用户数据。对已受理作业是否取消或继续，使用平台自身规则，不能把退出界面视为设备已停止。

### DSH 与 Company Agent 合同

DSH 仍是唯一 Agent Runtime。现有 `contracts/`、Python adapter、DSH 插件的职责和调用顺序不变。

此次原型不修改科学工具 schema；产品身份、目录和连接管理也不应随意暴露为模型工具。后续若确需增加模型可见工具，严格按合同 → Python adapter → DSH 插件 → 测试实施。

保持所有既有边界：

- 算法仅从平台 `algorithm.catalog` 发现，不固化算法名单或直接 import 科学包。
- 模型科学句柄只有 `asset_id`、`circuit_id`、`twin_id`。
- 仅 `quantum_device_run` 且 provider 为 `ionstack-twinrun` 可返回 `twin_id`。
- 设备运行在 `lab / sign` 必须 ask，在 `boot / algo` 必须 deny。
- 官方 Codex 保持 `permissionMode: never` 和 `inheritsParentContext: false`，不挂模型可见委派工具。
- 不开放带 shell 的可写 preset（运行配置）绕过审批；未知工具、preset、provider 与坏信封失败闭合。
- 大文件、完整电路、敏感控制正文和凭据走受控内容通道，不进入工具结果。

### 内容与分析服务

完整文件、可视化与报告通过独立授权通道进入中栏。网页、HTML / SVG 报告和 Canvas 的来源分开处理；用户生成的可执行内容不能继承产品会话、平台 token 或设备访问权。

分析请求仍经 DSH 工具调用与受管服务完成。展示图表不要求把原始结果或所有绘图数据塞进模型结果，也不把任意脚本执行器装入普通对话 preset。

## 三、按可验收范围分阶段实施

### A. 设计和交互确认（本轮）

已调整 HTML 原型：默认折叠的云 / HPC 目录、本机目录、工作空间会话分组、左下角登录注册和齿轮、中栏标签页、设置分类、分析视图及 DSH 挂载说明。

原型的注册登录只展示界面流程，不接受真实凭据；连接配置仅为当前页面内存草稿，不访问网络、不验证凭据、不持久化。没有添加模拟登录成功、假模型回复、虚构上下文用量或设备操作。

### B. 确认接入边界

- 确认产品身份服务、注册策略、组织项目映射和退出 / 撤权行为。
- 获取云平台与 HPC 的测试网页、接口说明、文件授权方法及是否允许嵌入的响应头。
- 核实固定 DSH 版本的原生对话 / 设置挂载方式、会话与工作空间 API、多用户隔离和上下文显示能力。
- 确认首期为 Web 本机应用、桌面封装或共享部署。默认延续 Web 方案；不能先以共享 DSH token 充当多用户部署。

这些属于真实服务接入依赖，不需要在设计原型中收集账号密码。

### C. 实现最小可用的产品界面

先实现登录保护与工作空间隔离、左栏 / 中栏内容路由、原生 DSH 挂载与设置导航。首个版本可以只提供平台页面入口和用户显式授权的本机文件；未接入的远端目录保持“未连接”，不生成假的目录或成功状态。

若修改业务接口，先确定其合同与责任，再实现对应后端和适配；公司科学插件仍只做工具注册与转调。界面工程应独立管理，不把业务逻辑塞入 `profiles/` 或既有工具插件。

### D. 接入目录与分析产物

增加云平台 / HPC 授权目录、文件读取和报告展示；为异步数据分析补齐真实受理、结果定位和失败语义。沿用 v0.2 的执行、结果、分析、计费四条状态轴。

### E. 生产验收

身份 / 文件 / 会话隔离、DSH 审批和取消语义、门户嵌入降级、远程凭据保护、恶意内容隔离、撤权与缓存清理分别验收。设计 DOM 测试通过不代表这些能力已经实现。

## 四、验收条件

1. 左下角登录 / 注册与齿轮始终可发现；注册登录必须由可信服务确认，退出后的受保护请求被拒绝。
2. 两个用户拥有同名目录与工作空间时，文件、对话、连接和缓存不能相互读取；身份切换后不能残留旧内容。
3. 云平台与 HPC 默认折叠；展开只是读取授权目录，不自动执行命令、计算或设备任务。
4. 左栏顺序固定；本机目录使用明确用户授权，工作空间展开显示自己的 DSH 会话。
5. 同名文件按来源区分；中栏开关标签、查看图表或进入设置不丢失右侧会话。
6. 云平台 / HPC 页面允许嵌入则嵌入，拒绝时提供正常打开入口；页面能打开与账号 / API 已连接的状态分开。
7. 设置中的云 / HPC 连接相互独立，错误 URL 和过期授权得到明确失败；密码、token 和私钥不进入模型、URL、日志和浏览器持久存储。
8. 模型设置、上下文显示、消息与工具执行行为同原生 DSH 一致；没有新建第二份模型配置或会话运行逻辑。
9. 原生审批流程不变；`lab / sign` ask、`boot / algo` deny 不受界面、身份类型或连接设置影响。
10. 原始科学结果走授权内容通道；Canvas / 报告中的不可信内容无法取得产品、平台或设备凭据。

## 五、本次验证范围

原型自动化检查位于 `tests/ui/`，与现有 DSH runtime 依赖隔离：

- 执行 `npm ci --prefix tests/ui` 安装固定的测试依赖。
- 执行 `npm test --prefix tests/ui` 检查目录顺序 / 折叠、账户弹窗、中栏标签与会话独立、连接草稿分离与清除、URL 校验与转义、DSH 复用边界、原有架构页交互。

这些测试使用解析后的页面 DOM；弹窗行为在该环境中使用测试替身。7 项检查通过。另外使用 Chromium 145 验证原生弹窗与 Esc 关闭、连接草稿保存、文件 / 会话切换独立、目录滚动时账户入口固定；1440、1024、768、390 像素视口均无页面横向溢出，已查看桌面原型与设置截图。

只读 Python 策略探针确认 `lab / sign` 为 ask、`boot / algo` 为 deny，未知工具和未知 preset 为 deny。尝试运行原有 Python 回归时，当前环境缺少 `hypothesis`，因此测试在加载阶段失败；没有把该尝试计为通过，也没有宣称完成全套回归。

真实身份认证、目录授权、DSH 挂载、科学服务和设备均未通过本次设计测试验证。生产用户制度仍需按上面的阶段另行实施。
