# 发布完成计划

日期：2026-11-09。产品是公司座席上的一个 DSH。量子研发、算法、理论计算、模拟和测控都在这一个 agent 里工作：办公和知识用 `boot`，只读排查用 `algo`，实验卡用 `lab`，签署计算用 `lab` 或 `sign`。DSH 仍是唯一 Agent Runtime。不把电脑上的每一个程序都搬进仓库，也不另写模型循环。

阶段顺序以手册第 6 节为准。本文只记录离可发布还差什么，以及哪些项不能由开发审查循环填完。

## 已经落地

- 合同、四个预设、插件划分和一次一批准。真机在 `lab` / `sign` 询问，在 `boot` / `algo` 拒绝。
- S1 的本地 `val_loss`、S2 的超算与云交接、S3 的章程和租户摘要，见 `docs/implementation-2026-11-06-s1-s3.zh-CN.md`。
- 开发座席上的云模拟器和超算烟测。这不是生产验收。
- 开发审查循环在 DSH 外面跑已登记的目录。目录用尽就停。

## 内部座席还差的两步

1. 开发审查循环每一拍自己跑一张实验卡：先编译，未批准时询问，批准后回执里有停止原因、次数、决策和候选触发，并且没有 `twin_id`。基线未复现则不运行。桌面界面上的「允许一次」仍由人在 DSH 里点。
2. Owner 把量子平台地址、GitLab 地址和令牌、模型端口写入私有环境。没写就保持失败闭合，不在仓库里伪造。

## 还不能叫发布

`docs/deployment-and-evidence.zh-CN.md` 写明：工程工具完成不等于生产授权。离线报告保持 `production_authorized=false`。生产启动要有仓库外的清单签认和人工证据。本计划不把这些标成已完成。

S4、S5、S6 不开始。S4 要等检索源，S5 要等可锁定的上游版本，S6 要等身份、账单和模型 Owner。全公司多租户生产以手册 S6 的退出标准为准。开发审查循环不提前做这三段，也不把缺 Owner 的项测成通过。

## 每一拍怎么走

人用自然语言说下一件。执行的人把它写成 `docs/dev-review/catalog.json` 的一项，附上 edits，再用新的输出目录启动。循环只改该项列出的文件。启动界面可以改成公司账号和密码，进入后仍是带公司风格和适配的 DSH 界面。已安装运行时不改。人还没点批准、Owner 还没给地址时，循环停下来等，不自己发明下一件功能。
