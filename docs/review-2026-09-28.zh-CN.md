## 结论与范围

现有分层符合项目方向：DeepSeek Harness（DSH）负责唯一运行时；本工程维护合同、确定性策略、知识检索及独立科学服务的 provider bridge（服务调用适配层）。本轮保留现有 11 个工具和三种科学句柄，没有新增模型循环、会话循环、科学算法或设备执行入口。

审查覆盖 `contracts/`、`src/company_agent/`、`packages/`、两个生产 profile、启动/验证脚本、依赖锁、发布配置和测试。审查方式包括源代码阅读、离线反例、回环 HTTP 测试、跨 Python/JavaScript 的工具注册与执行测试、wheel 安装测试，以及真实 DSH 会话装配验证。这里的“全面”指上述工程层面覆盖，不代表真实科学结果、模型任务效果或物理设备安全已经验收。

## 按优先级排列的发现和已实施修改

### 1. 高优先级：provider 结果与错误文本可绕过输出边界

- 原行为：`summary.apiKey`、`summary.accessToken` 等驼峰字段不在分词后的禁止字段集合中；非设备结果可以在嵌套摘要声称 `qccd-twin`。HTTP 错误和失败信封中的短字符串，只要没有命中少量敏感关键词就会原样回传。
- 影响：服务端调试输出可能将凭据、底层科学正文或错误的设备来源带入模型上下文。字段黑名单不等价于内容安全保证。
- 修复：新增 `contracts/results.json`；对字段做 Unicode 规范化和驼峰分词，拒绝常见凭据/科学字段及科学句柄别名；仅设备执行的顶层 `provenance` 可声明设备来源；拒绝明显的 OpenQASM 正文和 PEM 私钥标记；provider 错误一律转成固定失败信息。未知输出字段和重复 JSON 字段的错误不再回显远端字段名。
- 回归：`tests/test_providers.py`、`tests/test_review_regressions.py`，包含回环 HTTP 的端到端拒绝断言。
- 剩余边界：任意秘密放入语义无关的普通字符串无法靠通用黑名单完整识别。生产 provider 应继续只发送受审计的结构化摘要；后续应逐 provider 收紧 `summary` 的允许字段，而非承诺通用脱敏可以识别一切内容。

### 2. 高优先级：合同校验可以忽略坏 schema 分支

- 原行为：可选属性未出现在数据中时，其 schema 不会被检查；属性 schema 是整数或 `null` 等坏值时可能被直接跳过。`const` 使用 Python 普通相等比较，混淆布尔值和数字；`uniqueItems` 通过 JSON 字符串去重，不能识别数字 `1` 与 `1.0` 等价。
- 影响：坏合同可能仍被注册，甚至先调用外部服务，再在返回阶段才暴露输出合同问题。
- 修复：将 schema 定义检查与数据校验分开，递归检查所有分支；`load_tools()` 在提供工具目录前验证输入/输出定义；修正 JSON 等价语义、布尔元数据检查和 `pattern` 的搜索语义。句柄 schema 同步收紧为已有 adapter 所要求的 ASCII 字母、数字、下划线和连字符。
- DSH 同步：只允许 Python 合同支持的已知关键词；拒绝未知关键词、缺失 `properties` 和无效子 schema，仍剥离 DSH 不支持但 Python 会检查的数值、长度等约束。
- 回归：schema、合同目录、句柄、DSH 注册投影与新反例测试。

### 3. 中优先级：没有聚合结果预算，“每字段短”不保证工具结果短

- 原行为：32 个各 4,000 字节的字段可以形成约 128 KB 摘要并通过过滤；DSH 渲染层最多允许约 1.1 MB，接近传输层预算而非模型结果预算。
- 修复：`contracts/results.json` 规定模型可见结果为紧凑 UTF-8 JSON，最多 64,000 字节；Python 的本地与 provider 工具均检查聚合体积，DSH 返回和渲染端同步限制。禁止内容和超限结果整体失败，不通过删字段或截断伪装成功。
- 兼容性：原本依赖超大摘要的 provider 需要缩减摘要；不改变工具名、provider 协议或句柄种类。

### 4. 中优先级：严格 JSON 和跨语言桥接存在失真与异常边界

- 原行为：`1e999` 被 JSON 解析成无穷大；孤立 Unicode 代理项与过深 JSON 可产生未规范化异常；直接 `--args` 不受 stdin 同样的原始体积限制。JavaScript 会将 `NaN`、无穷大、负零和 `undefined` 改写或丢弃后再交给 Python。
- 修复：严格 JSON 解码拒绝指数溢出、非法 Unicode 和超过 64 层的解析结果；CLI 直接参数也应用体积限制；JavaScript 序列化拒绝会丢失信息的值。
- 同时加强 Python 子进程导入边界：使用 `-P` 排除启动目录同名包覆盖，保留指定的受管 `PYTHONPATH`。回归测试在临时启动目录放置会抛错的同名包，确认实际调用仍来自项目源码。
- 加强 CLI 结果检查：拒绝缺失字段、不一致的授权结果、未经批准却报告成功的 ask 结果，以及成功但载荷不是对象的结果。

### 5. 中优先级：知识检索版本不可追溯，遍历工作量没有真正受限

- 原行为：全部命中都标为 `workspace`，文件内容改变无法通过版本识别；先 `sorted(root.rglob('*'))` 再限制成功读取的文件数，目录遍历与排序可能先耗尽时间/内存。
- 修复：命中版本改为原始文件内容的 SHA-256；目录枚举预算 20,000 条、深度最多 32 层、读取最多 10,000 个文件、累计最多 16 MB；单文件读取仍限 1 MB，维护至多 8 条最佳命中；越过来源字段长度限制的条目跳过。
- 剩余事项：中文检索仍是确定性词项匹配，不是语义检索；超过扫描预算时只覆盖有界子集。扩大知识库前应使用固定评测集决定是否引入索引和分词，并在合同中明确部分检索的标识。

### 6. 中优先级：生产合同根与验证环境应更明确地隔离

- 原行为：生产启动和验证进程可继承外部 `COMPANY_AGENT_CONTRACTS_DIR`；验证子进程还继承真实科学服务和模型配置，本地认证 HTTP 使用环境代理。
- 修复：生产启动和验证固定项目 `contracts/`；直接 CLI 保留显式合同覆盖用于测试。验证子进程清除模型及科学 provider 的地址和凭据；回环认证连接禁用环境代理。
- 策略补强：`decide()` 独立确认工具属于真实合同，即使坏 preset 将未知工具加入可见列表也返回 deny。
- 小型维护优化：合同根查找在找到源码合同后不再无条件枚举安装元数据；provider 合同使用同一次文件读取的内容，避免双读验证不同快照。

### 7. 低优先级：provider 接入文档中的成功信封无法通过当前校验

- 原示例没有 `request_id`，`algorithm.run` 成功结果为空对象。
- 已修正 `docs/ARCHITECTURE.md`：完整展示请求 ID 回传、算法结果句柄、失败信封规则、结果预算与错误文本处理要求。

## 保持不变并复核的约束

- `quantum_device_run` 在 `lab` / `sign` 为 ask，在 `boot` / `algo` 为 deny；显式 approved 也不能将 deny 改成 allow。
- 只有 `quantum_device_run` 且 provider 为 `ionstack-twinrun` 可返回 `twin_id`。
- 最小 profile 不加载设备插件；完整 profile 的 Codex provider 保持 `permissionMode: never` 和 `inheritsParentContext: false`，不暴露模型可见的 Codex 委派工具。
- 两个 profile 关闭 DSH 内置和用户可写 preset 根；真实会话清单没有 shell 或 Codex 委派工具。
- DSH 的已安装工具执行实现先处理 pre-execute 的 ask，再经过批准服务，最后才调用注册的工具处理函数；本工程没有替代该生命周期。
- 本轮不放宽旧架构清理门禁；仅将新的结果合同加入允许文件集合。

4. 给 Python 开发依赖生成受管锁定或约束文件；持续核对直接依赖和传递依赖。当前 DSH 入口为 `0.1.5-rc.2`，锁文件包含 `0.1.5-rc.3` 的组件，不能将入口版本误写成全部组件版本。本轮没有升级任何生产依赖。

### 下一阶段三：性能与可观测性

1. 先测量每次 DSH 工具调用的 Python 启动、合同读取、校验和 provider 请求耗时，再考虑不可变合同快照或减少重复授权进程。任何缓存必须包含合同身份/版本，且不能复用人工批准。
2. 知识库扩容前建立中文检索准确率和延迟评测，再决定索引、分词与版本缓存；避免未经测量引入额外数据库或新的运行时。
3. 在现有 DSH 和 provider 日志中使用请求 ID 关联耗时、状态和错误类别；仅记录短元数据，不记录凭据或完整科学正文。

## 2026-09-29 全量整改增补

### 已交付的仓库改造与证据入口

1. **封闭摘要与严格合同。** `tools.json` 为 `1.2.0`、`results.json` 为 `1.1.0`，七项能力的操作合同为 `/1.1`；传输协议不变。七个操作的摘要只接受已定义状态、耗时及适用计数。六份合同形成单次调用内不可变快照，身份为内容 SHA-256；全部 provider 的字段和操作映射在发送前验证，再于网络边界核对合同内容。坏分支、未知字段、文件变化和最终路径符号链接失败闭合。证据：`test_contract_upgrade.py`、schema/catalog/provider 测试。
2. **多分支工作流。** 支持多个同类型输出，以 `bindings` 选择具体上游；旧 `needs` 只有唯一上游时自动解析。自引用、未来步骤、未声明输出、类型不符、来源歧义和错误设备来源均拒绝。`valid` 仅表示结构与参数通过，不执行计划、不兑换批准。证据：`test_workflow.py`。
3. **结果未知与短诊断。** 设备发送边界后超时、断连、取消或不可信响应，保留关联请求 ID 并报告未知，自动重试为零；请求 ID 不是服务幂等保证。诊断只含闭合元数据，stdout 仍为单个结果信封；开始诊断不可写则不发送。DSH 桥接终止子进程后等待退出及管道关闭；合法 JSON 但非法结果信封也保留未知语义。证据：`test_contract_upgrade.py` 的真实回环断连/坏结果与 `test_bridge_behavior.py` 的子进程行为测试。
4. **真实 DSH 生命周期及组合隔离。** 测试夹具挂载锁定 DSH 的真实工具、会话、审批与执行循环服务，固定模型只输出预设内容，科学服务仅监听回环地址。覆盖策略拒绝、用户拒绝、一次允许、重复询问、通道缺失、批准前取消、迟到批准、发送后取消/超时共十个场景，核对服务调用次数和审批事件。超时测试在服务收到请求后触发实际桥接定时器回调，避免把启动耗时误当发送后超时。六个合法组合实际创建认证会话；最小组合 `lab/sign` 启动拒绝。preset 验证使用真实会话对象，要求只读复制和未找到切换目标的明确错误码，并确认工具不变。证据：`test_dsh_lifecycle.py`、`verify_dsh_profiles.py`。
5. **检索质量、部分扫描与性能。** 八类固定原因描述扫描未完成；返回前八条本身不意味着部分扫描。采用轻量中文双字词项和有限同义扩展，固定合成集的前八条召回率由 0.4286 提升至 1.0；这不是实际用户或模型质量结论。基于重复合同读取剖析采用仅限调用范围的快照，没有批准缓存、数据库或向量服务。各轮延迟有升有降，尚未证明稳定提速；确定性收益是减少同次调用重复读取并保持合同一致性。证据：`test_knowledge_quality.py`、`benchmark_company_agent.py`、性能记录。
