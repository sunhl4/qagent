## 1. 前提

公司 Agent 运行时只有 DSH。公司包是 DSH 插件：登记合同里的工具，执行转给 `company-agent invoke`。插件里不写模型循环、会话循环或工具循环。

上游 `dsh-superagent-prototype` 在合同里的状态是 `official_status: unreleased`。公司采用它的对象和失败闭合：Source、Trigger、Eval、Mandate、Ticket、Assignment、Subscription。公司不复制它的内部表、提示词、Router、Worker 或 Watchdog。执行面是已经存在的一个 DSH 会话加上公司工具包。`forbidden_worker_modes` 包含 `danger-full-access`、`shell`、`second-loop`。

Mandate 只有四个：`boot`、`lab`、`algo`、`sign`。兼容的 DSH 版本记录为 `0.1.5-rc.2` 与 `0.2.1-rc.5`。开发桌面用仓库里的 `scripts/dev_desktop.ps1` 启动当前改过的客户端。

这条前提决定后面所有阶段：新能力先改 `contracts/`，再改 Python 适配器，再改 DSH 插件登记，最后改测试。未知工具、未知预设、缺失 provider、坏信封全部失败闭合。

上游 Super-agent 的整条流程是控制面基座，不是公司旁边的另一套产品。流程是：来源进入工作项，工作项带终态、预算和截止，书面规则写进 Mandate，一次 DSH 会话在能力边界内调用工具，结果回到原对话，只有必须由人决定时才占用注意力。

现在原型仍是 `official_status: unreleased`。`company_work_item` 的本地账本是这条流程的薄替身，角色记在 `contracts/superagent.json` 的 `architecture.flow_foundation`：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `owner_when_locked` | `upstream-super-agent` | 可锁定版本出现后，流程由上游拥有 |
| `stand_in` | `local-control-plane` | 锁定前由本地账本走同一条对象链 |
| `company_keeps` | 工具包、策略、平台时钟 | 办公、超算、云、真机、研究、租约和证据留在公司 |
| `required_upstream` | Router、订阅、注意力面板 | 任务量上来之后，没有人逐条输入也要能分发 |
| `replaced_when_locked` | 替身工单库、替身线程绑定 | 换掉的是今天的薄账本，不是 Router |
| `unattended.entry` | `source-event` | 无人输入的任务从 Source 事件进来 |
| `unattended.default_until_rule` | `observe` | 没有书面规则时只记录，不开工单 |
| `unattended.company_policy_still_applies` | 真 | 工单打开后，超算、云和真机仍走公司策略 |

Router 和订阅是基座的必要部分。后续 Company Agent 要同时处理很多自动化任务，其中一部分没有人在对话里输入。这些任务由上游 Router 按订阅推进到对应会话，人只在注意力面板上处理必须亲自决定的项。公司仓库不平行再写一套路由器或会话循环。今天的 `subscriptions` 表只在开工单时记下工单和线程的对应，不能自己监听外部事件，也不能在没有 DSH 会话时把任务跑起来。

因此每个新功能都要能被一个 Source 事件唤醒：要么是会话里的一个公司工具，要么是平台时钟投出的候选触发，要么是一张实验卡。开工单仍只走 `evaluate`。没有书面规则时保持 `observe`。书面规则把 `strength` 定为 `explicit` 后，才允许 `mode=auto` 打开工单。科学结果、会话正文和密钥继续留在账本外面，这样上游替换工单存储时不必迁移实验数据。

审批不因上游更新而放宽。超算、云、真机和计划写操作仍按公司策略询问或拒绝。上游原型里「以操作系统用户免审批执行」不作为生产配置。

## 2. 三个面

```text
员工、工作区、研究事实
        │
        ▼
控制面  Source → Trigger → Eval → Mandate → Ticket → Assignment
        │  Mandate = boot / lab / algo / sign
        ▼
执行面  一个 DSH 会话 + 公司工具包 + 审批策略
        ▲
平台时钟  research-layer：实验、租约、预算、证据
        └── 只投递 research 候选触发
```

| 面 | 拥有 | 不拥有 |
| --- | --- | --- |
| 控制面 | 本地工单账本；受理模式 `off` / `observe` / `auto` | 模型循环、科学结果、资源调度、全公司事实源 |
| 执行面 | 当前 DSH 会话、公司工具包、策略插件 | 第二个 Agent、带 shell 的编码预设、未发布的官方 Super-agent 包 |
| 平台时钟 | `research-layer/` 的实验规格、循环、租约、成本和证据 | 根目录工具合同、工单终态、设备批准、超算提交 |

控制面合同要点：

- 默认受理模式是 `observe`。工单只在 `evaluate` 同时满足 `mode=auto` 与 `strength=explicit` 时打开。
- 开放来源是 `company`、`workspace`、`research`。`github` 与 `feishu` 在合同里为关闭，写入会被拒绝。
- 账本角色是 `local-control-plane`，`company_fact_store` 为假。SQLite 执行本地规则，不是全公司多租户事实源。
- 同一租户、同一幂等键、同一载荷指纹返回原来的触发。载荷不同则拒绝。
- 同一触发最多一张未结束工单。会话绑定只在引用仍为空时写入，不能改绑。
- `unknown` 执行可以查询，不能重新提交。`reconcile` 只把它结案为 `ended`。
- 执行记录只保存 `dsh:` 会话引用和工具包名称。`recover` 只读回这组短字段。
- 平台信号只有 `experiment.completed.v1`、`lease.changed.v1`、`budget.exhausted.v1`。信号是候选触发，不开工单，不调用设备。
- Watchdog 的实现就是公司策略。它不能改策略、预算或租约，不能在未知执行时重试，不能自己开工单。

根目录 `contracts/` 与 `research-layer/contracts/` 不合并。研究层需要计算时走自己的 `ComputePort`。公司翻译层可以接这个端口，研究层不直接 import `company_agent.hpc_ssh` 或 `providers`。

## 3. 工程现在有什么

### 3.1 仓库分层

| 位置 | 职责 |
| --- | --- |
| `contracts/` | 工具、能力、provider、策略、预设、Super DSH 合同 |
| `src/company_agent/` | 合同内核和南向适配器 |
| `packages/` | 九个 DSH 插件，只注册工具并转调 |
| `profiles/` | `company-agent` 与 `company-agent-minimal` 两个组合 |
| `desktop/company-agent-preset` | 开发座席的预设与人格说明 |
| `research-layer/` | 平台时钟的库、schema 和桩适配器。默认装配是 `adapters/stub/` |
| `tests/` | 目标架构门禁 |

生产组合关闭 DSH 自带预设和用户可写预设根，只留 system-trust 的公司组合。

### 3.2 插件

插件按凭据、审批爆炸半径，以及能不能从某个组合里物理拿掉来分。

| 插件 | 能力 | 审批 | 划分理由 |
| --- | --- | --- | --- |
| `company-agent-policy` | 不登记工具，占 `tools/pre-execute` | 把 Python 的询问交给 DSH 卡片，名单外的询问改成拒绝 | 工具包不能自带审批 |
| `company-agent-core` | `company.workflow`、`company.knowledge`、`company.portal` | 无 | 工单、知识和一个门户是每个座席都要的 |
| `company-agent-quantum` | 算法、资产、仿真、编译、`compute.cloud` | 云提交要人批 | 云不签发 `twin_id`。以后若要「有算法目录、无云 worker」的组合，再把云拆成与超算同级的插件 |
| `company-agent-hpc` | `compute.hpc` | 提交、暂存、建目录、删除、取消要人批 | SSH 凭据和失败域单独 |
| `company-agent-device` | `quantum.device` | 人批 | minimal 组合不安装它，真机工具才是物理缺席 |
| `company-agent-latex` | `company.latex` | 写和推送要人批 | 有 Git 推送和 Overleaf，和办公分开 |
| `company-agent-office` | `company.office` | 无 | 文档、表格、幻灯片、图表、思维导图是文件种类 |
| `company-agent-plan` | `company.plan` | 写操作要人批 | GitLab 令牌不能进常驻核心包 |
| `company-agent-research` | `company.research` | `company_research_run` 在 lab 询问 | 时钟和提交插件拆开，避免实现把提交带进循环 |

能力共 14 个，工具名以 `company_`、`quantum_` 或 `hpc_` 开头。句柄只有 `asset_id`、`circuit_id`、`twin_id`。`twin_id` 只从 `quantum_device_run` 且 provider 为 `ionstack-twinrun` 时返回。

四个预设的可见性：

- `boot`：办公、工作流、知识、门户。没有计算提交，没有研究运行。
- `lab`：完整工具面，含超算提交、云提交、真机、研究运行、计划写、LaTeX 写。提交类每次询问。
- `algo`：算法、只读超算和云、研究编译与状态。没有提交，没有真机，没有 `company_research_run`。
- `sign`：提交和真机。没有办公，没有研究运行。

`quantum_device_run` 在 `lab` / `sign` 询问，在 `boot` / `algo` 拒绝。审批卡片只有「允许一次」。一次批准不覆盖下一次 `hpc_submit`、`hpc_stage_file`、`hpc_dir_create`、`hpc_file_remove`、`hpc_job_cancel`、`quantum_cloud_submit` 或 `quantum_device_run`。

`company_research_run` 的一次批准盖住这一次调用内部的有界修改再跑，最多 5 次。这次调用不提交超算、不提交云、不调用真机。`resource_type=qpu` 只记下 lab 真机交接。

minimal 组合不装 device。它仍装了 quantum、hpc、latex、office、plan、research。名字上的精简不等于工具面最小。若它的产品目标改成只做造包和知识检索，再从该组合拿掉超算、云和计划写工具。在那之前保持现状。

### 3.3 南向已经接通的路径

工具不直接使用桌面上的超算主机或云地址。`contracts/providers.json` 里 uniqon、uqc-cloud、hpc-slurm-ssh 各有自己的 invoke 地址和令牌。开发部署且 `COMPANY_AGENT_MANAGED_ACCESS=1` 时，接入运行时在本机回环上起网关并填入这些地址。

2026-11-06 开发座席 lab 会话里的事实：

- 云模拟器 `qiskit-sim` 提交后状态为 `SUCCESS`，结果为 `completed`。策略范围是仅模拟器，自动重试为 0。
- 超算作业 `67378` 与 `67379` 均为 `COMPLETED`。`67379` 的日志含 `python_ok 3.12.3` 与 `smoke-done`。分区名来自集群回执，脚本使用 `hpc`。
- 真机没有被调用。
- 量子平台资产列表因没有可用平台地址而失败闭合。开发私有环境里旧的本机回环地址不加载进这台桌面。
- GitLab 计划工具因私有环境没有 `COMPANY_AGENT_GITLAB_URL` 与令牌而失败闭合。内网 `http` 还要显式打开明文开关。

同日修过的适配器故障，不改变插件划分：

- 经 `wsl.exe` 发 SSH 时，未转义的 `$HOME` 会变成 WSL 自己的家目录。写操作把含 `company_agent` 段的路径放到集群账号家目录上。
- Windows 文本模式会把脚本写成 DOS 换行。SSH 标准输入改为原始字节。
- 云程序里的 `c = measure q;` 改写成平台要的逐比特测量。
- `company_office_open` 接受 `.xmind` 与 `.mm`。开发桌面默认 `COMPANY_AGENT_OPEN_WPS=wps`。关联程序不是 WPS 时拒绝。
- `company_research_run` 补进策略插件的可审批名单。询问不再被改成拒绝。

这些事实是开发座席证据。它们还不等于执行计划 E6 的生产验收。E6 仍要云、超算和设备 Owner 提供状态枚举、事件游标、取消语义、测试租户和真机窗口。未知状态只对账，不重投。

### 3.4 自动化现在怎么启动

空表在 `docs/experiment-card.zh-CN.md`。字段与 `company_research_compile`、`company_research_run` 相同。基线未复现或没有基线指标时，研究层 `compileExperiment()` 拒绝，运行不开始。当前桩时钟的指标读数是 `val_loss`，所以卡上的 `primary_metric` 填 `val_loss`。

顺序：

1. 人填卡，或在对话里给齐同样的字段。同一张表可以做成 WPS 表格。研究插件读取的是字段值。
2. `company_research_compile` 校验。
3. lab 里批准一次 `company_research_run`，带上本次 `idempotency_key`。
4. 这一次调用内部按 `max_attempts` 迭代，保留或预算用尽即停止。
5. 若要记下工单，再调用 `company_work_item`，`action=evaluate`，`mode=auto`，`strength=explicit`。工单绑定当前会话。
6. 下一轮是一张新卡，或用户明确要求再跑一次。

研究时钟的真实一轮尚未在这台桌面会话里跑过。编译和运行的桩路径有测试。桌面人格说明已经要求先收齐实验卡。

研究层里已经有、但还没有接到这次桌面运行上的平台时钟能力：有界循环、失败分类、失败库、日报和周报、worktree、租约状态机、成本账本、检查点、单轮回收扫描、策略决定留痕、假设质量门、方法卡结构校验。默认执行器仍是 stub。这些库由 `company_research_run` 调用，不单独做成插件。

### 3.5 办公、计划和代码提交

办公文件留在 `company.office`。图表用 `company_office_chart`。思维导图用 `company_office_create` 写 `.xmind` 或 `.mm`，事项导图用 `company_office_matter` 且 `kind=mindmap`。写完用 `company_office_open`。DSH 的 xlsx 预览会丢掉图表，不另做第二套图表渲染器。

GitLab 计划工具提交议题、评论和里程碑。它们不推送普通代码仓库。LaTeX 仓库的一次提交是 `company_latex_push`。普通 `git push` 不是公司工具，也不做插件。

工具结果保持短。禁止把 CAL、shuttle、bitstrings、Pauli 全文、密钥和完整电路正文放进工具结果。

### 3.6 仍未闭合的座席项

- GitLab 地址和令牌未写入私有环境。
- 量子平台地址未换成可用地址。
- 研究时钟尚未在这台桌面跑过一轮。
- 云门户嵌入脚本此前返回 404。嵌入页和 iframe 沙箱都还没改。
- 公司本地模型路由指向本机 `8000`，该端口未作为座席的现行模型。现行对话走公司中转。
- 本地工单账本还不是全公司事实源。企业身份、账单、模型版本标识仍等 Owner。对应执行计划 E5、E7、E8。

## 4. 前沿方法怎样落到这条缝上

78 项矩阵的检索截止是 2026-10-29。2026-11-06 只复核了和实验卡、一次作业、写权限分离有关的更新来源。结论是加强现有缝，不新装第二套运行时。

| 来源 | 时间 | 采用的机制 | 留在仓库外的部分 |
| --- | --- | --- | --- |
| GitHub Agentic Workflows safe-outputs 规范 1.29.16 | 2026-11-03 | 一次作业；作业侧只读；写操作另走带权限的步骤；每种写有次数上限；密钥不进作业 | 不安装 gh-aw |
| Spec Kit 1.2.1 | 2026-10-16 | 章程写一次；每张卡先规格再执行；人看过产物再继续；收敛只追加未完成项，对齐就停 | 不安装 `specify-cli`，不把 implement 循环嵌进插件 |
| 《Super-agent 设计探索》与原型 `docs/000-philosophy.md` | 2026-10-31 | 先有书面规则再行动；主动行为先只记录；一次只问一个具体问题；工单要有终态、预算和截止 | Router、Watchdog、端侧 daemon。原型写明文章设计并未全部实现 |
| autoresearch `program.md` | 文件页 2026-03-09 | 人改说明，代理只改允许的文件；指标短提取；账本只留提交、指标、状态、一句话 | `LOOP FOREVER`。次数仍以卡上的 `max_attempts` 为顶 |
| Robin, Nature，DOI `10.1038/s41586-026-10652-y` | 2026-05-19 | 代理提出假设和方案，人做实验，数据回来后再开下一轮 | Crow、Falcon、Finch。没有文献源之前不登记文献插件 |
| Copilot coding agent 近况 | 2026-02-26 | 一张写好的任务交给一个限制了工具的代理，做完就交回 | 代理审查自己的改动；云端会话交接 |
| The AI Scientist-v2，arXiv:2504.08066 | 2025-04 | 分阶段停止；预算用尽就停；只把当前最好的一个节点带进下一阶段 | 代理树搜索、自动写论文、去掉人写模板 |
| Google AI co-scientist | 2025-02-19 | 人先给目标，再产生可检验的假设和方案 | 六个专职代理和 Elo 自评 |

由此得到产品规则：

1. 实验卡是规格，也是书面规则。没有卡，研究运行不开始。
2. `company_research_compile` 是放行门。`company_research_run` 是那一个作业。
3. 超算、云和真机是作业外面的写操作。每次提交单独批准。研究卡上的 `hpc` 或 `qpu` 只记录类别。
4. 工单记录这一轮。`observe` 只记决策。`auto` 加 `explicit` 才打开，并绑定当前会话。
5. 下一轮来自新卡，或人把实验结果交回来。不来自常驻循环。
6. 作者与评审分开。代理不审查自己打开的变更。
7. 文献、树搜索和论文生成留到有证据定位和真实执行器之后。

## 5. 产品方向

产品是公司座席上的一个 DSH，不是另一套科学家软件。员工在原生界面里选公司预设，用公司工具完成办公、计划、电路、云模拟器、超算和研究迭代。需要人看的结果用 WPS 交付。会话里只留短回执。

四个使用场面：

| 场面 | 预设 | 人要做的事 | 系统做到哪里就停 |
| --- | --- | --- | --- |
| 办公和知识 | `boot` | 说明要哪一份文件 | 写出文件并交给 WPS。不申请计算 |
| 算法和只读排查 | `algo` | 给出要查的队列、设备或实验标识 | 返回短状态。不提交，不跑研究循环 |
| 实验迭代 | `lab` | 填实验卡并批准这一次运行 | 有界修改再跑。资源类别为超算或真机时只交接，不提交 |
| 签署计算 | `lab` 或 `sign` | 对每一次提交点允许一次 | 一次调用对应一次提交或一次取消。未知状态只查询 |

人的角色按 Super-agent 文章里的方向走：从逐步下命令，变成填写规格、批准边界、验收结果。这个转变只发生在书面规则和审批已经存在的地方。没有规则的主动行为保持 `observe`。

近期产品不追求「无人值守过夜跑完全部科学发现」。Robin 和 AI Scientist-v2 都说明，实验室动作和结果核对仍在人这边。公司版本把这个边界写成工具和预设，而不是写成提示词。

## 6. 开发计划

计划按依赖排序。时间沿用研究层路线图的口径：取决于人和现有基础设施，不是承诺日期。每一段都有退出标准。未达到就不进入下一段里依赖它的条目。合同先行。每段结束时按执行计划的格式写一篇 `docs/implementation-YYYY-MM-DD-<slice>.zh-CN.md`。

每一段的产物都要能被 Source 事件唤醒，不能只在有人打字的那一轮里存在。S5 之前由替身账本记下工单和线程；S5 由上游 Router 按订阅把没有人逐条输入的任务推进到会话。书面规则和公司策略在两段里相同。

### 6.1 阶段 S0：把开发座席上的现有缝收口

目标：一个人可以按实验卡在 lab 桌面跑完一轮桩时钟，并说清哪些资源还不能从时钟里提交。

交付：

- 用填好的实验卡调用 `company_research_compile`，再在 lab 批准一次 `company_research_run`。记录停止原因、次数、决策和候选 `trigger_id`。
- 同一轮里用 `company_work_item` 的 `observe` 记一次决策，再用 `auto` 加 `explicit` 打开一张工单，确认工单绑定的是当前会话引用。
- 卡上 `resource_type=qpu` 的路径只检查交接回执，不调用真机。
- 量子平台地址由 Owner 换成可用地址后再做资产列表。在那之前保持失败闭合。
- GitLab 地址、令牌和明文开关由 Owner 写入私有环境后再做计划写操作。在那之前保持未配置。
- 云门户 404 单独查静态资源。不放宽 iframe 沙箱。

退出标准：

- 桌面回执里能看到这一轮的 `stop_reason`、`attempts` 和 `decisions`。
- 基线未复现的卡被编译拒绝，并且没有运行记录。
- 同一次研究运行的工具结果里没有超算作业号、云任务号或 `twin_id`。
- 工单账本里没有会话正文、假设全文或密钥。

这一段不改插件划分，不提高 `max_attempts`，不把时钟接到 `hpc_submit`。

### 6.2 阶段 S1：把桩时钟换成一次真实的本地指标

目标：`company_research_run` 在允许的单个路径上改动并读取真实的 `val_loss`，仍在同一次批准内结束。

交付：

- 执行器从 stub 换成一个本地、有超时的运行。指标仍是 `val_loss`，方向仍是卡上的 `direction`。
- 只允许改 `changed_path`。路径含 `..` 或越出工作区则拒绝。
- 保留、撤销和崩溃分三态写入短账本。账本字段对齐 autoresearch 的短表：标识、指标、状态、一句话。不把运行日志放进工具结果。
- 崩溃和连续失败计入现有失败库。未知执行不重试。
- 预算用尽或达到 `max_attempts` 时停止，并按现有规则发候选信号。
- 工作区根是 Git 仓库时，每次本地尝试调用研究层已有的 worktree，只把当前候选写入该次工作树的 `changed_path` 并做一次本地提交。主目录里的候选文件保持原样。撤销时清掉干净的工作树。脏工作树不删除。不访问远端，不使用凭据。
- 可选的 `baseline_train_time_seconds` 让训练时间均值高出一成的尝试撤销。同一尝试的多种子相对标准差超过 0.5，或种子数少于 `min_seeds`，停止并要求更换 `changed_path`。

退出标准：

- 一次批准内完成至少两轮保留或撤销，并且撤销后工作区回到上一轮保留的状态。
- 超时被当成失败并停止，不另起一轮模型对话。
- 工具结果仍然短，不含日志全文。
- 研究层循环测试和公司研究时钟测试都通过。

这一段仍不提交超算或云。本地执行器挂掉时，回退方式是继续使用 stub，并在回执里标明 `executor=stub`。

### 6.3 阶段 S2：资源交接，而不是把提交并进时钟

目标：实验卡需要超算或云时，时钟停在交接；同一次 DSH 会话里的人再单独批准对应工具。

交付：

- `resource_type` 为 `hpc` 或 `cloud` 时，`company_research_run` 返回交接，不调用 `hpc_submit` 或 `quantum_cloud_submit`。
- 交接回执含实验标识、资源类别、`next_tool`，以及 `approval_still_required`。下一次提交仍要单独批准。
- 人批准的那一次提交继续走现有网关。未知、超时、排队和运行中只查询。
- 开发座席上已经完成的云模拟器和超算烟测写成回归用例：模拟器、`sbatch` 干跑或等价的非提交检查、短回执。真实作业不放进默认测试。
- E6 的 Owner 输入到齐之后，再把状态枚举、取消语义和测试租户补进合同。在那之前，开发座席证据保持在本文第 3.3 节，不标成生产通过。

退出标准：

- 研究运行的测试里不出现 Slurm 作业号。
- 单独的 `hpc_submit` 在未批准时仍是询问或拒绝，与研究运行是否刚刚交接无关。
- 取消和未知状态不会自动再提交。
- 云提交仍只能到模拟器。真机仍只有 `quantum_device_run`。

这一段若要拆出 `compute.cloud` 插件，条件是出现「要算法目录、不要云 worker」的组合。没有这个组合就不拆。

### 6.4 阶段 S3：规格生命周期

目标：一张实验卡从章程到停止都有可检索的短记录，人能看出下一张卡为什么存在。

交付：

- 研究章程继续是全平台的一份边界：一个问题、一个基线、一个指标、一份预算。改章程是边界变更，要留记录。
- 每张卡对应一个 `experiment_id`。编译结果、运行回执和候选触发用这个标识串起来。
- 停止原因为保留时，下一张卡必须写明新的假设或新的否证。沿用旧卡的幂等键会被拒绝。`next_fields` 只返回字段名。
- 停止原因为预算用尽时，只产生 `budget.exhausted.v1` 候选。开工单仍要人做 `evaluate`。
- `company_research_digest` 按租户返回次数、保留、撤销、交接、拒绝、失败次数和成本。不调用研究层日报的 Markdown，不生成论文，不调用文献插件。
- WPS 表格或 Markdown 只是填写界面。入库的是校验后的字段。

退出标准：

- 同一实验的状态工具能读回最近一次短记录。
- 两张卡共用一个幂等键时失败闭合。
- 日报里没有假设全文、日志和密钥。
- 没有人点头时，预算用尽不会打开工单。

Spec Kit 的 `converge` 在这里的对应物是：对照章程和这张卡，缺项就写成下一张卡的字段，而不是在插件里再跑一个实现循环。

### 6.5 阶段 S4：文献到可执行复现

目标：有真实检索源之后，把文献变成带证据定位的方法卡，再变成一张实验卡。

前置：检索源、全文获取方式和证据定位规则由 Owner 指定。没有这三项，本阶段不开始，也不登记 `company.literature`。

交付：

- 研究层已有的去重、方法卡编译和复现报告继续做结构校验。缺证据定位是硬错误。
- 新插件只在检索源稳定后增加，并且与研究时钟分开。插件返回短引用，不返回全文。
- 方法卡通过之后，才能生成实验卡草稿。草稿仍要人改基线是否复现、预算和允许修改的路径。
- 至少一个内部基线走完「方法卡、复现报告、实验卡、S1 的本地运行」。

退出标准：

- 没有证据定位的方法卡不能编译。
- 文献插件不能调用 `company_research_run`、`hpc_submit` 或 `quantum_device_run`。
- 复现失败的报告含差异归因，执行未知只能标成未尝试。

Robin 的实验室闭环放在这一段之后才有意义：文献代理提出候选，人做实验，数据再进入下一张卡。在检索源落地之前，实验卡继续由人填写。

### 6.6 阶段 S5：把替身账本换成上游流程

目标：可锁定的 Super-agent 用自己的 Router、订阅和注意力面板接管大量任务，包括没有人逐条输入的任务。替身工单库和替身线程绑定退出权威位置。公司工具包、策略和平台时钟留在原处。实验循环不改成编码循环。

前置：上游发布可锁定版本，并且对象链仍是 Source、Trigger、Eval、Mandate、Ticket、Assignment。当前合同写明官方原型未发布。未锁定时不自研 Router，也不把今天的原型源码嵌进仓库。S0 到 S4 已经按这条流程的替身在做，不另起一条公司流程。

锁定前维持的路径：

- 一张工单，一次新的 DSH 会话，一个 worktree。
- 规格写进这次 Mandate 的范围。公司侧的规格就是实验卡或一份等价的短规格。
- 会话输出不算证据。合并要另有测试、安全扫描和独立评审。
- 作者不审自己的变更。
- 主动行为默认只记录。

上游可锁定之后：

- 停止把本地账本当成工单权威。已有短记录只读保留到迁移完成。平台时钟的实验、租约和证据不进上游数据库。
- 本仓库作为一个 Source 注册进上游，而不是把上游表结构抄进来。
- Executor 使用已有技能做计划、测试和验证命令。
- 后续讨论回到同一执行会话。
- 进程重启后续跑，并且不重复已经发出的外部动作。
- 平台策略继续拦住花钱、上机、合并主分支和外发数据。

退出标准沿用研究层阶段 4：合并候选过全部门禁；Watchdog 不能改策略；人工可接管；上游不可用时可以回到上面的降级路径并标 `degraded`。

普通代码仓库的 `git push` 仍不是公司工具。编码工单若要提交到公司 GitLab，先有项目允许名单和写操作批准，再决定是走计划工具还是单独的受控推送。在允许名单出现之前不做推送插件。

### 6.7 阶段 S6：多租户生产化

目标：本地控制面不再被当成全公司事实源。多个团队使用同一套合同，凭据、账单和模型可以替换。

前置：E5 的模型版本和协议、E7 的账单字段、企业身份 Owner。这些输入缺失时，本阶段只保留失败闭合，不伪造通过。

交付：

- 租户隔离复核已经在 E4 有本地反例。生产验收要真实 IdP 和双租户。
- 账单分别对模型、超算节点时、真机用量和企业账单引用。观测 trace 只作诊断。
- 模型路由可以替换。异常时不切换到未批准的外部模型。公司本地路由和公司中转保持为两个 provider，不把密钥写进仓库。
- 控制面从 SQLite 迁出之前，先定审计和保留期。迁移期间旧账本只读。
- 研究层路线图里的 Temporal 放在这一段评估，不放在 S0 到 S2。评估标准是：现有租约、回收和未知执行不重试已经表达了状态机；只有在控制面重启后必须自动续跑、并且 Owner 接受一套新集群时，才引入持久工作流。引入前不把研究层循环改成常驻进程。
- SLO 使用研究层第 9 节的可靠性、安全、资源和科研指标作为目标，不在本文另造一组数字。昂贵或物理执行的重复次数目标是 0。

退出标准：

- 跨租户读取失败。
- 撤权后不能继续提交。
- 未知执行的账单状态不会显示成已完成。
- 至少一个内部租户完成办公、实验卡和一次模拟器提交。外部租户按 E8 另立试点。
- 发布可回滚。版本钉、合同摘要、验收证据和运行手册齐全。

### 6.8 阶段之间不许颠倒的依赖

```text
S0 桌面跑通实验卡
  → S1 本地真实 val_loss
    → S2 资源交接仍在时钟外面
      → S3 卡的生命周期和日报
        → S4 文献，仅当检索源存在
S5 编码工单与 S1 并行，但不共用循环实现
S6 等待身份、账单和模型 Owner，不阻塞 S0 到 S3
```

S4 不能插到 S1 前面。没有本地指标的实验卡，方法卡无法验收。S5 不能替换 S1。编码会话的完成只是一个信号，保留或撤销仍由实验指标决定。S6 不能用开发座席的烟测代替。

## 7. 明确不做

下面这些做法和本文的前提冲突。后续阶段也不把它们列为交付。

- 在插件或研究层里再写一个模型循环、会话循环或无限实验循环。
- 把 `company_research_run` 接到 `hpc_submit`、`quantum_cloud_submit` 或 `quantum_device_run`。
- 为了少点一次批准，把资源提交改成默认允许。
- 安装 Temporal、gh-aw、Spec Kit CLI、AI Scientist、Robin 的文献代理，或再部署 OpenHands、SWE-agent、Aider。
- 按每个工具、每个办公格式或每个按钮拆插件。
- 在没有检索源时登记 `company.literature`。
- 做普通 Git 推送插件，或做第二套图表渲染器。
- 把算法名单写死在 Agent 或知识库里。算法目录只来自量子平台的 `component_id`。
- 把本地 SQLite 账本升成全公司事实源。
- 把开发座席的云模拟器和超算烟测写成 E6 已通过。
- 把未发布原型的内部表或提示词写进长期合同。
- 在上游 Router 和订阅之外再写一套事件路由器或会话循环。新功能若不能被 Source 事件唤醒，也不能放进现有工作项、实验卡或公司工具，就先不开发。
- 用「没有人输入」绕过书面规则，或绕过超算、云和真机的公司策略。
- 重算或改写 2000 人天基线。

## 8. 风险

| 风险 | 现在的表现 | 处理 |
| --- | --- | --- |
| 原型与文章不一致 | 合同已标 `unreleased`；原型声明文章设计未全部实现 | 流程基座用对象链，不用今天的源码快照。锁定前本地账本只做替身 |
| 开发烟测被当成生产 | 云模拟器和两份超算作业已经在开发座席完成 | 写入第 3.3 节。E6 仍等 Owner 的状态语义和真机窗口 |
| 时钟实现把提交带进去 | 研究插件与超算、真机插件已经分开 | S2 用测试锁住「研究运行不产生作业号」 |
| 人忘记填卡就要求自动跑 | 人格说明和编译门已经要求字段齐全 | S0 把拒绝未复现基线列为退出标准 |
| 文献能力被提前做成插件 | 研究层只有结构校验 | S4 的前置不满足就不开始 |
| 持久工作流过早引入 | 租约和回收已是单轮扫描 | S6 才评估 Temporal。未知执行继续不重试 |
| 密钥进入仓库或工具结果 | 私有环境与凭据文件分开；工具结果有长度和内容禁令 | 新阶段不得放宽。计划令牌只进私有环境 |
| minimal 组合名实不符 | 它不装真机，但仍装超算、云、研究和计划 | 产品目标未改成纯造包之前不拆 |

## 9. 阅读和修改这份手册

改工具、预设或 Super DSH 合同之前，先改对应的 JSON，再改本文里受影响的段落。只改本文不改合同，视为文档漂移。

座席上的新证据写进 `docs/implementation-YYYY-MM-DD-<slice>.zh-CN.md`，并在本文第 3 节加一条日期和范围。阶段退出标准被勾掉时，在研究层路线图或执行计划里同步，不在本文把未跑的桌面步骤标成完成。

2026-11-06 的代码进度见 `docs/implementation-2026-11-06-s1-s3.zh-CN.md`。S0 的桩路径、S1 的本地 `val_loss` 日志和干净 worktree 撤销、S2 的超算与云交接、S3 的换卡规则和租户次数汇总已经有测试。公司执行计划里的 E0 到 E4 也已经落地。S4、S5、S6 以及 E5 到 E8 仍等检索源、可锁定的上游版本、模型协议、平台状态语义、身份和账单 Owner。桌面上一轮人工批准的研究运行还要人点「允许一次」。
