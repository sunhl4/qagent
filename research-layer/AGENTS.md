# AGENTS.md

本文件约束在此工程中工作的 Agent 与开发者。

## 工程定位

这是 DeepSeekHarness 企业级自主研发与自动科研平台的研究与实施工程。它不是产品代码仓库，所有实现必须另建代码仓库或子包，并遵循本工程的契约。

## 必须遵守

1. 不把 DeepSeek Harness 的 preview API 直接写进长期数据契约。
2. 所有对外对象必须能通过 `schemas/` 中的 JSON Schema 校验。
3. 所有高风险动作必须经过策略检查与审批。
4. 所有长任务必须有预算、超时、检查点和停止条件。
5. 所有实验必须有基线、指标、种子、环境锁和运行清单。
6. 所有资源申请必须使用租约，不得让 Agent 持有长期密钥。
7. 所有失败结果必须保存，不允许只记录成功。
8. 所有文档修改必须同步更新 `docs/交付清单.md`。
9. **不得重写 harness-core 已负责的能力**：DSH 核心、云平台、本地 HPC、本地模型、身份、对象存储、凭据。
10. **跨工程调用只能通过 `contracts/` 的端口**，不得直接 import 对方实现。
11. **契约变更必须双方评审**，主版本变更必须同步升级。
12. **本工程必须能在只有桩的情况下完整运行**，不得依赖对方代码才能编译或测试。

## 禁止

- 直接把模型输出当事实。
- 用 `while true` 实现 24/7 循环。
- 用 DSH 定时任务替代持久工作流。
- 让 Agent 直接访问生产环境或真实硬件。
- 在提示词、脚本、镜像或日志中写入长期密钥。
- 执行状态未知时自动重试。
- 把多套功能重叠的编排系统同时部署到同一环境。
- 在本工程实现云/HPC/模型适配器。
- 修改 `contracts/` 而不通知 harness-core。
- 用桩实现冒充生产实现。

## 目录约定

| 目录 | 用途 |
|---|---|
| `docs/` | 分册文档 |
| `schemas/` | 本工程领域对象契约 |
| `contracts/` | 跨工程端口契约（与 harness-core 共享） |
| `adapters/stub/` | 本地桩，独立开发用 |
| `configs/` | 配置样例 |
| `examples/` | 可校验示例 |
| `security/` | 威胁模型、权限、检查清单 |
| `deploy/` | 部署与运维 |
| `tests/` | 测试策略 |
| `research/` | 来源登记 |
| `canvas/` | 研究方案 Canvas |
| `scripts/` | 自检脚本 |

## 编辑规则

- 数学公式：行内用 `\(...\)`，块级用 `$$...$$` 且前后空行，块内不嵌套 `\(...\)`。
- 表格单元格内不要使用块级公式。
- 中文与英文之间保留空格。
- 链接使用官方地址。
- 不引用未核验的私有信息。

## 自检

提交前运行：

```bash
make validate
make contracts-typecheck
make stubs-check
```

要求：

- 全部 schema 可解析
- 全部 YAML 可解析
- 一致性用例结构完整
- 桩声明 degraded
- Canvas 存在且包含 DSH 内容
- 契约包可编译（若本地有 tsc）

## 变更记录

修改架构、契约或安全边界时，必须：

1. 更新对应文档。
2. 更新 `docs/交付清单.md`。
3. 说明影响范围。
4. 提供回滚方式。
