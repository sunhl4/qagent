# 部署拓扑

## 1. 最小可用部署

```text
┌─────────────────────────────────────────────┐
│ Kubernetes 集群                              │
│  ├─ platform-api                            │
│  ├─ dsh-runtime (deployment)                │
│  ├─ model-gateway                           │
│  ├─ approval-service                        │
│  ├─ policy-service                          │
│  └─ otel-collector                          │
├─────────────────────────────────────────────┤
│ 托管/自建                                    │
│  ├─ Temporal                                │
│  ├─ PostgreSQL                              │
│  ├─ MinIO / S3                              │
│  └─ MLflow                                  │
├─────────────────────────────────────────────┤
│ 外部                                        │
│  ├─ Slurm 集群（通过 bridge）                │
│  ├─ 模型端点（API 或自部署）                  │
│  └─ 文献 API                                │
└─────────────────────────────────────────────┘
```

规模：单团队、少量并发、非敏感数据。

## 2. 生产部署

```text
区域 A
  ├─ 控制面（多副本）
  ├─ Temporal（多副本）
  ├─ PostgreSQL（主备）
  ├─ 对象存储（版本化 + 备份）
  └─ 沙箱节点池（独立）

区域 B
  ├─ 控制面（热备）
  ├─ 数据库只读副本
  └─ 对象存储跨区复制

独立
  ├─ GPU 节点池
  ├─ HPC 集群（Slurm）
  ├─ 模型推理集群
  ├─ 凭据代理 / KMS
  ├─ 审计日志 WORM
  └─ 出网代理
```

## 3. 网络分区

```text
Z0 公网
Z1 边缘（WAF、API 网关）
Z2 控制面（K8s 服务）
Z3 数据（Postgres、对象、KMS）
Z4 沙箱（无外网，白名单）
Z5 资源（Slurm、GPU、K8s 批处理）
Z6 模型（自部署推理）
Z7 设备（真实硬件，独立）
```

规则：

- Z0 不能直连 Z4–Z7。
- Z4 默认无出网。
- Z5 只接受控制面指令。
- Z7 独立信任域。
- 管理面走带外。

## 4. 资源规划

### 4.1 控制面

| 组件 | 副本 | CPU | 内存 |
|---|---|---|---|
| platform-api | 3 | 2 | 4Gi |
| dsh-runtime | 按需 | 2 | 8Gi |
| model-gateway | 3 | 2 | 4Gi |
| policy-service | 3 | 1 | 2Gi |
| approval-service | 2 | 1 | 2Gi |

### 4.2 数据

| 组件 | 规格 |
|---|---|
| PostgreSQL | 4C16G 起，主备 |
| Redis（可选） | 2C8G |
| 对象存储 | 按数据量 |
| Temporal | 4C16G 起 |

### 4.3 沙箱

- 每会话 2–4 vCPU、8–16GB。
- 独立节点池。
- 本地临时盘。
- 不与控制面混部。

### 4.4 GPU

- 按实验需求。
- 独立节点池。
- 与沙箱隔离。
- 监控利用率。

## 5. 部署顺序

1. 基础网络与分区
2. PostgreSQL、对象存储
3. Temporal
4. 策略与身份
5. 凭据代理
6. model-gateway
7. platform-api
8. DSH runtime
9. 沙箱节点池
10. 资源适配器
11. 可观测
12. 审批与前端

## 6. 备份与恢复

| 数据 | 频率 | 保留 | 恢复目标 |
|---|---|---|---|
| PostgreSQL | 每日全量 + WAL | 30 天 | 1 小时 |
| 对象存储 | 版本化 + 跨区 | 90 天 | 4 小时 |
| 审计日志 | 实时 | 1 年+ | 只读 |
| 配置 | Git | 永久 | 分钟 |
| 模型 | 制品库 | 永久 | 小时 |

演练：

- 每季度恢复一次。
- 记录 RTO/RPO。
- 验证数据完整性。

## 7. 高可用

- 控制面无状态，多副本。
- 数据库主备。
- Temporal 多副本。
- 对象存储多副本。
- 模型网关多副本。
- 沙箱故障不影响控制面。
- 资源适配器可降级。

## 8. 监控

| 层 | 指标 |
|---|---|
| 基础设施 | CPU、内存、磁盘、网络 |
| 控制面 | 请求、延迟、错误、队列 |
| DSH | 会话、轮次、工具调用 |
| 模型 | 延迟、token、成本、回退 |
| 资源 | 队列、租约、利用率、回收 |
| 实验 | 成功、失败、部分、耗时 |
| 安全 | 拒绝、越权、密钥扫描 |

## 9. 容量规划

```text
并发会话数 ≈ 活跃用户数 × 平均并发率
沙箱需求 ≈ 并发会话数 × 每会话资源
模型 QPS ≈ 并发会话数 × 每会话请求率
存储 ≈ 实验数 × 平均产物大小 × 保留期
```

预留 30% 余量。

## 10. 发布

- 蓝绿或金丝雀。
- 数据库迁移向前兼容。
- 插件灰度。
- 模型灰度。
- 自动回滚阈值。
- 发布窗口与值班。

## 11. 灾难恢复

| 场景 | 动作 |
|---|---|
| 单区故障 | 切到另一区 |
| 数据库损坏 | 从备份恢复 |
| 对象存储不可用 | 读本地缓存，停止新写 |
| Temporal 不可用 | 停止新工作流，保留已运行 |
| 模型全不可用 | 降级为人工或只读 |
| 沙箱节点全故障 | 停止执行，保留队列 |
| 密钥泄露 | 全线撤销，轮换 |
