# 交付说明与研究边界

## 1. 本工程是什么

`ai-research-harness` 是本次对话调研成果的独立工程化落点。它不是一个已经可运行的 DeepSeek Harness 部署，而是一套完整的研究、架构、契约和实施材料，用来支撑公司后续在 DSH 上做深度开发。

交付物分四类：

1. **研究材料**：公开项目调研、来源登记、证据等级。
2. **架构材料**：总体架构、插件划分、资源与安全边界。
3. **契约材料**：JSON Schema、配置样例、运行清单。
4. **实施材料**：路线图、验收指标、测试与安全清单。

## 2. 本工程不是什么

- 不是 DeepSeek 官方文档的替代品。
- 不是对 DSH 全部能力的承诺。
- 不是已经通过生产验证的系统。
- 不是法律、合规、采购或安全认证结论。
- 不是一套可以直接无人值守操作真实硬件的成品。

## 3. 研究口径

### 3.1 时间

调研截止：2026-10-29。

计划修订：2026-11-01。编码协作改为接入上游 Super-agent，见 `docs/15_Super-agent接入与两套时钟.md`。其中「五模块会完成并开源」是计划假设，不提高文章本身的证据等级。

### 3.2 不依赖本地既有资料

本工程的结论来自本轮公开网络与 GitHub 调研。没有把其他工作区的既有文档当作证据。

### 3.3 证据等级

| 等级 | 定义 | 允许的用途 |
|---|---|---|
| A | 官方文档、官方仓库、官方 API、可下载代码 | 架构约束 |
| B | 同行评审论文、可复现实验、生产系统报告 | 设计参考 |
| C | 企业自述、媒体报道、社区文章 | 仅证明存在该说法 |
| D | 由 A/B 推导 | 必须标注推断 |
| U | 无一手来源 | 不得用于设计决策 |

### 3.4 三件必须分开的事

- **模型**：DeepSeek 或其他厂商的大模型。
- **Harness**：把模型变成 Agent 的运行框架，即 DSH。
- **平台**：多租户、可计费、可审计、可长期运行的企业系统。

自部署模型 ≠ 自部署 Harness ≠ 拥有平台 ≠ 拥有科学结论。

## 4. DSH 的时效风险

DSH 官方标注为 public preview，核心插件和 API 仍在演进。使用本工程时必须：

1. 锁定 DSH 仓库 commit 或发行版本。
2. 所有 DSH API 依赖经过公司适配层。
3. 不把 preview 插件清单、事件名、配置格式写进长期数据契约。
4. 每季度做 Harness 兼容性回归。
5. 保留替换 Harness 的能力：任务对象、实验数据、评测基准不绑定 DSH。

## 6. 术语约定

| 术语 | 含义 |
|---|---|
| Harness | 智能体运行框架，负责会话、工具、模型适配、上下文 |
| 插件 | 挂载在 Cordis 上下文上的能力单元 |
| 服务键 | `ctx.<name>` 形式的稳定服务入口 |
| 工作流 | 跨小时到跨月的持久业务流程 |
| 租约 | 短期资源使用权，含范围、时长、fencing token |
| Fencing token | 单调递增令牌，防止旧持有者继续操作 |
| 实验规格 | 可执行实验的完整声明 |
| 运行清单 | 一次执行的全部证据索引 |
| Provenance | 产物来源与变换链 |
| 失败库 | 可检索的负结果集合 |
