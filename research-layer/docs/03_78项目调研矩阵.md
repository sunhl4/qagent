## 7. 选型规则

### 7.1 每类只选一个主实现

| 类别 | 主实现 | 备选 |
|---|---|---|
| Agent Harness | DSH | OpenHands SDK（不部署） |
| 编码协作运行时 | 上游 Super-agent | 单工单 headless，标记 degraded |
| 持久工作流 | Temporal | Prefect |
| K8s 配额 | Kueue | Volcano |
| HPC | Slurm | Flux |
| 云资源 | SkyPilot | 自研适配 |
| 实验追踪 | MLflow | W&B / ClearML |
| 数据版本 | DVC | Pachyderm |
| 搜索 | Optuna | Ax |
| 前端测试 | Playwright | Cypress |
| 文献解析 | GROBID + Marker | MinerU |
| 文献问答 | PaperQA | 自研 RAG |
| 量子基线 | Qiskit | PennyLane（可微场景） |

### 7.2 不要同时部署的组合

- Temporal + Prefect + Airflow + Dagster + Flyte + Argo 全上。
- Kueue + Volcano 同时管同一批节点。
- MLflow + W&B + ClearML 三套追踪。
- 多个 Agent harness 同时接管同一工作区。Super-agent 是 DSH 插件，不与第二套编码代理并行。
- Ralph 的 shell 循环与 Super-agent 同时驱动同一个仓库。
- 多套文献解析器对同一批 PDF 重复跑。

### 7.3 引入新项目的最低门槛

1. 明确它替代现有哪个组件。
2. 许可证允许公司使用与分发。
3. 近 6 个月有维护活动。
4. 有可运行的测试或示例。
5. 有安全边界说明。
6. 有退出/迁移路径。
7. 不引入新的长期数据格式锁定。

## 10. 2026-11-01 量子补充：Walking Cat

IonQ 的 Walking Cat 是囚禁离子容错架构预印本（arXiv:2604.19481，2026-04-22），不是 Agent 的 Watchdog，也不计入上面的 78 项。

引入范围：

- 量子执行轨道的设计参考。记忆、猫态工厂、魔法态工厂和束搜索译码可以成为后续 qLDPC 实验的目标架构。
- 表面码匹配译码仍用 PyMatching。Walking Cat 的码族是广义自行车码、双变量自行车码和循环超图积码，译码用束搜索，不替换 PyMatching。
- 相关公开代码是 [ionq-publications/BeamSearchDecoder](https://github.com/ionq-publications/BeamSearchDecoder)。仓库许可证标为 Other，核过许可证之前只作候选，不进生产依赖。
- 不采用第三方、自称兼容 Walking Cat 的解码器产品。
- 不把这篇论文的资源估算写成已实现的硬件指标。文中稠密方案约 2,514 个物理量子比特、110 个逻辑量子比特、每天约一百万个 T 门，是设计估算。
- 真实离子作业仍走审批、租约和未知执行不重试。本工程不实现离子穿梭。

和 Watchdog 只共享一条结构：探针在计算外面报告错误，用完即弃，不改写被保护的状态。Agent 侧继续用这条约束，不把量子纠错码装进会话监督。
