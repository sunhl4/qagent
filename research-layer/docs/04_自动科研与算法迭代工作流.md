# 自动科研与算法迭代工作流

## 1. 目标

把一个模糊的研究方向，变成可执行、可验证、可停止、可复用的实验序列。

最终要能自动产出：

- 文献地图与方法卡
- 复现报告
- 候选改进假设
- 实验规格
- 运行结果与决策
- 失败库
- 日报 / 周报 / 阶段性技术报告

## 2. 总体流程

```text
研究目标
  → 文献检索
  → 去重与版本合并
  → 全文获取与解析
  → 方法卡与引用图
  → 代码与数据定位
  → 复现难度评估
  → 环境构建
  → 基线复现
  → 差异归因
  → 缺口与改进点
  → 候选假设
  → 实验规格
  → 策略与预算检查
  → 资源申请
  → 执行
  → 指标计算
  → 决策
  → 记忆与报告
  → 下一轮
```

编码改动若需要 Agent 写代码，使用上游 Super-agent 的一张工单。工单完成只是本流程里的一个信号。指标、运行清单、保留或撤销、租约结算仍由本节之后的平台流程完成。两套时钟见 `docs/15_Super-agent接入与两套时钟.md`。

## 3. 文献阶段

### 3.1 检索源

| 源 | 用途 |
|---|---|
| arXiv | 预印本、最新工作 |
| OpenAlex | 跨学科、引用图、开放获取链接 |
| Crossref | DOI 与出版元数据 |
| Semantic Scholar | 引用关系、影响力 |
| DBLP | 计算机会议与期刊 |
| PubMed / PMC | 生物医学 |
| 机构订阅 | 全文获取 |

### 3.2 去重规则

- DOI 相同 → 同一条目。
- arXiv ID 与正式版 DOI 关联 → 合并，保留正式版为主，预印本为版本。
- 标题+作者+年份高相似 → 人工或规则确认。
- 同一工作的会议版与期刊版 → 保留扩展版，记录差异。

### 3.3 解析

| 任务 | 工具 |
|---|---|
| 版面与章节 | GROBID |
| 复杂 PDF 到 Markdown | Marker / MinerU |
| 多格式转换 | MarkItDown |
| 引用解析 | GROBID + Citation.js |
| 元数据补全 | OpenAlex / Crossref |

### 3.4 方法卡

每篇入选论文生成一张方法卡。字段见 `总技术报告` 第 7.3 节与 `schemas/` 中的实验契约。

必须包含证据定位：页码、章节、图表编号、原文片段。没有定位的结论不可进入下游。

参考实现：`packages/domain/src/literature.ts` 的 `compileMethodCard()` 把缺证据定位记为硬错误，缺基线/代码/超参/数据集记为警告；方法卡由文献插件负责生成，本仓库只做结构校验。结构符合 `schemas/method-card.schema.json`。

### 3.5 引用图

- 后向：这篇论文依赖什么。
- 前向：谁引用了它、做了什么改进。
- 聚类：按问题、方法、数据集形成主题簇。
- 时间：识别已饱和方向与新方向。

## 4. 复现阶段

### 4.1 复现难度评估

| 维度 | 低 | 中 | 高 |
|---|---|---|---|
| 代码可得 | 官方仓库 | 第三方实现 | 无代码 |
| 数据可得 | 公开完整 | 部分公开 | 私有 |
| 超参完整 | 全部给出 | 部分给出 | 缺失 |
| 算力需求 | 单卡 | 多卡 | 集群 |
| 依赖复杂度 | 标准库 | 少量特殊依赖 | 私有系统 |
| 评测明确 | 有脚本 | 有描述 | 仅文字 |

### 4.2 环境构建

- 使用容器镜像。
- 锁定依赖版本（lockfile）。
- 固定 CUDA/驱动/框架版本。
- 记录硬件型号。
- 固定随机种子。
- 记录数据版本哈希。

### 4.3 三层验证

#### 语义复现

逐项对照：

- 算法公式与代码是否一致。
- 数据预处理是否一致。
- 训练/验证/测试划分是否一致。
- 评价指标定义是否一致。
- 是否有未说明的额外数据或后处理。

#### 数值复现

- 运行原始设置。
- 至少 3 个随机种子。
- 报告均值、方差、置信区间。
- 与论文数值比较，允许合理硬件差异。
- 偏差超过阈值时给出归因。

#### 可推广性验证

- 换一个数据集。
- 换一个规模。
- 换一个硬件。
- 检查方向是否一致。
- 检查成本是否可接受。

### 4.4 复现报告

```text
论文信息
复现目标
环境
数据
命令
随机种子
结果表
与原文差异
差异归因
复现结论（成功/部分/失败）
可复用资产
未解决问题
```

参考实现：`packages/domain/src/reproduction.ts` 提供复现难度评分（六维 0–2 分）、声明均值与容差比较、报告编译；部分/失败结论必须附差异归因，执行未知结论只能是 `not_attempted`。`packages/pipeline/src/reproduction.ts` 把每种子的独立提交接到 `ComputePort` 走 `acquireLease`，执行未知立即停止且不释放不重试，预算耗尽后剩余种子跳过。报告结构符合 `schemas/reproduction-report.schema.json`。

## 5. 假设阶段

### 5.1 假设来源

- 论文明确指出的未来工作。
- 论文的局限性章节。
- 复现中的异常现象。
- 失败库中的重复失败模式。
- 相邻领域的迁移方法。
- 成本/规模/硬件的约束变化。

### 5.2 假设质量门

一个假设必须满足：

- 可证伪：存在能推翻它的实验结果。
- 有依据：来自文献、复现或失败记录。
- 有差异：与现有方法的区别明确。
- 有最小实验：能在有限预算内验证。
- 有预期效应：说明希望改善多少。
- 有风险：说明可能失败的原因。

### 5.3 假设记录

```yaml
id: H-2026-001
statement: "在 X 条件下，用 Y 替换 Z 可以降低 W 指标"
origin:
  type: "literature_gap|reproduction_anomaly|failure_pattern|transfer"
  evidence: ["paper:...", "run:..."]
falsifiable_by: "如果 W 未下降或护栏退化，则假设不成立"
expected_effect: "W 下降 ≥ 3%"
minimal_test:
  dataset: "..."
  budget: "1 GPU-hour"
  repeats: 3
risks: ["数据分布不匹配", "实现复杂度高"]
```

参考实现：`packages/domain/src/hypothesis.ts` 的 `checkHypothesis()` 把可证伪、来源证据、最小实验预算与风险声明设为硬性缺失即拒绝；重复次数少于 3 只告警（正式结论要求 3 个种子）。记录结构符合 `schemas/hypothesis-record.schema.json`。

## 6. 实验阶段

### 6.1 实验规格编译

把假设编译成 ExperimentSpec：

1. 选择基线。
2. 定义变量与控制变量。
3. 定义主指标与护栏指标。
4. 定义数据与划分。
5. 定义种子与重复次数。
6. 定义资源与预算。
7. 定义停止条件。
8. 定义决策规则。
9. 定义产物清单。
10. 定义审批要求。

参考实现：`packages/domain/src/hypothesis.ts` 的 `compileHypothesisSpec()` 把通过质量门的 `HypothesisRecord` 编译成 `ExperimentSpec`——基线/变量/数据/种子/资源由调用方提供，决策文案由假设派生（`假设成立：…` / `假设不成立：…`），并再次通过 `compileExperiment()` 全量校验，不合法即返回 findings。

### 6.2 执行流程

```text
校验规格
→ 创建分支/worktree
→ 生成或选择代码
→ 静态检查
→ 单测
→ smoke test
→ 申请资源
→ 获得租约
→ 写入 attempt
→ 执行
→ 周期检查点
→ 收集指标
→ 释放资源
→ 计算统计
→ 决策
```

### 6.3 停止条件

必须同时设置：

- 最大 wall-clock。
- 最大成本。
- 最大尝试次数。
- 最大连续失败次数。
- 截止时间。
- 早停规则（如验证指标连续 N 轮不改善）。

任一触发即停止，不允许“再试一次”。

### 6.4 决策规则

```text
主指标改善 ≥ 最小可观测效应
且 护栏指标未退化
且 结果在多种子下稳定
且 成本在预算内
→ 保留，进入下一轮消融或扩展

否则
→ 撤销变更，记录负结果与失败类型
```

### 6.5 统计要求

- 至少 3 次重复。
- 报告均值与标准差或置信区间。
- 明确最小可观测效应。
- 避免只报告最好一次。
- 多种子结果不一致时，不进入昂贵资源。

### 6.6 参考实现

`packages/pipeline/src/loop.ts` 把 6.3 的停止条件实现为有界循环：

- 最大尝试次数取规格与调用方覆盖值的较小值，不使用无限循环。
- 每轮开始前检查截止时间与剩余预算，单轮按 `resources.max_cost` 预留。
- 首轮执行输入规格，后续轮由 `propose()` 生成候选；候选必须保持同一 `experiment_id` 与 `task_id`。
- 遇到保留结果、未知执行、需要审批、策略拒绝、连续失败上限或早停阈值立即停止。
- 每轮写 `manifest.json`，循环结束写 `loop-summary.json`，失败与负结果同样入库。

隔离工作区：`packages/workspace/src/worktree.ts` 为每次尝试创建 `exp/<slug>/attempt-<n>` 分支和独立 worktree，默认位于 `<repo>/.worktrees/`。已登记且分支匹配时复用；分支已存在但未登记时拒绝；清理只允许干净工作树，分支保留作为证据。配置 `LoopInput.workspace` 后，循环在每轮执行前创建或复用 worktree，并把分支与基线提交写入运行清单。该实现只调用本机 git，带超时，不访问远端，不执行 `--force`、`reset` 或 `clean`。

## 7. 记忆与知识回流

### 7.1 研究记忆

保存：

- 已读论文与方法卡。
- 已复现结果。
- 失败尝试。
- 有效提示与工具组合。
- 数据集与环境的坑。
- 决策与理由。

### 7.2 失败分类

| 类型 | 含义 | 处理 |
|---|---|---|
| 实现错误 | 代码 bug | 修复后重跑 |
| 数据问题 | 数据缺失/泄漏/分布问题 | 修数据或换数据 |
| 指标错误 | 指标定义或计算错误 | 修指标 |
| 资源不足 | 显存/时间/配额 | 调整规模或申请 |
| 假设错误 | 方向不成立 | 记录并转向 |
| 环境问题 | 依赖/驱动/版本 | 修环境 |
| 评测不稳 | 方差过大 | 增加重复或换评测 |

参考实现：`packages/domain/src/failure.ts` 把编译错误、策略规则、端口错误和决策原因映射到上述类别，并给出稳定的 `code` 与 `retryable`。未知执行永远不可重试。

### 7.3 记忆检索

- 按问题、方法、数据集、失败类型检索。
- 新任务开始时自动召回相关失败，避免重复。
- 召回结果附来源与时间，避免过时结论。

参考实现：`packages/domain/src/failure-library.ts` 提供失败去重、按任务/实验/类别/阶段/错误码/可重试性/文本/时间检索，以及按类别和错误码统计。循环把单次实验的失败库写入 `failures.json`；`pipeline/src/retrieval.ts` 的 `loadFailureLibrary()` 在新任务开始时经 `ArtifactStorePort` 读回历史 `failures.json` 并以 `mergeFailureEntries()` 合并去重（去重键 `entry_id`，重放保留最新消息），召回结果挂在 `LoopOutcome.recalledFailures` 交上层使用。SQL 级大规模检索仍需要上层数据层。

关键结果

## 9. 与 DSH 的接口

| 步骤 | DSH 角色 | 平台角色 |
|---|---|---|
| 检索 | 调用文献工具、总结 | 提供检索 API、限流、缓存 |
| 解析 | 选择解析器、抽取字段 | 提供解析服务、存储 |
| 复现 | 生成代码、调试 | 提供沙箱、环境、资源 |
| 假设 | 生成候选、解释依据 | 校验结构、去重、评分 |
| 实验 | 生成规格、分析结果 | 编译、审批、调度、执行 |
| 决策 | 提出建议 | 按规则判定、记录 |
| 报告 | 撰写草稿 | 模板、事实校验、发布 |

原则：**DSH 生成内容，平台判定事实。**

## 10. 反模式

1. 只读摘要就生成假设。
2. 不做基线复现就声称改进。
3. 单次实验就下结论。
4. 只报告成功。
5. 用模型自评代替指标。
6. 无预算上限的搜索。
7. 失败后立即换方向，不记录原因。
8. 把论文作者的说法当作已验证事实。
9. 忽略数据泄漏。
10. 把不同硬件的结果直接横比。
