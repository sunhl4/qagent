# 模型供应层与 DeepSeek 部署策略

## 1. 目标

让平台能够：

- 使用 DeepSeek API
- 使用公司自部署的 DeepSeek 或其他开源模型
- 使用采购的第三方模型
- 按任务、成本、合规、健康度自动路由
- 在模型变化时保持工作流与数据格式稳定

## 2. 三层分离

```text
模型层：权重 / API / 推理服务
Harness 层：DSH 的 ctx.llm 适配
平台层：路由 / 配额 / 评测 / 审计
```

任何一层替换都不应破坏其他两层。

## 3. 供应方式对比

| 维度 | 官方 API | 自部署 | 采购第三方 |
|---|---|---|---|
| 上线速度 | 快 | 慢 | 中 |
| 数据控制 | 低 | 高 | 中 |
| 单位成本 | 按 token | 固定+运维 | 按 token |
| 能力更新 | 快 | 慢 | 中 |
| 合规 | 依赖供应商 | 可控 | 依赖合同 |
| 运维负担 | 低 | 高 | 低 |
| 锁定风险 | 中 | 低 | 中 |

## 4. 自部署的现实检查

### 4.1 DeepInfer 公开事实

- Apache-2.0。
- 支持 DeepSeek-V4.1-Flash。
- 支持 NVIDIA SM100 与昇腾 950。
- 提供优化 kernel、并行策略、投机解码、异步调度、确定性采样、结构化输出。
- 明确不包含：KV cache 系统、PD 分离、数据并行副本负载均衡。

### 4.2 必须补齐的组件

```text
模型权重管理
推理引擎
KV cache / 上下文管理
Prefill / Decode 分离
副本负载均衡
推理网关（鉴权/配额/限流）
可观测
评测
灰度与回滚
故障转移
```

### 4.3 引擎选择

| 引擎 | 适用 | 注意 |
|---|---|---|
| DeepInfer | DeepSeek 模型、官方优化 | 需补齐服务组件 |
| vLLM | 通用开源模型、生态广 | 版本与 kernel 兼容 |
| SGLang | 高吞吐、结构化输出 | 需评估 |
| TensorRT-LLM | NVIDIA 极致性能 | 构建复杂 |
| 昇腾生态方案 | 国产硬件 | 生态成熟度需评估 |

选择依据：

- 硬件可用性
- 模型支持
- 吞吐/延迟目标
- 团队运维能力
- 许可证
- 社区活跃度

## 5. 模型路由

### 5.1 能力注册表

```yaml
models:
  - id: "deepseek-v4.1-flash"
    provider: "local"
    version: "1017"
    capabilities: ["chat", "tools", "json", "long_context"]
    context: 128000
    cost: {input: 0, output: 0, unit: "token"}
    limits: {rpm: 600, tpm: 200000}
    residency: "cn"
  - id: "deepseek-api"
    provider: "deepseek"
    capabilities: ["chat", "tools", "json"]
    cost: {input: 0.0, output: 0.0, unit: "token"}
    residency: "external"
  - id: "purchased-model-a"
    provider: "vendor-a"
    capabilities: ["chat", "tools", "vision"]
    residency: "external"
```

### 5.2 路由规则

```text
1. 过滤：能力、上下文、地域、合规
2. 过滤：预算、配额
3. 过滤：健康度
4. 排序：成本 + 延迟 + 质量惩罚
5. 选择并记录决策
```

### 5.3 回退

```text
主模型失败
  → 同类备用模型
  → 降级能力（如不支持工具则改用纯文本规划）
  → 人工接管
```

回退必须记录，不能静默。

## 6. 评测

### 6.1 评测集

| 类型 | 内容 |
|---|---|
| 通用能力 | 推理、编码、长文 |
| 工具调用 | 参数正确性、多步调用 |
| 结构化输出 | JSON schema 合规率 |
| 领域任务 | 文献抽取、实验设计、代码修复 |
| 安全 | 越狱、注入、数据泄漏 |
| 稳定性 | 重复运行一致性 |
| 成本 | 每任务 token 与金额 |

### 6.2 门禁

模型进入生产前：

- [ ] 能力达标
- [ ] 结构化输出合规 ≥ 阈值
- [ ] 工具调用成功率 ≥ 阈值
- [ ] 安全测试通过
- [ ] 成本在预算内
- [ ] 延迟达标
- [ ] 稳定性达标

### 6.3 回归

- 每次模型升级重跑。
- 每次提示模板变更重跑。
- 记录基线。
- 退化即回滚。

## 7. 提示与版本

- 提示模板独立版本化。
- 记录模板 ID、版本、哈希。
- 模型与模板组合是评测单元。
- 不把提示写死在代码里。
- 变更需审查。

## 8. 成本控制

### 8.1 计量

- 输入 token
- 输出 token
- 缓存命中
- 推理时间
- GPU 占用

### 8.2 配额

- 租户级
- 项目级
- 用户级
- 任务级

### 8.3 优化

- 缓存常见请求。
- 小模型做分类与抽取。
- 大模型做规划与复杂推理。
- 批处理。
- 上下文压缩。
- 结构化输出减少重试。

## 9. 数据与合规

| 数据分类 | API | 自部署 | 采购 |
|---|---|---|---|
| 公开 | 允许 | 允许 | 允许 |
| 内部 | 需评估 | 允许 | 需合同 |
| 机密 | 禁止 | 允许 | 需专用 |
| 受限 | 禁止 | 需专用环境 | 需合规审查 |

规则：

- 数据分类决定可用模型。
- 跨境传输需审批。
- 供应商不得用数据训练（需合同）。
- 日志脱敏。
- 删除可执行。

## 10. 可观测

- 每次调用记录：模型、版本、模板、token、延迟、成本、结果状态。
- 按租户/项目/任务聚合。
- 异常告警。
- 质量抽样。

## 11. 迁移策略

### 11.1 从 API 到自部署

```text
1. 选定模型与引擎
2. 搭建推理服务
3. 跑同一评测集
4. 对比质量、延迟、成本
5. 小流量灰度
6. 逐步切换
7. 保留 API 作为回退
```

### 11.2 从自部署到其他模型

- 不改变工作流对象。
- 只替换适配器。
- 重跑评测。
- 对比历史任务。

## 12. 反模式

1. 把模型 API 密钥发给 Agent。
2. 只部署推理引擎，不部署网关。
3. 不做评测就切换模型。
4. 把模型版本写死在工作流里。
5. 用平均 token 估算成本。
6. 不做回退。
7. 不记录模型版本。
8. 把敏感数据发给外部 API。
9. 用提示词控制配额。
10. 假设换模型后行为不变。
