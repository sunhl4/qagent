# 代码结构与开发指南

## 1. 工程形态

TypeScript monorepo，直接用 Node 运行（Node ≥ 22.6 支持类型擦除），无需构建步骤。

```text
contracts/                 跨工程契约（唯一集成面）
  src/types.ts             公共类型、PortResult、错误码
  src/ports/*.ts           9 个端口
  src/index.ts             公共导出
  schemas/*.json           能力描述、集成清单
  conformance/             一致性用例
  fixtures/                集成清单样例
adapters/stub/             全部端口的内存桩（仅本地）
packages/domain/           纯领域逻辑（无 IO）
  src/experiment.ts        规格编译与校验
  src/decision.ts          保留/撤销/扩展/停止/升级
  src/policy.ts            服务端策略判断
  src/states.ts            任务状态机
  src/failure.ts           失败分类与可重试性
  src/failure-library.ts   失败去重、检索与统计
  src/lease.ts             租约状态机、续租与可执行判定
  src/cost.ts              三段成本账本与预算检查
  src/checkpoint.ts        检查点记录、恢复/重启/升级决策
  src/reclaim.ts           单次扫描的回收与泄漏决策
  src/software-gate.ts     软件合并门禁（降级路径，不包含路由器）
  src/literature.ts        文献去重、语料组装与方法卡校验
  src/reproduction.ts      复现难度、声明比较与报告编译
  src/hypothesis.ts        假设质量门与假设→实验规格编译
  src/platform-signal.ts   实验、租约、预算事实事件
packages/pipeline/         编排流水线（只依赖端口）
  src/run.ts               单次尝试与运行清单（可选租约门控与成本快照）
  src/loop.ts              有界实验循环、循环摘要、失败库写入与事实事件
  src/report.ts            日报与周报聚合、产物写入
  src/lease.ts             租约编排：报价、预留、提交与释放
  src/reclaim.ts           一轮对账、过期回收与泄漏告警
  src/retrieval.ts         失败库读回与跨循环合并召回
  src/software.ts          降级会话启动：结构预检 + 一工单一次会话
  src/reproduction.ts      多种子复现执行与报告生成
  src/literature.ts        文献阶段编排：方法卡组装、语料落盘
packages/workspace/        本地工作区（只依赖 Node 与 git）
  src/worktree.ts          分支/worktree 创建、复用与清理
tests/                     契约、清单、流水线、循环、失败库、日报、worktree、租约、回收与软件门禁测试
scripts/                   自检与类型检查
```

依赖方向：

```text
tests → pipeline → domain → contracts
tests → pipeline → workspace
tests → workspace
tests → adapters/stub → contracts
```

不允许反向依赖。`domain` 不认识任何端口；`pipeline` 只认识端口，不认识具体实现。


## 3. 核心对象

### 3.1 ExperimentSpec

位置：`packages/domain/src/experiment.ts`，对应 `schemas/experiment-spec.schema.json`。

关键约束：

- 假设必须可证伪。
- 基线必须已复现且有指标值。
- 变更必须声明允许/禁止路径。
- 必须有主指标、方向、最小可观测效应。
- 必须有护栏指标。
- 长任务必须有检查点。
- 必须有停止条件与决策规则。
- 必需产物：`code_hash`、`env_lock`、`raw_metrics`、`manifest`。

`compileExperiment()` 返回 `errors` 与 `warnings`，不抛异常。

### 3.2 Decision

位置：`packages/domain/src/decision.ts`。

优先级：

```text
unknown_execution → escalate
failed → stop
partial → escalate
缺少主指标 → escalate
超预算 → stop
缺少产物 → escalate
未达最小效应 → discard
护栏退化 → discard
方差过大 → extend
通过 → keep
```

决策是纯函数，输入 `ObservedResult`，输出 `Decision`。便于回放与单测。

### 3.3 Policy

位置：`packages/domain/src/policy.ts`。

规则顺序：

1. 未知执行后重试 → DENY
2. Agent 出网 → DENY
3. restricted 数据驻留不符 → DENY
4. 超预算 → DENY
5. QPU / 生产写入 / 不可逆 / 高风险 → 审批
6. 已批准高风险 → ALLOW_WITH_LIMIT
7. 默认 → ALLOW

策略是服务端判断，不由提示词决定。

### 3.4 TaskState

位置：`packages/domain/src/states.ts`。

```text
draft → queued → waiting_approval / waiting_resource → running
running → succeeded / failed / partial / cancelled
终态不可回退
```

### 3.5 FailureRecord

位置：`packages/domain/src/failure.ts`。

失败类别与 `docs/04` 的失败分类表一致：

```text
implementation  data  metric  resource  hypothesis
environment     instability  policy  unknown
```

规则：

- `classifyFailure()` 是纯函数，输入阶段、错误码、决策原因，输出稳定 `FailureRecord`。
- 未知执行无论传入什么 `retryable`，结果都为 `false`。
- 编译错误按语义映射，例如基线未复现 → `hypothesis`，检查点缺失 → `resource`，产物缺失 → `metric`。
- 决策失败按原因映射，例如方差过大 → `instability`，护栏退化 → `hypothesis`。

### 3.6 ExperimentLoop

位置：`packages/pipeline/src/loop.ts`。

循环边界：

- 最大尝试次数取规格 `stopping.max_attempts` 与调用方覆盖值的较小值。
- 每轮开始前检查截止时间与剩余预算。
- 单轮预算占用按 `resources.max_cost` 预留；实际成本从剩余预算扣除。
- 首轮使用输入规格，后续轮由 `propose()` 提供候选；候选不得改变 `experiment_id` 与 `task_id`。
- 遇到 `keep`、未知执行、需要审批、策略拒绝、连续失败上限、早停阈值即停止。
- 每轮写 `manifest.json`；循环结束写 `loop-summary.json`，包含全部尝试与失败记录。
- 有失败时另写 `failures.json`，内容为去重后的失败库与分类统计。
- 配置 `workspace` 时，每轮执行前创建或复用 worktree，并把分支与基线提交写入 manifest；worktree 不在循环内自动删除，保留为失败现场。
- 配置 `lease` 时，每轮走租约门控（预留 → 提交 → 结束释放结算）；循环持有共享账本，剩余预算按账本“已承诺成本”（`max(实际, 净预留)`）扣减，未释放的预留同样占用预算。`LoopOutcome.ledger` 返回最终账本，可直接交给 `sweepLeases()` 做回收扫描。
- 同时提供 `checkpoints` 与 `resume` 时，每轮结束用 `planResume()` 生成恢复决策（恢复/重启/重启原因不足）；写入尝试记录 `resume_plan` 与 `resume_from`，达到恢复上限转人工。未知执行不使用恢复决策，直接升级。

### 3.7 FailureLibrary

位置：`packages/domain/src/failure-library.ts`。

- `buildFailureEntries()` 以 `run_id + stage + code` 去重，保留最后一次消息。
- `queryFailureLibrary()` 支持按任务、实验、类别、阶段、错误码、可重试性、文本与时间检索，结果按时间倒序。
- `failureStats()` 输出总数、按类别计数与按错误码计数；类别覆盖全部 9 类。
- 失败库是纯内存索引，持久化由 `loop.ts` 写对象存储；跨任务检索需要上层数据库或检索服务。

### 3.8 DailyReport

位置：`packages/pipeline/src/report.ts`。

- `buildDailyReport()` 聚合当天的 `LoopSummary`，输出实验统计、关键结果、负结果、失败分组、成本、人工决策与明日计划。
- Markdown 固定包含：今日目标、完成的实验、关键结果、失败与原因、资源消耗、明日计划、需要人工决策。
- `writeDailyReport()` 写入 `reports/daily/<date>/report.json` 与 `report.md`；任一写入失败返回 finding，不抛出端口错误。
- 日报只陈述可追溯事实，不生成新的实验结论。

### 3.9 Worktree

位置：`packages/workspace/src/worktree.ts`。

- `worktreeLocation()` 从实验 ID 与尝试号派生确定性的分支和路径，默认在 `<repo>/.worktrees/` 下。
- `createExperimentWorktree()` 创建 `exp/<slug>/attempt-<n>` 分支；已登记且分支匹配时复用，路径被其他分支占用或分支已存在但未登记时拒绝。
- `removeExperimentWorktree()` 只删除干净工作树；脏工作树返回 `DIRTY`，分支保留作为证据。已不存在时返回 `absent`，保证清理可重入。
- 所有 git 调用使用参数数组、30 秒默认超时和 `GIT_TERMINAL_PROMPT=0`；不访问远端，不执行 `--force`、`reset` 或 `clean`。
- 返回记录符合 `schemas/worktree-record.schema.json`。
- `LoopInput.workspace` 可以把该能力接入实验循环；创建失败时循环停止且不执行实验。

### 3.10 Lease

位置：`packages/domain/src/lease.ts` 与 `packages/pipeline/src/lease.ts`。

领域规则：

- `createLease()` 生成 `REQUESTED` 租约，校验持有者、资源数量、TTL、fencing token 与预留成本。
- `transitionLease()` 实现 `REQUESTED → PREPARED → ACTIVE → DRAINING → RELEASED`，以及 `REVOKED`、`EXPIRED`、`FAILED` 分支；重复释放幂等，终态不可回退。进入 `DRAINING` 时把原因写入 `hold_reason`。
- `renewLease()` 延长过期时间并提升 fencing token；续租检查新时间、`renewable_until` 与剩余预算。
- `canExecuteLease()` 只允许 `ACTIVE` 且在时间窗口内的租约执行。
- `recordLeaseHold()` 在不改变状态时记录暂停原因。尚未 `ACTIVE` 的未知执行用它记住“禁止自动释放”。

编排：

- `acquireLease()` 先报价，再按 `maxCost` 做悲观预留与项目级预算检查，然后提交；提交失败释放预留，`UNKNOWN_EXECUTION` 保留预留且禁止自动重试。
- `releaseLease()` 先确认资源释放成功，再记录实际成本、退回未使用预留并迁移到 `RELEASED`；释放失败保留账本。`ACTIVE` 转入 `DRAINING`，其他非终态只写 `hold_reason`。
- `RunInput.lease` 启用后，`runExperiment()` 走租约准入：报价 → 预算预留 → 提交；结束统一释放并结算，写 `costs.json` 快照；未知执行转对账，升级时保留预留，确认未执行或取消则退回预留。

### 3.11 CostLedger

位置：`packages/domain/src/cost.ts`。

- 条目分 `reserve`、`actual`、`release` 三类，`entry_id` 确定性生成，重试幂等，内容冲突被拒绝。
- 已承诺成本按 `max(实际, 净预留)` 计算，避免预留与实际重复计费。
- `checkBudget()` 支持附加预留，返回剩余额度与超额值。
- `leaseCostSummary()` 计算单个租约未使用的预留额度，供释放时退回。
- `buildCostLedgerSnapshot()` 输出符合 `schemas/cost-ledger.schema.json` 的快照。

### 3.12 Checkpoint

位置：`packages/domain/src/checkpoint.ts`。

- `latestCheckpoint()` 只接受同一实验、同一 attempt、哈希合法且 `valid !== false` 的检查点，按 step 和创建时间取最新。
- `planResume()` 输出 `resume`、`restart`、`escalate` 或 `none`：
  - 有效检查点 → 恢复到 `previous_attempt + 1`。
  - 缺失、过期、代码版本或环境不一致 → 重启。
  - 未知执行、恢复次数达到上限 → 转人工，禁止自动恢复。
  - 上次成功或已取消 → 不恢复。
- `checkpointArtifactKey()` 使用 attempt 前缀，新 attempt 不会覆盖旧检查点。
- 运行时闭环（2026-11-02）：`runExperiment()` 在供应商返回 `checkpointUri` 时写入 `CheckpointRecord` 产物（`checkpoint` 类型；`sha256` 摘自指针 URI，真实载荷哈希由存储侧校验），并通过 `RunOutcome.checkpoint` 返回；循环把它并入检查点池，`planResume` 自动可用。桩的 `failCheckpointUri` 用于注入"失败现场也留检查点"。

### 3.13 Reconcile

位置：`packages/pipeline/src/lease.ts` 的 `reconcileLease()`。

- `executed` 且终态 → 释放资源并结算实际成本。
- `queued_or_running` → 同步租约状态，继续等待。
- `not_executed_confirmed` → 退回预留、标记失败，可安全重新提交。
- `cancelled_before_execution_confirmed` → 退回预留并撤销租约。
- `unknown` → 升级人工，保留预留，禁止重试。

### 3.14 Reclaim

位置：`packages/domain/src/reclaim.ts` 与 `packages/pipeline/src/reclaim.ts`。

领域决策：

- 窗口内或宽限内 → `keep`。
- 过期且没有资源句柄 → `expire`。`ACTIVE` 却没有句柄，超过告警时限才告警。
- 过期仍持有资源 → `reclaim`。默认超过 300 秒才记为泄漏。
- `hold_reason` 以 `release_failed` 开头 → 立即补偿回收并告警。
- 未知执行，或 `DRAINING` 但原因不明 → `escalate`，禁止自动释放。

编排 `sweepLeases()` 每次只跑一轮：

- `keep` 且已有句柄 → 做一次对账。结束则结算，确认未执行则允许上层重提，本轮不提交。
- `reclaim` → 调用 `releaseLease()`。未知执行改为升级。
- `expire` → 只迁移本地状态，不调用算力端口。
- 告警发到 `TelemetryPort`，标签只有稳定错误码和资源类型。遥测失败记 `W_TELEMETRY`，不回滚已经完成的释放。
- 扫描记录符合 `schemas/reclaim-sweep.schema.json`。

### 3.15 Literature 与 MethodCard

位置：`packages/domain/src/literature.ts`。

- `deduplicatePapers()`：同 DOI（忽略大小写与 doi.org 前缀）合并，正式版里较新年份为主记录；无 DOI 的 arXiv 记录能关联到正式版就并入（`arxiv_link`），否则按 arXiv ID 自分（`arxiv_match`）；剩余记录按 标题+年份+第一作者 聚类，多于一条只报 `W_LIT_REVIEW`，不自动合并。
- `buildLiteratureCorpus()`：语料组装。引用边端点解析到合并后的主记录，端点缺失记 `W_LIT_EDGE_UNKNOWN`，同一记录自引用记 `W_LIT_EDGE_SELF`；主题聚类来自记录的 topics 字段。
- 非法记录（缺 paper_id、title、authors 或年份非整数）记 `E_LIT_RECORD` 并排除，不抛异常。
- 语料结构符合 `schemas/literature-corpus.schema.json`。
- `compileMethodCard()`：缺 `method_card_id`、`paper`、`problem`、`method_summary` 任一硬错误；`evidence_locations` 为空时记 `E_METHOD_CARD_EVIDENCE`（没有证据定位的结论本就不应进入下游）；缺基线、代码、超参、数据集、声明只给警告。方法卡由文献插件生成，本仓库校验结构。
- `compileReproductionCandidate()`：在宽松编译通过之后，还要求公式或表格证据、公式的 `ledger_id`、带单位和平台资格标记的指标、容差、数据划分。官方或第三方代码必须有 commit；没有代码时 `missing_information` 不能空。主张依赖的附件若未解析，候选不能通过。平台五种单位以外的指标可以留在候选里，但 `platform_metric_eligible` 为 false，不进入研究时钟。

### 3.16 文献编排

位置：`packages/pipeline/src/literature.ts`。

- `assembleMethodCard()` 补齐 ID、时间与版本号后过领域编译；编译失败不返回卡片。
- `ingestLiterature()` 去重并把 `corpus.json` 与 `review-candidates.md` 写入 ArtifactStore，幂等键分别是 `<corpus_id>:corpus` 与 `<corpus_id>:review`。写入失败只记 `W_LIT_INGEST_JSON` / `W_LIT_INGEST_MD`，语料照常返回。
- 确认清单列出全部人工确认候选；没有候选时明确写"全部合并均为确定性规则"。

### 3.17 ReproductionReport

位置：`packages/domain/src/reproduction.ts`。

- `assessDifficulty()`：六维 0–2 分（代码/数据/超参/算力/依赖/评测），≤4 低、≤9 中、其余高。
- `evaluateClaim()`：种子值均值与原文差值是否落在容差内；无种子值时 mean/std/within_tolerance 全为 null。
- `buildReproductionReport()`：
  - 语义检查全过 + 每个声明有种子值且全部落在容差内 + 至少一个可推广性方向一致 → `succeeded`；此时必须记录环境锁哈希与硬件型号。
  - 数学与语义达标但缺可推广性 → 错误 `E_REPRO_GENERALITY`，结论暂为 `partial`。
  - `partial`/`failed` 必须附差异归因，否则 `E_REPRO_NO_DIFFERENCE` / `E_REPRO_DIFFERENCE_REQUIRED`。
  - 有运行状态未知 → `not_attempted`。
  - 全部运行无种子值 → `failed`。
- 报告结构符合 `schemas/reproduction-report.schema.json`。

### 3.18 Hypothesis

位置：`packages/domain/src/hypothesis.ts`。

- `checkHypothesis()` 是进入实验阶段的门槛：
  - 硬性要求：可证伪声明（`falsifiable_by`）、来源类型与证据引用（`origin.type` + `origin.evidence`）、最小实验预算（`minimal_test.budget`）、重复次数 ≥1、风险列表非空。
  - 重复次数 <3 只告警 `W_HYP_REPEATS`；正式结论要求至少 3 个种子。
  - 未写预期效应只告警。
- `draftHypothesisFromReproduction()` 从复现结果草拟候选：内容仍由研究侧输入；origin 固定 `reproduction_anomaly`，证据链接自动生成 `reproduction:<id>` 与逐声明 `reproduction:<id>#<claim>`，然后过同一条质量门。
- `compileHypothesisSpec()` 把通过质量门的假设编译成 `ExperimentSpec`：基线、变量、数据、种子与资源由调用方提供；决策文案由假设派生（`假设成立：…` / `假设不成立：…`），`stopping` 有默认值；编译结果再过 `compileExperiment()` 全量校验，失败即整体失败。
- 记录结构符合 `schemas/hypothesis-record.schema.json`。

## 4. 端口

### 4.1 结果封装

```ts
const result = await compute.submit(request);
if (!result.ok) {
  // result.error.code / retryable / details
  return;
}
const handle = result.value;
```

不要 `try/catch` 端口调用：端口不抛异常，只返回 `PortResult`。

### 4.2 能力检查

```ts
const caps = await port.describe();
if (!caps.ok) throw new Error(caps.error.message);
if (caps.value.degraded) {
  // 只允许本地开发
}
if (!caps.value.features?.includes("reconcile")) {
  // 降级：不允许自动重试
}
```

### 4.3 错误语义

| 错误码 | 处理 |
|---|---|
| `UNKNOWN_EXECUTION` | 停止，人工对账 |
| `PERMISSION_DENIED` | 转审批或终止 |
| `NOT_SUPPORTED` | 降级或换实现 |
| `UNAVAILABLE` / `TIMEOUT` | 可有限重试，但先确认幂等 |
| `QUOTA_EXCEEDED` | 等待配额或调整预算 |

## 5. 新增端口

1. 在 `contracts/src/ports/` 新建文件。
2. 只使用 `contracts/src/types.ts` 的公共类型。
3. 所有方法返回 `PortResult<T>`。
4. 提供 `describe()`。
5. 在 `contracts/src/index.ts` 导出。
6. 在 `contracts/schemas/capability-descriptor.schema.json` 与 `integration-manifest.schema.json` 的端口枚举中登记。
7. 在 `contracts/conformance/cases.yaml` 增加 MUST 用例。
8. 在 `adapters/stub/src/` 增加桩。
9. 在 `tests/contracts.test.ts` 增加测试。
10. 更新版本（新增端口为次版本）。

## 6. 新增桩

1. 继承 `StubBase`。
2. 构造函数传入 `degradedReason`。
3. 实现 `describe()`，通过 `ok({ ...this.caps(), ... })` 返回。
4. 所有方法返回 `PortResult`。
5. 支持至少一种失败注入。
6. 不访问网络、不读真实凭据。
7. 在 `adapters/stub/src/index.ts` 装配。
8. 在 `contracts/fixtures/integration-manifest.stub.json` 登记。

## 7. 新增领域规则

- 规则放在 `packages/domain/`。
- 纯函数，不做 IO。
- 输入输出用显式类型。
- 错误用 `Finding` 表达，不抛异常。
- 每条规则有稳定 `code`。
- 必须有测试覆盖通过与不通过两条路径。

## 11. 常见问题

### Q：为什么不用 zod？

避免运行时依赖与版本漂移。边界校验集中在 `PortResult` 与领域编译函数；schema 由 JSON Schema 表达。

### Q：为什么桩要这么复杂？

因为桩要验证语义，不是验证函数被调用。幂等、未知执行、租户隔离必须可测。

### Q：合并后桩还留着吗？

留着，用于单测与回归。生产装配使用 harness-core 的实现。

### Q：本工程能直接驱动 DSH 吗？

不能。必须通过 `SessionPort`，由 harness-core 适配。这样 DSH 升级不会破坏本工程。编码协作同样不直接调用 Super-agent 内部库；上游接口冻结后另开端口，冻结前不在业务代码里依赖它。

### Q：实验循环要改成常驻 Super-agent 吗？

不要。`packages/pipeline` 的有界循环、租约和回收属于平台时钟。编码工单才进入上游 Super-agent。见 `docs/15_Super-agent接入与两套时钟.md`。

### Q：可以在这里加一个云 SDK 吗？

不可以。属于 harness-core。先加端口。
