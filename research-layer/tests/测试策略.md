# 测试策略

## 1. 目标

保证平台在长期运行、并发、多租户和故障条件下仍然正确、可恢复、可审计。

## 2. 测试分层

| 层 | 对象 | 工具 | 频率 |
|---|---|---|---|
| 单元 | 函数、模块 | pytest / vitest | 每次提交 |
| 契约 | Schema、API | JSON Schema 校验、契约测试 | 每次提交 |
| 集成 | 数据库、队列、存储 | Testcontainers | 每次提交 |
| 工作流 | Temporal 流程 | 时间跳跃、重放测试 | 每次合并 |
| 资源 | 适配器 | 模拟器 + 真实沙箱 | 每日 |
| 端到端 | 用户路径 | Playwright | 每次合并 |
| 性能 | API、调度 | 负载测试 | 每周 |
| 故障 | 网络、节点、租约 | 注入 | 每周 |
| 安全 | 权限、注入、逃逸 | 扫描 + 手工 | 每季度 |

## 3. 契约测试

### 3.1 Schema

- 所有示例必须通过对应 schema。
- 非法示例必须被拒绝。
- 字段新增必须向后兼容。
- 删除字段必须升主版本。

### 3.2 API

- 请求/响应符合 OpenAPI 或 schema。
- 错误码稳定。
- 幂等语义正确。
- 状态转换合法。

## 4. 工作流测试

### 4.1 重放

- 用固定历史重放，结果一致。
- 非确定性代码不得进入工作流。
- 所有外部调用通过 Activity。

### 4.2 定时器

- 使用时间跳跃测试长等待。
- 验证超时与补偿。

### 4.3 恢复

- 杀 worker，验证恢复。
- 重启控制面，验证继续。
- 断网，验证重连与对账。

## 5. 资源测试

| 场景 | 期望 |
|---|---|
| 申请成功 | 获得租约，状态 ACTIVE |
| 申请失败 | 返回明确原因，不创建 attempt |
| 执行超时 | 停止，释放，记录 |
| 节点丢失 | 从检查点恢复 |
| 租约过期 | 拒绝新工作 |
| 旧 fencing token | 拒绝 |
| 释放失败 | 告警并补偿 |
| 执行未知 | 进入 UNKNOWN，不重试 |

## 6. 多租户测试

- 租户 A 不能读租户 B 的对象。
- 租户 A 不能使用租户 B 的模型配额。
- 租户 A 不能看到租户 B 的审计。
- 配额隔离。
- 密钥隔离。
- 缓存隔离。

## 7. 安全测试

| 测试 | 方法 |
|---|---|
| 提示注入 | 构造恶意文档，验证不执行外发 |
| 工具越权 | 尝试调用未授权工具 |
| 沙箱逃逸 | 已知逃逸样例 |
| 密钥泄露 | 扫描日志、镜像、环境 |
| 依赖投毒 | 恶意包模拟 |
| 插件后门 | 未声明权限的插件 |
| 数据外泄 | DLP 规则 |

## 8. 性能测试

| 指标 | 目标 |
|---|---|
| API P95 | < 300ms |
| 会话启动 | < 5s |
| 工具调用开销 | < 100ms（不含工具本身） |
| 调度决策 | < 500ms |
| 事件延迟 | P95 < 5s |
| 并发会话 | 按容量规划 |

## 9. 测试数据

- 不使用生产数据。
- 使用合成数据或脱敏数据。
- 固定随机种子。
- 可重复生成。
- 测试后清理。

## 10. CI 流水线

```text
lint
→ typecheck
→ unit
→ contract
→ integration
→ workflow replay
→ e2e
→ security scan
→ dependency scan
→ sbom
→ build
→ deploy to staging
→ smoke
```

## 11. 发布门禁

- [ ] 全部测试通过
- [ ] 覆盖率达标
- [ ] 无高危漏洞
- [ ] 性能无回归
- [ ] 安全审查
- [ ] 回滚演练
- [ ] 文档更新

## 12. 反模式

1. 只测成功路径。
2. 用 mock 替代所有集成。
3. 测试依赖执行顺序。
4. 不确定的随机测试。
5. 生产数据进测试。
6. 跳过故障注入。
7. 没有性能基线。
8. 安全扫描只在发布前跑。
